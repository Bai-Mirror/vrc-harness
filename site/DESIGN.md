# Harness 宣传网站 · 设计说明

稿件范围：`index.html`（首页）、`product.html`（产品介绍）、`download.html`（下载与安装说明）、`known-limitations.html`（已知限制）、`articles/demo.html`（文章模板）、`assets/`。纯静态，无外部请求。所有令牌定义在 `assets/css/site.css` 顶部，文章专用样式在 `assets/css/article.css`。

## 1. 取向

- **像产品，不像广告。** 网站沿用 GUI 的令牌（同一套底色、面板、线、主色、圆角），读者从网站进到应用时不会觉得换了一个牌子。文案只写任务书里列出的事实，「规划中」单独成段并逐条打标签。
- **浅色默认，深色跟随系统。** 现行 GUI 是浅色（底 `#f5f6f7`、面板 `#fff`、正文 `#182027`、主色 `#334e91`、选中底 `#dde7ff`）。任务书里的深色 `#101214` 是旧主题，按主理 09-28 的更正以截图为准。调研的 12 个同类站里 11 个默认浅色，也支持这个选择。深色主题完整保留（即 GUI 的旧配色），由 `prefers-color-scheme: dark` 切换，所有组件两套都验过截图。
- **界面图当主角，装饰让位。** 只有两处装饰：从 Logo 底纹取来的菱形格纹（hero 背景，遮罩渐隐）和一块深蓝横幅（照 GUI 首页的「下一步」面板做）。其余全是内容组件。
- **中文为主，英文只作副标题。** 大标题不做字距压缩（CJK 不需要），英文副标题用 `.en` 微收字距。

## 2. 设计令牌

### 2.1 颜色

品牌梯度（两套主题共用）：`--brand-950 #12173a`、`900 #192149`（Logo 边缘取样）、`800 #252d5c`（Logo 底色取样）、`700 #334e91`（GUI 主色）、`500 #5f7fd6`、`300 #9bb6ff`（GUI eyebrow）、`200 #b9caff`（GUI 计数）、`100 #dce6ff`（GUI 主按钮 / 选中底）。

| 令牌 | 浅色（默认） | 深色 | 用途 |
|---|---|---|---|
| `--bg` / `--bg-2` | `#f5f6f7` / `#eef0f2` | `#101214` / `#15181b` | 页面底 / 页脚与侧栏底 |
| `--panel` / `--panel-2` | `#ffffff` / `#eef1f5` | `#191d21` / `#20252a` | 卡片 / 次级按钮底 |
| `--line` / `--line-2` | `#dfe3e6` / `#c6cdd4` | `#2a3036` / `#3b4650` | 分隔线 / 描边 |
| `--text` / `--text-2` / `--muted` | `#182027` / `#3d4852` / `#5b6670` | `#e9edf1` / `#b6c0ca` / `#939da7` | 正文 / 次级 / 弱化 |
| `--accent` / `--accent-ink` / `--accent-soft` | `#2f55b8` / `#fff` / `#dde7ff` | `#83a6ff` / `#151a22` / `#222e4a` | 链接、强调 / 其上文字 / 选中底 |
| `--eyebrow` | `#334e91` | `#9bb6ff` | 小标签 |
| `--ok` / `--warn` / `--bad` | `#1f7a4d` / `#8a5a00` / `#b42318` | `#64c493` / `#e5b85c` / `#e27878` | 状态色（各配 `-soft` 底色） |
| `--btn-primary-bg` / `-ink` | `#334e91` / `#fff` | `#dce6ff` / `#151a22` | 主按钮（与 GUI 一致） |
| `--code-bg` / `--code-ink` | `#151a22` / `#e9edf1` | `#0b0d0f` / `#e9edf1` | 代码块两套主题都保持深色 |

固定色（不随主题变）：设备框 `--device-bar #eef0f2`、`--device-line #d9dee3`、`--device-dot #c3cad1`、`--device-title #5b6670`、`--device-screen #f5f6f7`；标注圆点 `--callout-bg #334e91` + 白字；横幅 `--banner-bg`（`#1b2646 → #111a33 → #0e1529`）+ `--banner-ink #f2f5fb`。理由：截图是浅色界面，框和标注要像「应用本身」，不能在深色页面里变成深框套浅图。

浅色 `--muted` 从 GUI 的 `#66717b` 压深到 `#5b6670`，因为它在页脚底 `#eef0f2` 上只有 4.36:1；压深后 5.14:1。对比度审计见第 6 节。

### 2.2 字体与字号

字体栈：`Inter, "Noto Sans SC", "Noto Sans CJK SC", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif`；等宽 `ui-monospace, Menlo, Consolas, "Noto Sans Mono", monospace`。全部系统字体，不自托管、不请求字体服务（任务书要求；自托管一套 Noto Sans SC 子集也要 1 MB 以上，超过首页预算）。Linux 上整站落到 Noto Sans CJK SC，截图即此效果。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-0` | 12px | 标签、图注、页脚声明 |
| `--fs-1` | 14px | 次级正文、卡片正文 |
| `--fs-2` | 16px | 正文，行高 1.75（CJK 需要比拉丁文更高的行高） |
| `--fs-3` / `--fs-4` | 18 / 20px | 导语、卡片标题 |
| `--fs-5` | `clamp(24px, 1.2rem + 1.2vw, 32px)` | 分节标题、功能标题 |
| `--fs-6` | `clamp(30px, 1.4rem + 2vw, 44px)` | 产品页与文章 h1 |
| `--fs-7` | `clamp(36px, 1.4rem + 3.4vw, 68px)` | 首页大标题 |

CJK 没有词边界，`text-wrap: balance` 会把「重启」拆成两行。做法：标题里按短语包 `<span class="nb">`（`white-space: nowrap`），浏览器只在短语之间换行。这比 `word-break: keep-all` 安全，后者会让长句在窄屏上溢出。

### 2.3 间距、圆角、阴影、断点

- 间距 4px 基数：`--s-1…--s-10` = 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128。分节上下留白 `clamp(48px, 8vw, 96px)`，页边 `clamp(16px, 4vw, 40px)`。
- 容器 1120px（正文）与 1280px（页头、产品 hero）；文章正文 44em，导语 `--measure: 38em`。
- 圆角与 GUI 相同：8（按钮、输入）/ 12（卡片）/ 16（面板、设备框、横幅）/ 胶囊。
- 阴影：浅色用 `0 1px 2px rgb(15 23 42/.05)` 的贴地阴影；深色不用阴影，靠描边分层（GUI 的做法）。设备框统一用 `--glow`（1px 描边 + 蓝色大光晕），暗示「这是应用窗口」。
- 断点：400（导航缩字）、480（状态板改单列）、600（兼容行去分隔点）、640（页头状态胶囊出现、横幅双列）、720（品牌副标出现）、760（流程图四列、页脚三列）、800（路线图横排）、960（功能行双列、hero 分栏、设备框透视）、1100（文章目录侧栏）。手机 360px 到桌面 1920px 都截过图。

### 2.4 动效

只有两处：hero 元素依次上浮 0.7s（`.rise`，延迟 80ms 递增）和「开发中」圆点的呼吸光晕。都包在 `prefers-reduced-motion: no-preference` 里。注意：无头浏览器在 t=0 截图时上浮动画还没跑，内容会不可见——截图要加 `--virtual-time-budget`；真实浏览器不受影响。

## 3. 版式

- **页头**：粘性、毛玻璃、64px。左品牌（Logo 32px + 名称 + 副标），右导航四项（首页 / 产品 / 下载 / 开发日志，`aria-current="page"` 高亮；五项页面共用同一组，已知限制页把「下载」标为当前），最右「开发中 · 尚未发布」胶囊（<640px 隐藏）。
- **首页** hero 分栏（与产品页同构）：左文案（eyebrow → 口号「让自我，更简单。」→ 导语 → 版本与平台说明 → 两个按钮 → 兼容说明），右设备框。之后依次是：我想解决的问题（三张卡）、怎么用（四步流程 + AI 接入状态板）、我做了什么（核心口径横幅 + 六张机制卡 + 产品页导流）、开发状态（横幅 + 状态板）、联系方式（两张邮箱卡）、页脚。首页不再使用 `.roadmap` 三节点路线图（组件保留，当前无页面使用）。
- **产品页 hero** 分栏：左文案 + 页内跳转胶囊，右设备框带 7° 透视（<960px 取消透视）。之后：四步流程图（第四步「闸门」用暖色标出）、六个功能行（文字 5 : 图 7，左右交替）、安全边界三卡、协作学习卡、规划中、导流。
- **文章页**：头部（分类 eyebrow、标题、导语、元信息行）；正文 44em；≥1100px 右侧 240px 粘性目录，窄屏改为正文顶部的可折叠 `<details>` 目录（两份目录，用 `display:none` 互斥，避免读屏器读两遍）。

## 4. 组件

- `.eyebrow` 小标签：12px。面向访客的标签直接用中文；英文只用于确实需要的产品名和技术名。
- `.pill` / `.tag` / `.dot`：状态胶囊、标签、状态点。`.tag.plan` 用暖色，是页面上唯一允许出现未实现功能的地方：产品页写「规划中」，已知限制页写「未实现」（那一页整页就是在讲未做的部分，用更直白的词）。
- `.btn` / `.btn-primary`：44px 高（触控最小尺寸）。主按钮颜色跟 GUI。
- `.card` / `.cards`：`auto-fit, minmax(260px, 1fr)`，一列到三列自适应。
- `.banner`：深蓝横幅，在首页只说明目前的开发状态，不把阶段数当作装饰性卖点。
- `.roadmap`：三节点路线图，桌面横排（节点间连线），手机竖排。节点三种状态：当前（实心 + 光环）、进行中（空心蓝圈）、之后（空心灰圈）。
- `.flow`：四步流程，桌面四列、卡片间 CSS 画的箭头，手机竖排。
- **设备框 `.device`**：36px 标题栏（三个中性圆点 + 等宽字体标题）+ `aspect-ratio: 1440/900` 的屏幕。截图 `object-fit: cover`，因为所有渲染图都是 1440×900，不会裁切。
- **标注 `.callout`**：绝对定位在屏幕上，坐标用 CSS 变量 `--x / --y`，单位是图片宽高的百分比（例：`style="--x:88.7%; --y:17.4%"`）。图下 `.callout-list` 用 CSS 计数器自动编号，颜色与圆点一致。换截图后只需改坐标。
- **局部放大 `.zoom`**：同一张图再放一次，`translate(50% − zx, 50% − zy)` 把关注点移到中心再 `scale(5)`。为什么是 5：设备框在桌面约 600px 宽，图片缩到 0.42 倍；插图框是它的 42%，再放大 5 倍后界面文字约 1:1 像素，能读。图下方留 12% 内边距给插图溢出。
- **阶段条 `.stages`**：16 段等宽，只表达「16 个」（`builtin/knowledge/process/pc-recolor-outfit.process.yaml` 的 `stages:` 有 16 项），不标某段的状态（任务书没有给各阶段状态的事实）。全部 16 个阶段名用胶囊列出。
- 文章组件（`article.css`）：`.note-info / -tip / -warn` 提示框（图标 + 标题 + 正文）、`.code-block`（标题栏 + `<pre>`，JS 可用时加「复制」按钮）、`.table-wrap` 表格（可横向滚动）、`figure` + `figcaption`（`<b>图 N</b>` 前缀）、`.diagram` 内联 SVG（颜色全走令牌，两套主题自动适配）、`.pager` 上下篇、`.anchor` 标题锚点（悬停显示）。

## 5. 渲染图规范

- 文件：`assets/renders/*.png`，1440×900，真实 GUI + 演示数据（名称带「（演示）」），由主理用 `npm run gui:demo -- --shots <目录>` 生成。**不改截图内容，不把演示数据说成真实用户。**
- 当前用法：`home.png` 首页和产品页 hero（均注明演示数据）、文章图 3；`projects.png` 项目列表（功能 01）；`workflow.png` 制作进度（功能 02）；`project.png` 设计目标（功能 03）；`booth.png` 素材（功能 04，含局部放大）；`core.png` 核心管理（功能 05、文章图 1，含局部放大）；`settings.png` 设置（功能 06）。
- 标注坐标按当前截图量过；换图后要重新量。量法：目标点像素 ÷ 1440（或 900）。
- 图片本身不做滤镜、不合成假界面；透视、光晕、标注、放大都由 CSS 完成。
- alt 文本写「这张图里有什么」，并注明「演示数据」。

## 6. 可访问性与性能

- 对比度：36 对前景 / 背景组合用 WCAG 公式逐一算过（脚本见施工过程），浅色最低 4.61:1（`--muted` 在 `--bg` 上），深色最低 5.69:1，全部 ≥ 4.5:1（AA 正文标准）。
- 键盘：跳到正文链接、所有交互元素可聚焦、`:focus-visible` 2px 描边。页面不依赖 JS：文章的目录高亮与复制按钮是渐进增强。
- 图片全有 alt；装饰性 SVG `aria-hidden`；标注圆点 `aria-hidden`，含义由图下的有序列表提供；示意图有 `role="img"` + `aria-label`。
- `prefers-reduced-motion` 关闭动画与平滑滚动。
- 体积：首页实际加载的 `index.html`（15 KB）+ `site.css`（30 KB）+ `logo-96.png`（22 KB，页头）+ `logo-48.png`（6 KB，页脚），合计约 141 KB（不含渲染图，预算 1 MB）；`favicon-32.png`（3 KB）与 `apple-touch-icon.png`（69 KB，仅 iOS 添加到主屏时取）另计；`og.png`（210 KB）只被社交爬虫取，不进页面加载。渲染图每张 110–220 KB。无外部 CDN、字体服务或统计脚本。

## 7. 已知限制与下一步建议

1. **阶段名的措辞**：产品页的阶段胶囊与 README 已改用 GUI 的叫法（检查素材、确认制作方案、准备工程、装配服装、调整颜色、制作换装菜单……），与截图一致；以后阶段改名时，GUI 词表（`harness/src/shared/labels.ts`）、产品页与 README 一起改。
2. **文章列表页**（`articles/index.html`）还没有，模板页的上下篇是占位。
3. **没有手动主题切换**：只跟随系统。加一个切换需要少量 JS + `localStorage`，令牌已经支持（把 `[data-theme]` 选择器接到现有两套值上即可）。
4. **日文版**：结构可直接复用，正文需要人工翻译；建议在公开发布档做 `/ja/`。
5. **OG 图**（`assets/img/og.png`，1200×630）按浅色站 + 深蓝横幅风格生成；如换 Logo 或口号需重出。
6. **入场动画**在无头截图工具里会让 hero 显示为空（见 2.4）。如果日后要做自动视觉回归，给截图命令加 `--virtual-time-budget=10000`。
7. **`assets/renders/core.png` 的过期问题已解决**：重出的 `core.png` 里「AI 与执行」列出的是当前实际可配置的 API 接入方（`pi · deepseek`），不再把 Codex CLI 与 Claude Code 画成接入的执行方（本版停用订阅接入，见 `决定记录/D-8`）。
8. **文章页 `articles/demo.html` 仍是模板页**：正文技术内容与产品页口径未逐段同步（首页与产品页的文案已按 D-7/D-8 改过），且 `articles/index.html` 列表页仍不存在。
9. **三个 Logo 文件没有任何页面引用**：`assets/img/logo-192.png`（77 KB）、`logo-512.png`（79 KB）、`logo-512.webp`（70 KB）在 HTML / CSS / JS / 文档里都搜不到引用；实际用的是 `logo-96.png` 与 `logo-48.png`。它们会随 `site/` 一起被部署，属 226 KB 死重。本轮只更正了第 6 节对 Logo 体积的描述，**没有删文件**——是否删除或改用它做 `srcset`/PWA 图标由协调者决定。
