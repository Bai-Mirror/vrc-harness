# 案例：交付打包出过的事故与修法

## 打包排除规则递归命中，插件源码被排掉

- **症状**：客户打开交付工程，编译报 `CS0234`；交付包里 Gesture Manager 缺了 19 个文件（`Packages/vrchat.blackstartx.gesture-manager/Scripts/Editor/Library/` 与 `Scripts/Runtime/Library/` 下的 `.cs` 及其 `.meta`）。
- **机制**：打包时用 7z 的 `-xr!Library` 排除 Unity 的 `Library/` 目录，但 `-xr!` 会递归匹配**任意层级**的同名目录，把插件内部叫 `Library` 的源码目录也排掉了。同样危险的名字还有 `Temp`、`Logs`、`obj`、`Captures`。
- **判据**：排除规则必须锚定工程根（只匹配顶层的写法，或改用 `-i@list` 白名单）；打完包后 `7z l` 搜 `Packages/**/Library/`，命中数必须 >0，为 0 说明插件内部同名目录被误排。
- **修法**：用原交付包内容＋只含这 19 个文件的修复件重打（不拿开发工作副本代替，那里有审查代码与编辑器连接包）；新旧包成员逐个比对：工程内文件 11361 → 11380，新增 19、删除 0、变化 0，逐文件 CRC 与 SHA256 一致；成品解到新目录冷导入，退出 0、编译与依赖错误 0；旧包改名留底，新包记录大小与 SHA256。
- **适用条件**：所有用 7z / zip 命令行打 Unity 工程包的场合。客户总包按规程用 store 方式的 ZIP；7z 压缩包只作本地中间产物，不作交付格式。
- **证据等级**：单一案例（候选）——一个 Kipfel 客户工程的交付事故与修复。

## 打包与清理脚本默认只演练

- **症状（风险）**：清理脚本删错文件无法回头；有些生成资产太大不进 git，删了只能从某个菜单重新生成，甚至无法重生成。
- **机制**：交付前清理要在性能优化之后做；提前真删等于白做，还可能删掉之后步骤要用的东西。一个工程里有一个 118 MB 的生成网格资产被 git 大文件规则排除，重生成入口只有一个编辑器菜单项——它是整单唯一「删了就没了」的文件。
- **判据**：脚本默认 `DRY_RUN=1`，必须显式 `DRY_RUN=0` 才动手；每个删除、打包动作都走同一个函数，演练时只打印「将要做什么＋目标大小」；动手前对不可再生的文件做白名单断言，不在就 `exit 1`；每一步的后置判据在脚本里自动查，不过就退出。
- **修法**：清单逐项取证（路径、大小、依据）；工程专用脚本与通用工具副本分三列（通用副本 / 本单专用 / 拿不准）交人判断，不由脚本自己决定删哪些；中间报告类文件列出来由人判定，不自动删。
- **适用条件**：交付前清理与打包。
- **证据等级**：单一案例（候选）——一个 Milfy 工程的交付脚本任务。

## 解包脚本取错工程根

- **症状**：批量解包存档后，有的工程被当成打不开或路径错乱，只能手动重解。
- **机制**：脚本按「第一个子目录」取工程根；压缩包根部没有外层目录时就取错。
- **判据**：工程根 = 同时含 `Assets/` 与 `ProjectSettings/` 的最浅目录；对「有外层目录」与「没有外层目录」两类压缩包各做干跑自检。
- **修法**：改判据后跑自检（3 个样例全过）再批量使用。
- **适用条件**：批量解包历史存档或交付包复核。
- **证据等级**：单一案例（候选）。

## 修复已交付的包：以原包为底，不以开发副本为底

- **症状（风险）**：已交付的包需要补件或清理时，直接从开发工作副本重新打包，会把审查代码、编辑器连接包、测试产物、Play 副作用一起带进去。
- **机制**：开发副本在交付后仍被当作工作区使用，内容已与交付时不同。
- **判据**：选定交付基线（例：用 `git log --stat -- ProjectSettings` 找出批处理的 iOS 支持项改动与形态键钳制开关改动，基线应在它们被还原之后，且与最初入库版本逐字节相同）；用实际交付包直接比对基线。
- **修法**：以原交付包为底加修复件；或在开发副本上按清单清理（审查工具目录、`manifest.json` 与 `packages-lock.json` 里的编辑器连接包条目、`ProjectSettings` 还原到基线），保留修复资产；之后跑缺失项五查与冷导入。
- **适用条件**：重交、补件。
- **证据等级**：多工程验证——一个 Rurune 客户工程（清理开发副本并按基线还原）与一个 Kipfel 客户工程（以原包为底补件并冷导入）各自完成并验收。
