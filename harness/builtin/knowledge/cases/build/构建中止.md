# 构建中止案例

## 案例：插件该生成的骨骼、菜单、参数全都没有：场景里挂了两个 AvatarPoseSystem

- **症状**：SDK 只报「Preprocess Callback Failed」。AvatarPoseSystem 该生成的骨骼、菜单、参数全都没生成；后面 AAO 抱怨「检测到未知的组件类型」；控制台上最显眼的是一条「PhysBone 超过 256」的警告。
- **机制**：场景里挂了两个 AvatarPoseSystem 预制体。这个插件只允许挂一个，多了就在自己的 pass 里抛 `InvalidOperationException`（异常信息是日文）中止，异常被 NDMF 吞进 `Error Reported`，控制台上不显眼；没人处理的组件残留到后面的 pass，于是 AAO 报未知组件。那条 PhysBone 警告是 NonFatal，根本不是阻塞源。
- **判据**：日志里筛 `Error Reported`；按组件类型数一遍只允许单例的插件各有几个实例。
- **修法**：删掉重复的那一份，再构建。
- **适用条件**：NDMF 管线、装了只允许挂一个的插件的工程（成文时为一个 Milfy 素体工程上的 AvatarPoseSystem）。

## 案例：追着 NonFatal 的 PhysBone 警告做合并，真正中止构建的是配错的 MergePhysBone

- **症状**：同一轮构建中止的排查里，花了很长时间追「PhysBone 超过 256」这条警告，甚至写了硬合并工具想把数量压下去；构建照样中止。
- **机制**：那条警告是 NonFatal，只是提醒。真正报 Error 的是本工程自己加的 3 个无效 AAO MergePhysBone。早先的检查按「组件所在物体的父对象」判断配置是否合法，把坏配置全部判成了正常；正确的口径是每个目标 PhysBone「有效根」的父对象。
- **判据**：只追 `Error Reported` 里的条目；MergePhysBone 的校验按有效根的父对象判。
- **修法**：修正或移除无效的 MergePhysBone，再构建。
- **适用条件**：使用 AAO MergePhysBone 的工程。

## 案例：两个互不相关的插件在同一次构建里一起抛空引用：工程里有编译错误

- **症状**：一个面捕版头像突然传不上去：服装管理插件 MapleCloset 与 Triturbo 面捕的量化步骤在同一次构建里同时抛 `NullReferenceException`；此前两次上传都是好的。
- **机制**：工程里有脚本编译不过，编辑器程序集是坏的，`AnimatorState.AddStateMachineBehaviour<T>()` 静默返回 null，于是所有往动画层里添加 Parameter Driver 的插件一起失败。早期记录里的起因是：为切换场景临时写的一个小工具用了不存在的公开 API，编译错误恰好出现在点上传之前。
- **判据**：多个互不相关的插件同批失败，先查编译错误；按日志行号把编译错误出现的时间与失败构建的时间对齐（未实测）。
- **修法**：先清编译错误，再构建。往别人正在用的工程里加临时脚本，加完立刻确认编译通过。
- **适用条件**：往动画层添加 StateMachineBehaviour 的插件较多的工程。

## 案例：每次进 Play 都卡住、编辑器调用全超时：VRCFury 参数超限弹了单按钮对话框

- **症状**：进 Play 之后，通过编辑器桥发出的调用连续超时，Unity 日志里是 `MCP-FOR-UNITY: Command TCS timed out (N consecutive)`，CPU 掉到 0；每次进 Play 都一样。
- **机制**：VRCFury 在测试构建时发现参数超限（342/256，压缩后仍有 291），弹出「would have failed to upload」的单按钮警告（无条件调用 `DisplayDialog`），编辑器主线程被挡住。只要参数没砍到 256 以下，每次进 Play 都会弹。
- **判据**：截屏，或枚举 Unity 进程的可见窗口，确认有没有对话框。
- **修法**：场景已存盘、且没人在用这个编辑器时，按 PID 结束 Unity（不要用带路径的 `pkill -f` 模式），并还原被 Play 改写的 `ProjectSettings.asset`；根治是把参数砍到 256 以内。
- **适用条件**：VRCFury 工程。成文时在 Linux 宿主上、没有界面自动点击工具，点不掉对话框。
