# 优化：PhysBone 降级的案例

## PhysBone「零手感合并」：判断「没有动画写入」要读构建后的控制器

- **症状**：合并脚本的计划阶段判定 6 组 PhysBone 参数逐字段相同、可以无损合并；逐组复审后 6 组全被否决，最终可合并组为 0，PB 数不变。
- **机制**：
  1. 计划只扫描了描述符里的动画层与 Animator，看不到 VRCFury、MA 在构建期生成的开关：4 组在完整预处理后的控制器里有对成员的 `m_IsActive`、`VRCPhysBone.m_Enabled` 写入，或 pull、radius、maxAngleX 曲线，或一个有效根下挂着多条子链。
  2. 用脚本添加的 AAO MergePhysBone，`endpointPositionConfig` 默认是 Clear（只有组件 Reset() 才改成 Copy）；一组链设置了 `endpointPosition=(0,0.06,0)`，直接合并会丢掉末端，被预检拦下。
  3. 最后一组的宿主上已有 MergePhysBone，拒绝叠加。
- **判据**：可查问句：判「无动画写入」时，读的是编辑态描述符层，还是 `OnPreprocessAvatar` 之后的控制器？合并前逐字段回读（抽查 3 组共 153 个字段差异为 0）、碰撞体集合一致；合并前后用同一口径读 SDK 的 PB、Transform、Collider、Check 四项并确认无循环依赖。
- **当时的修法**（人工作业，供理解机制）：动画写入检查改读完整预处理后的控制器；把「宿主已有 MergePhysBone」列为排除条件；需要保留末端时显式设置 endpoint 为 Copy。零手感口径下无可合组时，是否放宽口径交用户决定。
- **在 Harness 流程里**：在 optimize 的 design.json 里，physbone_actions 只对 Runtime 报出 redundant_with（逐字段等价且碰撞体为保留项子集）的组写 remove_duplicate；构建后控制器对成员有写入的不合并，不自行合并不同骨链。
- **适用条件**：Shinano 素体、多套厂商服装、AAO MergePhysBone 已接管部分链的工程。
- **证据等级**：单一案例（候选）

## PhysBone 降级前先对准基线：以完整构建链后的读数为准，禁用的组件也计入评级

- **症状**：两份文档里的 PB 数一份是 207（NDMF 烘焙克隆体的报告）、一份是 142，据此算出的「要降到 Poor 还需砍多少」完全不同；降级方案一度把 207 当基线。
- **机制**：
  1. 口径不同：207 / 905 / 22 / 980（PB / Transform / Collider / Check）来自较早的烘焙克隆体；完整 `OnPreprocessAvatar` 链（含 AAO 已有的 MergePhysBone）后的 SDK 读数是 142 / 925 / 21 / 774，后者才是当前基线。
  2. 性能等级取所有项里最差的一项；菜单里默认关闭、处于禁用状态的 GameObject 与组件也计入评级，「关服装时关 PB」只改善运行时负担，不降评级。
  3. 合并组件数下降时，Transform 与 Check 不会同比下降。
- **判据**：VRChat PC 阈值：Poor 为 PB 32 / Transform 256 / Collider 32 / Check 512，Medium 为 16 / 128 / 16 / 256。该例整体 VeryPoor 同时被面数 922,682 与材质槽 147 锁定，只降 PB 改不了综合评级。合并时非源子链要写进 `ignoreTransforms`，并确认 Spine、Head、眼、四肢未被覆盖；空的 MergePhysBone 会让构建中止。
- **当时的修法**（人工作业，供理解机制）：给用户三种取舍：A 只合并参数逐字段相同的链（零手感，接受 VeryPoor）；B 裁末端骨、停次要摆件，把 PB 四项压到 Poor（近看摆动变少）；C 另做轻量版头像（移除非默认服装与第二发型的 PB）。该例用户选 A。每条路线完成后都以完整构建链的 SDK 读数验收。
- **在 Harness 流程里**：以 perf.json 的构建后读数为基线写 rationale；PB 要降到哪一档、接受哪种取舍交用户决定，不在 design.json 里擅自裁骨。
- **适用条件**：多套服装、带大量物理骨的头像（Shinano 素体）。
- **证据等级**：单一案例（候选）

## 头发穿进身体：给长发链加躯干碰撞体，按「链长够不够得着」挑链

- **症状**：客户反馈头发穿进身体；实测所有发链都没挂躯干碰撞体（素体发 10 条、一套厂商发型 27 条全是 0，另一套只有头部碰撞体）。
- **机制**：身上现成的胸部碰撞体挂在尾巴对象下面，会被耳尾轮盘关掉，不能借用；它的上沿到 y=1.045，等于把脖子当成 12 cm 粗，会把贴着颈侧垂下的发链顶出去。碰撞按「骨线 + radius」计算，radius 接近 0 时骨线贴到皮肤，网格仍会穿进去。
- **判据**：新碰撞体挂在永远激活的主骨架胸骨上（例：世界 (0, 0.790, 0.045)，胶囊 r=0.115、h=0.30，覆盖 y 0.640–0.940，低于肩线 0.949）。挑链用两条几何判据：已有骨在胶囊里面的不挂（会把造型顶变形）；链根到胶囊表面距离 ≥ 链长 + 3 cm 的不挂（怎么甩都够不着）。不能看静止时离得多近：10 cm 长的呆毛离胸口 24 cm 永远碰不到，40 cm 的后发一低头就贴上去。
- **当时的修法**（人工作业，供理解机制）：该例挂上 24 条长发链、跳过 28 条，并把素体发链的 radius 从 0.001–0.010 提到 0.015。代价：评级口径 +150 次碰撞检查，当前发型实际每帧 +95 次（346 → 441，仍比优化前的 682 低 35%）。修后需 Play 实测，记录里当时标为待测。
- **在 Harness 流程里**：optimize 的设计输入没有新增碰撞体的字段；遇到头发穿身体时写明链长、链根到身体的距离等证据，停下交人。
- **适用条件**：Kaguya 素体的长发发型。
- **证据等级**：单一案例（候选）
