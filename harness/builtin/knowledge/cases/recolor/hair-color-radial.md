# 改色：发色轮盘与渐变贴图的案例

## 发色轮盘按材质槽写：只换头发槽，材质副本保留变体继承

- **症状**：要给三种发型加一个「原色 / 银灰 / 渐变 / 金」的发色轮盘。厂商已有银灰和金的材质，但头发渲染器有多个材质槽（假阴影、毛绒、金属宝石、缎带），整件换材质会把这些槽一起换错。
- **机制**：
  1. 厂商的整包变色预制体只覆盖头发主槽（槽 0），假阴影槽（槽 1）在各颜色下不变。
  2. 一些厂商头发材质是材质变体（`m_Parent` 指向基础材质），用 `new Material` 复制会丢掉继承。
- **判据**：
  - 先盘点：每种发型的头发渲染器、每个材质槽挂的是什么、厂商变色件覆盖了哪些槽。
  - 生成后回读：该例 16 条材质曲线只写「这一槽挂的是本发型头发材质」的槽，跳过 7 个非发槽；Play 读回 3 种发型 × 4 档，头发槽材质逐档正确，非发槽四档都不变。
  - 校验脚本要同时数普通曲线与对象引用曲线：只数 `GetCurveBindings` 时，整条都是材质曲线的 clip 会以 0/0 假通过。
- **当时的修法**（人工作业，供理解机制）：用一个 Float 做轮盘（档中点 0.125/0.375/0.625/0.875），层放在发型层之上，按槽写 `m_Materials.Array.data[i]` 对象引用曲线；渐变材质用 `AssetDatabase.CopyAsset` 复制厂商材质再换贴图，保留 `m_Parent`，厂商原件不动。参数预算加 8 bit（一个 Float）；后来按用户选择扩成 5 档，仍是同一个 Float，不增加参数位。
- **在 Harness 流程里**：改色走 generate-recolor-candidates 工具与 plan.yaml 的 recolor.targets；多档材质切换的发色轮盘超出本流程的改色范围，写明需求交人。
- **适用条件**：Kaguya 素体配多种厂商发型、lilToon 材质；同样适用于其他按材质槽换色的轮盘。
- **证据等级**：单一案例（候选）

## 头发渐变贴图：按骨链弧长逐 UV 岛归一化，只刷被覆盖的像素

- **症状**：用世界高度做「发根→发梢」渐变，翘起的呆毛整条颠倒；按共享顶点找 UV 岛，一件后发 3147 个面被拆成 3147 个岛；第一版把图集留白也刷了色，自检的根部亮度从 49 虚高到 109。
- **机制**：
  1. 呆毛发梢比发根高，按高度排序会反过来（按弧长与按高度逐顶点平均差 0.34–0.45）。
  2. FBX 发丝是分裂法线，顶点索引不共享，要按 UV 量化后的边配对找真实的岛（该例 1–41 个岛）。
  3. 留白区不被任何三角形采样，刷了也看不见，却会污染统计。
- **判据**：
  - t 定义为骨链弧长（挂在 Head 下的第一根发骨为 0），逐 UV 岛归一化；回读自检：渐变图按顶点 UV 采样与弧长的相关 r=+0.76~+0.98（厂商原贴图为 −0.51~+0.03）；t 对全局 v 的 R² 只有 0.05~0.14，说明不是屏幕横切。
  - 只刷覆盖掩膜膨胀 8 像素以内：网格 UV 99.97%~100% 落在已刷区；alpha 与源逐像素相等；去趋势笔触相关 r=0.79~0.91（笔触保留）；连跑两次文件哈希不变。
  - 出图工具的两个坑：Blender `Image.save()` 默认按 sRGB 做 gamma 编码（回读差 0.25，改自写 PNG 后为 0）；PNG 行序与 Blender 像素行序相反。
- **当时的修法**（人工作业，供理解机制）：出图 = `ramp(根色, 梢色)` × 保笔触的亮度系数 0.35；根色取默认贴图均值 × 0.42，梢色取厂商对应色贴图均值。逐岛归一化会让过渡带参差，这是设计取舍，要不要改成按高度分带交用户看渲图定（代价是短刘海到不了梢色）。
- **在 Harness 流程里**：本流程没有生成渐变贴图的通道；写明需求与判据，停下交人。
- **适用条件**：Kaguya 素体的三种厂商发型；需要 Blender 读 FBX 骨骼与 UV。
- **证据等级**：单一案例（候选）

## 审美候选交用户挑：同机位对照图，差别太小的要明说

- **症状**：眼睛光效有 4 个候选材质、渐变梢色有「银灰」「金」两种、狐耳缩放有 1.0 / 0.9 / 0.8 三档，执行方无法替用户决定。
- **机制**：审美取舍没有客观判据，只能让用户在可比较的图上选。
- **判据**：候选在 Play 里用运行时副本逐个替换（材质换槽、骨骼只改运行时 localScale），不落盘；同机位、同光照渲图拼成对照图；某个候选与另一个几乎一样时要量出来告诉用户（一例厂商金色本就是浅奶油色，「渐变→金」与「渐变→银灰」贴图均值 222/219/217 对 219/218/220，渲图差 0.3%）。
- **当时的修法**（人工作业，供理解机制）：用户选定后再落盘到所有头像根的对应位置；用户也可能选「维持现状」（狐耳维持 1.0）或「两种都要」，后者优先在同一个参数里加档，不增加参数位。
- **在 Harness 流程里**：改色阶段按 plan.yaml 的 candidates 生成 3–5 档候选交用户挑；差别太小的在说明里写明。
- **适用条件**：配色、光效、比例、材质质感类的审美决定（Kaguya、Shinano 两个素体的工程）。
- **证据等级**：多工程验证
