# 案例：服装装配中的判断与失误

## 跨素体服装：骨槽都落在素体骨架里不等于贴合

- **症状**：给 Kaguya 新加三套外购服装，其中两套的「骨槽口径」读数全部合格（一套 927 个骨槽、一套 3556 个骨槽都落在 Kaguya 的 `Armature` 子树内，未合并骨 0），渲图却显示一套左袖悬空、右袖缺失，另一套袖套悬空；第三套可用。
- **机制**：骨槽落在素体骨架里只说明「绑上了」，不说明「形状对」：服装网格是按别的素体的体型做的，绑到 Kaguya 骨上后位置和比例仍然不对。其中一套服装包里根本没有 Kaguya 版预制件（只有 Rurune 的 12 个预制件），骨名匹配只有 73/255。
- **判据**：开工前先查服装包是否提供目标素体的版本（预制件或 FBX）；没有目标素体版本的，骨名匹配率与骨槽口径都只是必要条件；最终以多视角渲图（含侧面、袖口、下摆）判贴合。
- **修法**：没有目标素体版本的服装，先向需求方说明风险与工作量（需要重新适配或改做），不要用「骨槽全部落进骨架」当完成依据。
- **适用条件**：跨素体装配（服装包里没有目标素体的专用版本）。
- **证据等级**：单一案例（候选）——一个 Kaguya 工程的三套新衣试穿。

## 导入顺序让 FBX 材质重映射过期，材质槽大面积为空

- **症状**：一套服装的某个颜色版本（`(pink)`）26 个材质槽里 25 个是空的。
- **机制**：多个包连续导入时，导入顺序导致该 FBX 的材质重映射结果过期（引用的材质在它导入时还不存在）。
- **判据**：装配后逐个渲染器数空材质槽，应为 0；上传前终检同样要求「洋红 0、空材质槽 0」。
- **修法**：重新导入该 FBX（Reimport）后空槽 25 → 0；不要手工一个个补材质。
- **适用条件**：一次导入多个互相引用的厂商包之后。
- **证据等级**：单一案例（候选）。

## 新建的资产与脚本要连同 .meta 一起提交

- **症状**：换机或从版本库重新检出后，新做的动画片段、编辑器脚本的引用断开。
- **机制**：Unity 用 `.meta` 里的 GUID 建立引用；只提交资产本体、漏了 `.meta`，别处的引用在另一台机器上就解析不到（Unity 会生成新的 GUID）。
- **判据**：提交前核对：每个新增资产都有对应的 `.meta` 同时提交；删除资产时 `.meta` 一起删。
- **修法**：补交漏掉的 `.meta`（必须是原来那份，不能重新生成）。
- **适用条件**：所有用版本库管理的 Unity 工程。
- **证据等级**：多工程验证——一个 Shinano 工程（同类漏交第二次）与一个 Milfy 工程（新片段漏交）各自发生。

## 厂商没要求、实测也没穿模的，不要改

- **症状（风险）**：审查工具报出一串「可能要补键」的候选，逐个都补上会改动大量本来正常的配置。
- **机制**：检测工具按规则给出「可能缺键」的嫌疑，但厂商设计本身可能就不需要（例：袜子按平脚建模、鞋底是平的），规则看不到这些设计意图。
- **判据**：改之前要有证据——厂商在别处有明确做法，或实测（量距、渲图、盲测）看到了问题。实例：一个 Rurune 工程里三双鞋的数据都支持「不需要平脚键」，需求方最终决定三双都不改；一个 Shinano 工程的一双袜子按平脚建模、只穿袜时没有脚趾穿出，判定不补键；一个 Kaguya 工程里两款没有任何身体收缩机制的厂商服装，不臆补「漏挂」。
- **修法**：把候选分成「证实有可见后果」「证实没有」「未测」三类；只修第一类，第三类写进待测清单，不写成缺陷。
- **适用条件**：审查、回归阶段对候选问题的处置。
- **证据等级**：多工程验证——Rurune、Shinano、Kaguya 三个工程各自的处置记录。

## 为新衣装另建头像根时，原根必须零改动

- **症状（需求）**：需求方想在同一工程里另做一个只带原装和几套新衣的头像，或因为组件数超限要把服装分到两个头像。
- **机制**：新根与原根共用同一批资产（菜单、控制器、材质）；在新根上改共享资产或复制菜单树，会改到原根或让其他插件的菜单安装落空。
- **判据**：新根从现有根（通常是在用的面捕根）复制出来；复制后原根的序列化对比 diff 为 0 行（实例：原根 6753 个物体 diff 0）；新根的菜单要保持能被各插件的菜单安装找到（不要整树复制菜单）；两个根分别按 SDK 口径计数，各自 ≤ 上限。
- **修法**：所有改动只落在新根；每一步做完断言原根与原面捕根的序列化哈希不变；旧根如不再上传，在场景里默认停用而不是删除。
- **适用条件**：同一工程维护多个头像根。
- **证据等级**：多工程验证——一个 Kaguya 工程（新衣根）与一个 Milfy 工程（按组件数拆成两个衣装根）各自完成。
