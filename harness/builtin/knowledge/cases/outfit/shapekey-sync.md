# 装配：服装跟随身体形态键的案例

## 同名胸型键没人同步：服装恒为 0，胸型拉满时整片穿出

- **症状**：素体菜单里的胸型轮盘能改身体胸型，但某套服装的衬衫、外套、领带、两个兜帽不跟着变；胸型拉满时，渲图里双乳整片穿出衬衫和外套（正面肤色像素 6,822）。
- **机制**：这 5 件服装网格带着与身体同名的胸型键（`Breast_small_____胸_小`、`Breast_big(limit)`、`Breast_Big_____胸_大(mizuki)`），但没有任何组件把身体的值同步过去，恒为 0。同工程里厂商的其他套装预制体都自带 MA Blendshape Sync（共 72 个），只有这一套缺。胸型轮盘本身是 1D BlendTree（阈值 0/0.5/1），默认 0.31。
- **判据**：
  1. 列出身体被驱动的形态键，再列出每件服装上同名的键；有同名键却不在任何 Blendshape Sync 或动画的写入列表里，就是候选。
  2. 胸型取 0、默认、1 三档读回，服装键与身体键逐值相同才算修好。
  3. 第二个模型盲测：修前修后各档混排 5 张图、答案表留在本地，它只指认了两张「未同步 + 胸型拉满」，零误报。
- **当时的修法**（人工作业，供理解机制）：在这 5 件上各加一个 MA Blendshape Sync，从同一头像根下的身体 `Body_b` 同步件上存在的那几个键（兜帽只有后两个）；场景里有两个头像根就两根都改，共 10 个组件。修后胸型拉满肤色像素 6,822 → 837，与手动模拟同步的渲图逐视角相同（剩余差异是抽绳的 PhysBone 摆动）。
- **在 Harness 流程里**：装配会为带着素体同名形态键、却没有任何驱动的衣物自动补 Blendshape Sync（`D-139`，补了哪些写进装配回执）；执行方仍加不了别的同步，也不能补帧。自动补之后同名键检查仍失配的，按同名键逐件列出候选，写明哪件、哪些键、三档读数，停下交人（换预制件或改方案）。
- **适用条件**：Rurune 素体配 PLUMARIUM「Re-Poppin' Cat」套装；同名键不会自动同步，任何「素体带可调体型键」的头像都适用。
- **证据等级**：单一案例（候选）

## 同名键没同步不一定是缺陷：先量距或看图定性，再决定补不补

- **症状**：同名键跟随检查列出候选：服装件带着与身体同名的体型键却没人同步（身体 38、件 0，或件恒为 100）。
- **机制**：两类情况都不是缺陷：
  1. 厂商有意固定：一个双肩包自带 `Breast_Big(mizuki)=100`，让背带贴合默认胸型；背带走肩上与身体两侧，不经过胸区。
  2. 件落在该键几乎不动的区域：一件外套的胸前挽具与上衣带 `Breast_small` 却没人同步；量距发现挽具到身体 p50 在件 0 或 38、身体 0 或 38 时都是 5.8 mm，上衣 14.5 → 14.1 mm，变化可以忽略。
- **判据**：候选先定性再动手：
  - 量距：件与身体的距离分位数随该键变化多少；
  - 看图：胸型取 0、默认、1 三档，上身四个方位渲图，看是否进入该区域、穿模或悬空；第二个模型核对 0 指认。
- **当时的修法**（人工作业，供理解机制）：两类都不补同步，保留厂商设定；交付件少动为宜。检查结果里记为「已定性、不修」，避免下次重复报。件上另有身体没有的同名键（如另一套命名的大胸键）时，也不接。
- **在 Harness 流程里**：在装配说明或诊断里写明「已定性、不修」及依据，不为有意固定的键补同步。
- **适用条件**：Rurune 素体的两个工程；检查工具只列候选、不下结论（「只列不判」），定性要靠量距或渲图。
- **证据等级**：多工程验证

## Blendshape Sync 的参照键在这个素体版本里不存在：同步静默空转，胸贴离胸 3–4 cm

- **症状**：一件新衣（Trinity2088「The Velour」Kaguya 版）的胸贴整体离开胸口：到身体最近面的距离中位 30.49 mm、p95 39.72 mm，100% 顶点离身体 >1 cm、穿入 0%；束身衣与上衣也同向偏离。视觉模型也指认悬空。
- **机制**：厂商的 MA Blendshape Sync 以身体的 `Breast_Big_____胸_大` 为参照键，而该素体版本（Kaguya v1.06）的身体网格 `Body_b` 只有 `Breast_Big_____胸_大(mizuki)`。MA 重新绑定时找不到参照键就跳过（`refIndex == -1` 时 continue），组件存在却不同步；服装上该键停在厂商默认值 100，把胸贴顶离身体。
- **判据**：
  - 每条 Blendshape Sync 都要检查：参照网格上有没有源键、服装网格上有没有目标键（该例 3 条绑定的 `refMeshHasKey` 都为 false）；
  - 修后在阶段截断的克隆上验证：身体该键为 0 时三件衣服跟到 0，胸贴中位 1.03 mm、>1 cm 为 0%；反向验证：身体键设 100，衣服跟到 100。
- **当时的修法**（人工作业，供理解机制）：只在场景实例上把 3 条绑定的参照键改指 `Breast_Big_____胸_大(mizuki)`，恢复「衣服跟身体胸型」的厂商原意；不手工把衣服键设成 0，不改厂商预制件。落盘差异应只有这 3 条绑定（该例 15 行）。
- **在 Harness 流程里**：执行方改不了实例上的绑定（装配层由 Runtime 按方案重建），`blendshape_sync_missing_keys` 会每次阻断；逐条确认参照键在当前素体版本上是否存在，不存在的写明候选键名，停下交人。
- **注意**：编辑模式下 NDMF 预览会实时把 MA 同步应用到场景实例（实例读数已是 0，而预制件默认是 100），克隆会继承这个预览值；取证时在克隆上显式按同步关系设值，不依赖预览状态。
- **适用条件**：Kaguya 素体不同版本的键名差异；任何跨素体版本复用的 Blendshape Sync。
- **证据等级**：单一案例（候选）
