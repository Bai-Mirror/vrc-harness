# 装配：形态键数据的迁移与复用案例

## 形态键数据包哈希对不上：先比轴向和顶点顺序，再按位置一一对应搬键

- **症状**：服装厂商用 BlendShare 分发的形态键数据（例如袜子的短袜键 `[Short_key]`）应用到工程里的 FBX 时，三件网格都报哈希不符，厂商推荐的穿法（长裤套装保留短袜）无法实现。
- **机制**：
  1. 工程网格与厂商生成件只差网格空间轴向（工程为厂商的 (x, −z, y)），且顶点被导入优化重排了顺序，几何本身相同。
  2. BlendShare 的顶点哈希只看数组最后 8 个元素，哈希不符不代表网格不同。
- **判据**：
  1. 先证明两份厂商数据给出的位移相同（该案例差 0）。
  2. 把工程网格按轴向旋转后，按位置建立一一对应：最大距离 0、双射 1360/1360、UV 差 0，才允许搬键。
  3. 卸掉临时装的数据包后重开工程，导出的网格与卸前逐值相同。
- **当时的修法**（人工作业，供理解机制）：按对应关系把 `[Short_key]` 位移复制到网格副本，另存为普通网格资产并替换引用，不依赖数据包在构建时运行；临时装的 BlendShare 包移除，`packages-lock.json` 还原。再在长裤对象上挂 MA Shape Changer 把袜子的 `[Short_key]` 设为 100，并从长裤的开启 clip 里删掉「关袜子」的曲线，让袜子跟随袜子开关。结果：裤口到鞋口之间露出的身体点 474→0。
- **在 Harness 流程里**：本流程没有搬运形态键数据的通道；数据包哈希不符时写明轴向与顶点序证据，停下交人。
- **适用条件**：Kipfel 素体配 atelier-kotone「デフォルト衣装アレンジセット」；任何「形态键数据包按顶点哈希校验」的场合都可按此思路先比轴向与顶点序。
- **证据等级**：单一案例（候选）

## 给衣物补形态键：Blender 往返在 Unity 里会错位，改在 Unity 里用位移场加帧

- **症状**：某套服装的乳贴网格只有大胸键、没有小胸键（厂商没做小胸适配）。身体默认胸型为 38 时，其他上衣都经 MA Blendshape Sync 跟随，乳贴不跟随。最初凭渲图说它「陷进皮肤」，量距后发现实际是外浮 4–8 mm，定性方向反了。
- **机制**：
  1. 缺键：乳贴没有 `Breast_small`，身体缩胸后乳贴原地不动，离开皮肤外浮。
  2. 第一版在 Blender 里给 FBX 副本加键，Blender 内往返核对全部为 0 偏差；但导入 Unity 换上后一烘焙，世界坐标与原件最多差 71 mm（顶点差到米级、bindpose 差 1.27、新键位移被缩小 100 倍）：导出的网格空间与厂商 FBX 不同，而渲染器沿用场景里原来的骨骼。只在 Blender 里验证，没在 Unity 里验。
- **判据**：
  - 量乳贴顶点到身体最近点的距离（p05/p50/p95，mm）：原件在胸型 0 时 0.50/1.33/2.14，胸型 38 时 4.36/5.74/7.38，胸型 100 时 11.43/14.48/17.43。
  - 修后必须在 Unity 里烘焙量距，并在 Play 里按胸型 0/0.31/1 读回键值与身体一致。
- **当时的修法**（人工作业，供理解机制）：在 Unity 里做：身体该键取 0 和 100 各烘焙一次，得到世界位移场；乳贴每个顶点取身体最近 4 个点做反距离加权；用乳贴的蒙皮矩阵逆变换回网格空间；作为新帧加到原网格的副本上（基础几何、权重、bindpose 与原件逐位相同），只替换渲染器的 `sharedMesh`，再加 MA Blendshape Sync。修后胸型 38 时 0.48/1.28/2.06 mm，100 时 0.48/1.13/1.95 mm；世界位移最大 17.19 mm，与 Blender 里算的量级一致。同法补第二个键 `Breast_big(limit)`：身体 100、乳贴 0 时 p50 14.95 mm → 补后 1.66 mm。
- **在 Harness 流程里**：本流程没有给衣物补形态键的通道；写明缺键与距离证据，停下交人。
- **适用条件**：Rurune 素体配 ILE'S SHOP「Esmera」的乳贴件；胸型轮盘默认 0.31。任何「厂商件缺少与身体同名的体型键」都可用此法。
- **证据等级**：单一案例（候选）
