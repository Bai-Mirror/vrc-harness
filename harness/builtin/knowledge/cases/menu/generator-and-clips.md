# 菜单阶段案例：生成器、clip 与人形层

## 报告说覆盖了十几个物体，落盘的 clip 却是零曲线

- **症状**：生成报告写「覆盖 16 个物体」，落盘的 `.anim` 只有 1307 字节、零条曲线；另一次同批生成的 7 个菜单资产里 3 个落盘为空。此后的验收图全错，而脚本日志是对的。
- **机制**：先 `AssetDatabase.CreateAsset` 落盘，再往 List 字段或 clip 上加内容、再 `SetDirty` 与 `SaveAssets`，这些改动不保证刷得出去，且不是每次都丢。
- **判据**：生成完从磁盘重新加载资产，比较 `GetCurveBindings` 条数、菜单控件数与内存是否一致；或比对资产在各次提交里的字节数（空菜单约 330 字节，每个控件约 200 字节）。
- **修法**：内存里填满后最后才 `CreateAsset`，按依赖顺序（被引用的子菜单在前）；落盘后回读断言。
- **适用条件**：任何用编辑器脚本生成菜单、clip、ScriptableObject 的流程。

## 四档贴纸轮盘整档没反应：补丁脚本追加的层权重为 0

- **症状**：菜单里有四档贴纸轮盘，拨哪一档都没变化；参数面板显示参数在变。
- **机制**：补丁脚本用 `ac.AddLayer("…")` 追加层后没有设权重，新层 `defaultWeight` 为 0，曲线写不出去；同工程主生成器与另一个补丁都显式写了 1，只有这个补丁漏了。MA 合并只把每个控制器的第 0 层强制为 1，这个 0 一路带到构建后。
- **判据**：构建后逐层读权重，对照全部 LayerControl；权重 0 且无人抬权即为此类。
- **修法**：取出 `ac.layers` 数组、设 1、整体回写，并回读断言。补丁之前跑过的组合遍历与构建期复验全部作废，要重跑。
- **适用条件**：往已有控制器里追加层的补丁脚本。

## 刚修好的遮罩极性自己复发：两个补丁脚本写同一个字段

- **症状**：lilToon 第二主色的遮罩极性修好了，过一会儿又变回错的。
- **机制**：两个补丁脚本都写 `_Main2ndBlendMask`，一个挂原始遮罩、一个挂取反遮罩；修好后为别的事重跑了前一个，原始遮罩被写回。
- **判据**：对该字段名在所有补丁脚本里 grep，命中必须为 1。
- **修法**：前一个脚本改为引用后一个脚本产出的遮罩，并在两个文件头写明该字段由谁负责；更好的是合并成一个脚本。
- **适用条件**：同一工程积累了多个可重跑的补丁脚本时。

## 换整套看起来什么都没变，渲染器数骤降：删生成目录后克隆根的引用被置空

- **症状**：Play 里切整套毫无变化；构建后渲染器数从 166 掉到 114，所有衣服被合成一块。
- **机制**：生成器开头删掉整个生成目录再重建，Unity 把场景里指向被删资产的引用全部置空；生成器只按名字给原件头像根接回引用，而面捕安装器克隆出的第二个头像根（实际会被上传的那个）上的 13 处引用（Merge Animator、描述器菜单、各 Menu Installer）留空。构建时自己的 FX 没合进来，优化器把所有衣服当静态件合并。
- **判据**：按资产 `.meta` 的 guid 在场景文件里计数，与上一次提交逐资产比较，少了即断链；同时数场景里有几个头像根、各自是否激活。
- **修法**：不删目录，原地复用资产（GUID 与引用都不动）；不得已时把原件根上的生成引用按「同相对路径、同类型同序号组件、同属性路径」回填到其他根（只填空、不覆盖）。
- **适用条件**：场景里存在多个头像根（面捕安装器等会克隆头像）时重跑生成器。

## 菜单改名后，插件菜单掉回了根菜单

- **症状**：把子菜单改名后，插件的菜单不再出现在指定子菜单里，而是出现在根菜单。
- **机制**：用 `DeleteAsset` 加 `CreateAsset` 实现改名，资产换了 GUID，插件 Menu Installer 的 `installTargetMenu` 与描述器的 `expressionsMenu` 静默变成 null。
- **判据**：grep 场景 YAML 里该 `objectReference` 的 guid，与资产 `.meta` 的 guid 对不上。
- **修法**：用 `AssetDatabase.RenameAsset`（返回值是错误串，非空即失败）；菜单与参数资产已存在就清空内容原地复用。
- **适用条件**：分区重划、菜单改名时。

## 调用菜单项报「invalid, disabled, or context-dependent」：名字里有斜杠

- **症状**：自动化调用一个刚写好的编辑器菜单项，报找不到，看起来像编译失败。
- **机制**：菜单项名字里写了「鞋 / 袜」，Unity 把 `/` 当子菜单分隔符，实际建出了多级菜单，目标项不存在。
- **判据**：`Assembly-CSharp-Editor.dll` 比脚本新，说明编译已完成，问题在名字、拼写或类不是 static。
- **修法**：菜单项名字里不用 `/`。
- **适用条件**：Unity 编辑器菜单项。

## 配饰关着，衣服上的帽子仍被压住：关档阈值写成 0.01

- **症状**：配饰轮盘拨到「关」，衣服上的帽子、手套仍然不显示。
- **机制**：程序取每档区间中点，三档轮盘的「关」档值是 0.167；压制层阈值写成 0.01，关档被当成开，压制一直生效。
- **判据**：压制条件里的常数是否与档数有关。
- **修法**：阈值一律写 `1/档数`（或按区间写上下界）。
- **适用条件**：用 Float 轮盘值驱动压制或派生层时。

## 扩档后关掉耳尾，衣服自带的猫耳也用不了了：阈值压制覆盖了后续档

- **症状**：耳尾轮盘从两档扩到四档后，把耳尾关掉时，衣服自带的猫耳反而显示不出来。
- **机制**：「压制衣服自带猫耳」的条件还是「参数 > 1/2」，原本只压第 2 档（新耳尾），扩档后连第 3 档（关闭）一起压了。
- **判据**：扩档后逐条复查所有以该参数为条件的转移。
- **修法**：改成区间；一条转移里的条件只能是「与」，离开区间要两条转移（低于下界、高于上界各一条）。
- **适用条件**：任何轮盘扩档之后。

## 部位开关与压制层整层被跳过：单关键帧 clip 的长度是 0

- **症状**：某些工具处理或模拟动画层时，部位开关层、压制层像不存在一样。
- **机制**：部位开关与压制层的 clip 全是单关键帧，`clip.length` 为 0；工具里 `if (clip.length <= 0) continue;` 把整层跳过。
- **判据**：检查 clip 是否只有 `t=0` 一个关键帧，以及读取代码是否拿长度当门槛。
- **修法**：生成时给单帧 clip 补一个 `t = 1/60` 的尾帧；读取时不拿长度当门槛。
- **适用条件**：生成或解析单帧开关 clip 的工具。

## 整套衣服都不显示：只写了子件，父物体关着

- **症状**：整套切换档写了该套各部件的 `m_IsActive = 1`，整套仍不显示。
- **机制**：厂商服装挂在一个共用的父物体下，父物体是关着的，只写子件无效。
- **判据**：对默认态要写 1 的每条路径，逐级查祖先是否激活、是否有层管理。
- **修法**：父物体进同一张曲线表；生成器加祖先自检，有祖先关着且无人管就抛错。
- **适用条件**：一组件共用一个空物体作父的服装包。

## 手势表情全失效，手一直半握：手指遮罩没有曲线

- **症状**：加了一个姿势层后，所有手势表情失效，手一直保持半握。
- **机制**：该层遮罩包含手指，clip 里却没有手指曲线；人形层遮罩认领的部位没人写时输出零姿势，手指的零姿势是微微成爪，把下面厂商的手势层整个盖掉。
- **判据**：遮罩含手指的层，每个状态是否都有手指曲线。
- **修法**：手臂层与手指层拆开，各用各的遮罩；手指只在需要时用权重接管。
- **适用条件**：人形头像上添加涉及手臂或手指的动画层。

## 抱物姿势纹丝不动：叠加层 clip 是恒定值

- **症状**：Additive 叠加层的姿势开关打开后，手臂没有任何变化；曲线、遮罩、权重、状态机都检查过是对的。
- **机制**：人形叠加算的是「当前帧 − clip 首帧」，脚本生成的 clip 没有 additive reference pose，恒定 clip 的增量恒为 0。
- **判据**：clip 的首帧与后续帧是否相同。
- **修法**：写成 `t=0 → 0`、`t=RAMP → 目标值` 的斜坡，不循环，播完停末帧；状态上挂 `VRCPlayableLayerControl(Additive → 1)` 排除可播放层权重为 0。
- **适用条件**：在 Additive 可播放层做人形叠加姿势。

## 手臂上的呼吸微动消失：叠加姿势层用了 Override

- **症状**：加入 Additive 可播放层的姿势层后，站立时手臂的呼吸起伏没了。
- **机制**：Additive 可播放层第 0 层是 VRChat 自带的呼吸微动（含手臂曲线）；新层混合模式设成 Override，Idle 的空 clip 把手臂呼吸抹成 0。
- **判据**：新层的混合模式。
- **修法**：层混合模式改为 Additive；关闭姿势时也不要把 Additive 可播放层权重拨回 0。
- **适用条件**：往 Additive 可播放层加层时。

## 手指姿势 clip 写了，运行时手指不动：肌肉曲线绑定名写错

- **症状**：同一份 clip 里手臂姿势正常，手指完全不动；回读曲线条数是对的。
- **机制**：手指曲线写成了 `Left Index 1 Stretched` 这类 `HumanTrait.MuscleName` 风格，而手指的绑定名是 `LeftHand.Index.1 Stretched`；错名 `SetEditorCurve` 照收、`GetCurveBindings` 照数，只在运行时静默失效。
- **判据**：Play 下 `GetHumanPose` 读出的 40 条手指肌肉恒为 0.000。
- **修法**：按 `<Side> <Finger> <剩余>` → `<Side>Hand.<Finger>.<剩余>` 变换，以 SDK 自带 `proxy_hands_fist.anim` 为准。
- **适用条件**：脚本生成含手指的人形 clip。

## 代码设了 Gesture 遮罩，场景里仍是默认手部遮罩

- **症状**：脚本把描述器 Gesture 层的遮罩改成了自定义遮罩，运行时手臂姿势仍不生效；场景里该字段还是 `vrc_HandsOnly`。
- **机制**：场景重载、预制体覆盖或别的工具重跑把字段冲掉；另外 `baseAnimationLayers[2].isDefault` 为 true 时描述器上的遮罩与控制器本来就被忽略。并且经 NDMF、VRCFury 构建后，可播放层遮罩实际取自合并后控制器第 0 层的 `avatarMask`。
- **判据**：场景 YAML 里搜 `propertyPath: baseAnimationLayers.Array.data[2].mask`，看 `objectReference` 的 guid 指向哪个文件；构建后读合并后控制器第 0 层的遮罩。
- **修法**：改完立即复核场景实际值；需要改可播放层遮罩时，用负 `layerPriority` 的 Merge Animator 把带目标遮罩的空层顶到第 0 层。
- **适用条件**：需要让 Gesture 层写手臂的头像。

## 粒子档第二次拨到就没有粒子：切了物体激活

- **症状**：轮盘第一次拨到特效档能看到粒子；拨走再拨回来，物体是激活的，一颗粒子都没有。
- **机制**：`ParticleSystem.playOnAwake` 只在 Awake 触发一次，关掉再开时系统停在 Stopped。
- **判据**：该档切的是 GameObject 的 `m_IsActive` 还是 `ParticleSystemRenderer.m_Enabled`。
- **修法**：物体常开，动画只切 `ParticleSystemRenderer.m_Enabled`，组内所有渲染器（包括不发射的根容器）都写；`cullingMode` 设 `AlwaysSimulate`。
- **适用条件**：菜单切换粒子特效。

## 六色轮盘有两对档位看起来一样：档位差在贴图

- **症状**：用材质属性动画做的六色轮盘，六档里有两对完全相同。
- **机制**：一对的 `_Color` 相同、差在法线波纹贴图，另一对差在 matcap 贴图；贴图引用不能被动画化，属性动画做不出这个差别。
- **判据**：先跑「各份材质之间差哪些属性」的全表，看差异是否包含贴图。
- **修法**：改为用 PPtr 曲线 `m_Materials.Array.data[N]` 切换整份材质。
- **适用条件**：外观档位之间的差异包含贴图时。

## 尾巴条数轮盘在离屏图上几档一模一样

- **症状**：用 Driver 设厂商「尾巴条数」参数的轮盘，离屏对比图里各档完全相同。
- **机制**：厂商用一个 Float 参数加一棵混合树实现条数（9 个阈值 0.1～0.9）；轮盘各档靠 Parameter Driver 在运行时设这个参数，编辑期预览与离屏渲染都不执行 Driver。
- **判据**：该档是否只由 Driver 区分。
- **修法**：这是预期，不是缺陷；在 Play 中验证，并在出图工具里注明「Driver 档位在离屏图上相同」。
- **适用条件**：档位差异完全由 Parameter Driver 产生时。

## 改了参数重渲，图纹丝不动：取到了烘焙克隆体

- **症状**：修改后重新出图，图与修改前完全一样。
- **机制**：手动烘焙在场景里留下 `<名字>(Clone)`；离屏渲染把它也当头像渲了一遍，文件名多出 `_00_`、`_01_` 索引，联系表按文件名排序取到的是停在烘焙时刻的克隆体。
- **判据**：场景里的头像描述器数量；出图目录里是否有带索引的文件名。
- **修法**：烘焙工具跑完清掉新增的头像；出图工具排除带索引的文件名。
- **适用条件**：手动烘焙后接着出图的流程。
