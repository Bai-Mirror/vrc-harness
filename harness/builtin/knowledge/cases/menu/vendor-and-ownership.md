# 菜单阶段案例：厂商参数与属性归属

## 耳朵网格开着，骨骼还折在头里：写了网格没改厂商参数

- **症状**：帽子关掉后猫耳网格显示了，但耳朵的骨骼仍是收进头里的姿势，看起来「耳朵长在头里面」。
- **机制**：厂商的帽子参数通过两层同时驱动帽子网格、一个鱼骨发饰、猫耳网格和猫耳左右骨骼姿势。生成层直接写了帽子网格的显隐，厂商参数仍为开，厂商的猫耳控制层一直播「猫耳收起」。
- **判据**：读厂商该参数所驱动的全部层与 clip，列出它管的网格、骨骼与形态键。
- **当时的修法**（人工作业，供理解机制）：通过改厂商参数切换（菜单直接绑定厂商参数，或状态上用 Driver 设值），不写帽子网格；帽子与猫耳的互斥交给厂商层。
- **在 Harness 流程里**：把帽子的厂商 ON/OFF clip 登记为对应 control 的 `vendor_clips`，Runtime 会连骨骼与猫耳曲线一起复制；不能绑定厂商参数，也没有 Driver。
- **适用条件**：厂商用参数层管理「帽子与耳朵」联动的素体包（在 Kipfel 上实测）。

## 关了外套，上衣还缺一截：厂商参数顺带写的收缩键没复原

- **症状**：用部件开关关掉外套后，上衣下摆仍是收起的，露出一截肚子。
- **机制**：厂商外套的 ON 动画在上衣网格上把两个脊柱收缩键写成 100（把上衣下摆收进外套里防穿模）。生成层只关了外套网格，厂商外套参数还是 1，ON 动画一直在播，上衣就一直是收起的。
- **判据**：读厂商 ON clip 的全部曲线，找写在其他可见网格上的 `blendShape.*`。
- **当时的修法**（人工作业，供理解机制）：部件开关层的 On、Off 状态各挂一个 Driver，让厂商参数跟着开关走（On 设 1、Off 设 0），厂商层会自己把形态键还原。
- **在 Harness 流程里**：把外套的厂商 ON/OFF clip 登记为 `vendor_clips`，收缩键曲线随之复制进部件层；没有 Driver。
- **适用条件**：厂商换装动画在别的网格上写防穿模键的素体包（在 Kipfel 上实测，同类还有背包参数连带骨架里的玩具）。

## 穿外挂整套时，身体的肩膀也被收掉：厂商换装动画常驻写身体键

- **症状**：切到外挂整套后，素体的肩膀与上臂仍处于收缩状态。
- **机制**：厂商衬衫的 ON 动画把身体网格上的 `Shoulder_OFF`、`Upper_arm_OFF` 写成 100，防止肩膀从衬衫里穿出来；衬衫参数默认为 1，这条动画一直在播，穿别的整套时肩膀也被收掉。
- **判据**：把「谁在写这两个身体键」全部列出，看写者是否随衬衫真正显示而生效。
- **当时的修法**（人工作业，供理解机制）：把身体收缩键挂到衬衫部件本身的 MA Shape Changer 上（Set 100）：部件失活即不生效，天然跟着衬衫走；厂商动画里那两条曲线归零（保留曲线结构）。过渡做法是在整套层选外挂整套时把这两个键写 0、选素体默认时不写。
- **在 Harness 流程里**：菜单改不了厂商换装动画；装配阶段的 `vendor_blendshape_curves_zeroed` 会拦下这类服装，写明交人（换预制件或改方案）。
- **适用条件**：厂商用常驻动画写身体收缩键的素体包（在 Kipfel 上实测）。

## 帽子再也打不开：在切换 clip 里写了厂商管的属性

- **症状**：切到某个外挂发型后再切回，帽子开关怎么拨都打不开。
- **机制**：为实现「换外挂发型时关掉帽子」，在发型 clip 里直接写了帽子的属性为关；这等于一直按住它，厂商帽子层之后写开也被盖掉。
- **判据**：分清需求是「切换时关一次」还是「开着期间一直压」；前者不应出现在任何 clip 曲线里。
- **当时的修法**（人工作业，供理解机制）：在外挂发型的状态上挂 Driver，进入时把厂商帽子参数设为 0；用户之后仍能再打开。
- **在 Harness 流程里**：没有 Driver，「关一次」做不到；帽子若属于素体，部件开关也碰不到它。写明交人。
- **适用条件**：切换一个功能时需要顺带关闭另一个厂商管理的功能。

## 换发型再换回来，猫耳消失了：厂商层播一次就停

- **症状**：切到外挂发型再切回原版发型，猫耳不再出现，重新开关帽子后才恢复。
- **机制**：厂商猫耳控制层的结构是「初始 → 播完 → 无条件跳 Empty」，Empty 只有一条出边（帽子开才回初始）。外挂发型的 clip 写了猫耳关，切回原版时生成层停写、厂商层也不写，值卡在关。
- **判据**：读厂商层状态机，找无条件进入的空状态及其出边。
- **当时的修法**（人工作业，供理解机制）：单开一层持续驱动猫耳显隐，复合条件为「原版发型且帽子关 → 显示；帽子开或非原版发型 → 隐藏」（多个「或」拆成多条转移），骨骼姿势仍交给厂商层。
- **在 Harness 流程里**：没有组合条件与持续驱动层，做不到；写明交人。
- **适用条件**：厂商层存在「播一次就停」结构，且生成层曾覆盖它管的属性。

## 切一圈衣服再切回来，关掉的皇冠自己回来了：两层 Driver 设同一参数

- **症状**：头饰关着 → 随便切一套衣服 → 再切回第 0 套 → 皇冠又出现了。时有时无，不稳定复现。
- **机制**：整套层第 0 档无条件用 Driver 把 `Crown_OFF`、`Cardigan_OFF`、`Bottoms_OFF`、`Slippers_OFF` 四个厂商参数设为 false（即显示），而这四个参数同时被四个部件开关层驱动。Driver 只在进入状态时写一次，谁最后进入谁生效，层序不起作用。
- **判据**：在构建后控制器里数写每个参数的层数，大于 1 即为此类。
- **当时的修法**（人工作业，供理解机制）：整套层不再 Set 这些参数；需要跟随某个开关时用 Driver 的 Copy（取反用 `convertRange`），或把参数收归部件开关一处。
- **在 Harness 流程里**：本流程没有 Driver，Runtime 生成的层每条属性只有一个所有者；厂商层自己的 Driver 互相打架时写明交人。
- **适用条件**：同一厂商参数既被整套层、又被部件开关层用 Driver 写。

## 关掉上衣后，头上浮着一对垂耳：该「只压不放」却写了开

- **症状**：头部轮盘选「服装头部饰品」档、上衣关闭时，头上仍挂着一对没有兜帽本体的垂耳。
- **机制**：垂耳长在 LEM 夹克的兜帽上，由厂商参数 `LEM/Jacket` 与「上衣」开关共同管理；头部轮盘该档硬写 `Jacket_Ear = true`，绕过了上衣开关。
- **判据**：问「这件出不出现是否还取决于别的开关」；是，则本档不能写开。
- **当时的修法**（人工作业，供理解机制）：该档不写（交给原所有者），其余档写关——轮盘只能压，不能放。配套做所有权审计。
- **在 Harness 流程里**：部件层两态都由 Runtime 写满，轮盘层只写衣装根与 BoneProxy 可视件；回归里出现同样症状时，查 `design.json` 里 `objects`、`disable_when_on` 的归属，改不了的交人。
- **适用条件**：构建后 WD=OFF、不写即透传时；WD 被改写为 on 时要把条件合进所有者层。

## 同时穿着两条裙子：该「只放不压」却两条都写开

- **症状**：部件开关「裙裤」打开后，两条裙子同时出现。
- **机制**：厂商用 `LEM/Jacket` 在 `Skirt` 与 `Skirt_Jacket` 之间二选一；生成层的开态把两条都写成显示，覆盖了厂商的选择。
- **判据**：读厂商 clip，确认这两件是否由同一参数互斥。
- **当时的修法**（人工作业，供理解机制）：开态不写（让厂商挑），关态才写关（两条一起收）。
- **在 Harness 流程里**：部件层两态都写满，写不出「开态不写」；二选一交给厂商 clip（登记 `vendor_clips`），或只收默认那条，其余写明交人。
- **适用条件**：厂商用单个参数在两件之间二选一；构建后 WD=OFF 时。

## 光脚时脚踝还挂着两圈绑带：显隐归错了部位

- **症状**：脱掉鞋袜光着脚，脚踝上还缠着两圈丝带；需求是「鞋或袜任一开着就显示，两个都关才隐藏」。
- **机制**：Violet Nocturne 的 `Straps`（材质名叫 `Anklet`，是缠在脚踝的绑带）被归在「上衣」部件里，鞋袜开关管不到它。
- **判据**：问「把上衣脱光只穿鞋，这东西该在吗」；答案决定它归谁。
- **当时的修法**（人工作业，供理解机制）：新开一层做它的所有者，On、Off 两态都写 `m_IsActive`（鞋 If → On；袜 If → On；鞋 IfNot 且袜 IfNot → Off），同时从「上衣」的对象表里删掉它、补进覆盖率自检的排除名单；在交付说明里写明「关上衣不再影响它」。
- **在 Harness 流程里**：由鞋、袜组合决定显隐做不到（没有组合条件）；写明交人。
- **适用条件**：某件显隐是几个部件开关的布尔组合。

## 默认态头上有两副耳朵：聚合开关的作用域没封闭

- **症状**：加载头像后，头上同时出现一副猫耳和素体自带的熊耳；另有两个发型自带的兽耳没有任何开关。
- **机制**：「兽耳尾」开关只管一部分来源，两个品牌的猫耳发箍被归到「头饰」，发型自带的兽耳没进任何开关，同一位置的来源被拆到多个控件下，默认值各自为开。
- **判据**：按位置枚举全部来源（场景枚举加逐件单独渲染），统计默认态开着的来源数，大于 1 即失败。
- **当时的修法**（人工作业，供理解机制）：同一位置的全部来源收进一个轮盘，0=关、其余每档一件，默认一档。
- **在 Harness 流程里**：只有衣装一个轮盘：各来源分属不同衣装时由轮盘互斥；同一衣装内的多件同位置件按用户任务选一件做开关，其余写明交人。
- **适用条件**：素体、服装、发型、外购配饰都可能提供同部位件的工程（在 Milfy 上实测）。

## 头两侧浮着两颗铃铛：厂商开关连带的挂件没收全

- **症状**：压制猫耳发箍后，发箍消失了，两颗铃铛还浮在头两侧。
- **机制**：厂商的猫耳发箍开关 clip（`KemoHandMB/Toggle-NekomimiHB`）同时写发箍本体和两颗铃铛；压制表是按名字列的，只写了发箍。
- **判据**：读厂商 `Toggle-*` clip 里的全部路径，与压制表逐条对照。
- **当时的修法**（人工作业，供理解机制）：压制表按厂商 clip 的完整路径清单填写。
- **在 Harness 流程里**：登记厂商 clip 为 `vendor_clips` 时全部曲线会一起复制；`objects` 也按厂商 clip 的完整路径列全。
- **适用条件**：压制或收纳厂商开关管理的配饰时。

## 结构相同的耳、尾开关，一个正常一个不正常：空 clip 加 WD=ON

- **症状**：耳尾轮盘第 0 档用 Driver 把耳、尾两个厂商参数都设为「显示」，结果素体耳显示、素体尾不显示。
- **机制**：厂商耳、尾两层的「显示」档挂的是 0 条曲线的 clip 且 WD=ON，还原的是构建那一刻场景里的物体状态；场景里耳的物体 `activeSelf=True`、尾的物体为 False。
- **判据**：对靠 WD=ON 空 clip 还原的物体，核对场景 `activeSelf`。
- **当时的修法**（人工作业，供理解机制）：不改场景；在排在厂商层之后的自己的层里，对该档显式写一条显示曲线，其余档不写。
- **在 Harness 流程里**：把该对象列进对应 control 的 `objects`（部件层两态都写），前提是它在衣装根下；不在的写明交人。
- **适用条件**：厂商开关层用空 clip 加 WD=ON 表示「默认」。

## 两件几乎重合的网格同时显示：厂商 ON clip 收进了备选件

- **症状**：打开某件外套后，出现两件几乎重合的网格（约 70% 顶点相距 ≤ 0.5 mm），表面闪烁或穿插。
- **机制**：按厂商 ON clip 的路径把物体收进开关组时，把一件开襟、大胸型的备选件（如 `outer_breast_big_open`）也收了进来；说明书要求这类件二选一，预制体里它默认是关的。
- **判据**：对 clip 里的每条路径，查它在厂商预制体里默认 `m_IsActive` 是否为 1；默认关的是备选件。
- **当时的修法**（人工作业，供理解机制）：备选件不进组，保持预制体默认关；需要时单独做切换。只有说明书与单独预览都证明应联动时才逐路径放行。
- **在 Harness 流程里**：Runtime 发现厂商 ON clip 会打开默认关闭的对象时直接报错；只有说明书与单独预览都证明应联动时，才列进 `allow_default_off`。
- **适用条件**：厂商用 ON/OFF clip 表示部件组、同时附带胸型或开襟等互斥备选件时。

## 整套自带内衣，素体的内衣从髋侧露出来

- **症状**：穿上一套自带胸衣、内裤的第三方整套后，素体自带的内衣从髋侧顶出一圈。
- **机制**：同部位两层内衣都在显示。
- **判据**：逐套渲染，看有没有两层布料互相穿插。
- **当时的修法**（人工作业，供理解机制）：在整套层给素体内衣加「只在这一档写 0」的曲线，其余档不写；不新增开关、不占参数位。袜、鞋同理。
- **在 Harness 流程里**：整套层由 Runtime 生成，写不进素体件；外购整套下都不需要的素体内衣由方案 `hide_body_parts` 永久剔除，要按套切换的写明交人。
- **适用条件**：整套自带与素体同部位的件；「其余档不写」依赖构建后 WD=OFF。

## 做完一整套「按服装退让」机制，需求其实只要基线

- **症状**：为「胸部默认调到最大」实测了各服装支持到哪一档，生成了 34 条衣服侧曲线；最后得知需求是「基线（全 0）就够」，整套机制作废。
- **机制**：尺寸类需求没有先问清是「默认值」还是「最大值」。全 0 是厂商建模时的默认体型，每套衣服都照它做，天然适配；而素体出厂停在 `Breast_small=100`，比基线还小 9.9%，「设为 0」相对原状态本来就是放大。
- **判据**：设计前量出出厂值与基线之差，把数摆给用户。
- **当时的修法**（人工作业，供理解机制）：先问清需求再做机制；只需基线时不做退让层。
- **在 Harness 流程里**：menu 阶段没有等人的闸门：按方案与需求原话定，没写的按基线做，写进说明。
- **适用条件**：胸围、身高等尺寸类需求。
