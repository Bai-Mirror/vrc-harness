# 捏脸案例

## 案例：叠层卡片眼睛整体缩小，按深度分成前后两簇做相似变换

- **症状**：想让整只眼睛变小，厂商没有对应的形态键（「眼睛变小」类键的位移签名与闭眼键一致，是闭眼而不是缩小）；几种直觉做法分别造成横向内缩、最深的卡片从脸皮穿出、接缝裂开。
- **机制**：眼睛是几十张叠在一起的平面卡片，层间距最小 0.03 mm；只有「整组做同一个相似变换」在数学上保证层序不乱。眼部卡片的深度分布天然是两簇：前簇可见，深簇在脸皮之后、看不见，两簇之间有空隙。
- **判据**：眼部网格与皮肤网格（该例为 `Body_eye` 与 `Body_skin`）共用顶点数为 0；没有跨卡片接缝点跨越前后两簇的分界；变换后跨卡片接缝（原本 <0.3 mm 的顶点对）不显著变大；深度变化 `|Δy|` 最大值 < 2 mm。
- **修法**：工作文件放在素体包解压目录内，保留 `*_prebake_backup.blend` 与 `*_unity_original.fbx` 两个还原点；按深度分前、深两簇：前簇做完整的三维相似变换，深簇只缩 x、z；不要按高度阈值把眉毛拆出来单独处理（眼线卡片本身纵跨眼睛到眉毛，任何水平切分都会把一笔连续线条切成两段）；画在脸皮上的眼窝阴影要补一份带平滑衰减的同比收缩，否则睫毛收缩后与眼窝之间露缝，俯视能看到后面的眼球；表情键的位移同乘缩放系数，相似变换下两侧同乘同一系数，闭合关系精确保持。
- **适用条件**：叠层卡片式眼部的素体；这属于动网格造型，默认不走，只在厂商键确无此方向、且用户明确点头时启用，并由用户判形。只在一款素体上做过。

## 案例：外眼角要「转平」，厂商键到天花板后改用自建闭式旋转键

- **症状**：委托方要外眼角不上扬、转平，厂商键怎么调都压不下去。
- **机制**：唯一相关的旋转键只作用在十几个顶点上，拉到远超 100 也几乎看不出，还会削掉上睑的弓度；调眼睛高度的键主要在改眼裂大小。厂商键能做到的上扬压低量有天花板。
- **判据**：先给出厂商键的实测天花板（该例为 −13%），证明确实没有对应方向；自建键验收两条：受影响顶点落在掩膜满强度区内的比例（该例睑缘 89.5% 在内、区外 0 个），以及不受采样漂移影响的功能判据（闭眼时上睑顶点到最近下睑顶点的距离，旋转 0／1／2 三档为 8.699／8.667／8.907 mm，±2.4%）。
- **修法**：用户点头后，建绕深度轴的面内旋转键（叠层卡片的层间距不变），位移按建键那一刻的混合形状算：`新键位移 = R(当前混合) − 当前混合`；做到 −36%。用户后来改了其他键时重建一次。
- **适用条件**：一个 Milfy 工程。先用「按未变形位置定的采样列」量闭合，得出「旋转让闭眼残留从 6.13 mm 涨到 6.62 mm」的假结论，原因是顶点转出了采样列；换成最近点距离后才得到正确判断。

## 案例：捏脸后下眼睑到脸颊一带起褶皱，局部同步位移场修复

- **症状**：用户反映捏脸让网格出现凹凸纹理；cavity 渲染里下眼睑—脸颊带有褶皱棱线。
- **机制**：不是法线陈旧（厂商法线是手绘场，跟随旋转无效），也不是整体拉皱（逐顶点 Laplacian 的 p99 从 4.757 mm 降到 4.675 mm，增量的 p99 只有 0.132 mm）。真因是局部挤瘪加卡片层间互穿：对比厂商原版，网格自交从 632 处增至 666 处（新增 114 处，其中 66 对是透明脸卡片互穿），30 个面的法线转角超过 25°（最大 49.69°），60 个面的面积比低于 0.5（最小 0.129），无法线翻转。三项集中在同一条带（高度 1080–1128 mm），上眼睑带（转角 p99 9.03°、面积比最小 0.882）与嘴周带（9.55°、0.688）相对干净。
- **判据**：种子为新增自交面、转角 >20° 的面、面积比 <0.75 的面；修后三项硬门槛归零，总自交数不高于厂商原版（修后 629 < 632）。
- **修法**：只在种子邻域平滑位移场，邻域用 3D 半径而非网格连通性。扫了多组参数（r_smooth／r_blend／轮数 → 新增自交、>25° 面、面积 <50% 面、面积最小、对捏脸扰动 max／p99／mean）：4／10／1 → 16、0、0、0.552、1.43／0.73／0.11 mm；8／16／2 → 10、0、0、0.692、2.31／1.08／0.20 mm；10／18／2 → 0、0、0、0.726、2.54／1.19／0.23 mm（选用）；12／20／3 → 4、0、0、0.730、2.64／1.47／0.29 mm。再大反而回升，因为平滑半径超过卡片间距的尺度后开始互相带偏。
- **适用条件**：一个 Milfy 工程。参数与卡片间距、网格密度相关，换素体要重扫；反向评审还指出外眼角与上唇、人中仍有比原版略深的浅阶，脸颊峰值曲率被摊平约 5–10%，这些都在数值阈值以下。

## 案例：三项指标全部归零，上眼睑的阶梯横纹却一条没动

- **症状**：按自交、面法线转角、面积塌陷三项修完，下眼睑的硬暗线消了，上眼睑那种分层的横向明暗条带一条没动，在 Unity 的实际着色下被评审一眼看出。
- **机制**：三项量的都是「面自己」转了多少、塌了多少、穿没穿；阶梯横纹是相邻面之间的断阶。该带三项都没超标（转角 p99 9.03°，面积比最小 0.882，无新增自交）。
- **判据**：加两个量：相邻面二面角变化 Δdihedral（直接对应明暗断阶，是 toon 着色真正看到的量），以及位移场高频 `|Laplacian(D)|`（做种子用，更早暴露问题区）。拿额头（全程未动）当对照：Δdihedral>5° 的边数／p99／`|Laplacian(D)|` p99，上眼睑 34／5.43°／0.4445 mm，下眼睑 200／7.76°／0.4683 mm，嘴周 83／6.55°／0.227 mm，额头 0／0.07°／0.0386 mm；于是取 Δdihedral>3°、`|Laplacian(D)|`>0.06 mm。
- **修法**：把这两类点并入种子再修。修后超标边数上眼睑 34→10、下眼睑 200→14、嘴周 83→11，三项硬门槛仍为 0，对捏脸的扰动 p99 从 1.19 mm 升到 1.37 mm；对照带的 Δdihedral p99 从 0.07° 升到 0.34°、`|Laplacian(D)|` p99 从 0.039 mm 升到 0.171 mm，但超 5° 的边仍为 0。
- **适用条件**：一个 Milfy 工程；阈值只对该网格标定。

## 案例：导出时带出临时材质，脸用上了眼睛的材质

- **症状**：覆盖 FBX 后，Unity 里脸部显示成眼睛的材质。
- **机制**：为了在 Blender 里看清脸，把 Body 的三个厂商材质槽临时换成两个自建材质，跟着一起导出了；槽数变少，Unity 侧的材质数组错位。错误版本的 `Model` 节点数也比原版少一个（1986 对 1987），因为一个槽被并掉了。
- **判据**：二进制自检加一项：厂商材质名的出现次数与原版相等。
- **修法**：导出前把材质槽指回原来的材质数据块（它们通常还在 `bpy.data.materials` 里）；覆盖后重挂材质并扫空槽。
- **适用条件**：一个 Kaguya 工程；凡是在 Blender 里临时换过材质的导出都适用。

## 案例：清理按索引的权重覆盖，冒出错位的厂商默认值

- **症状**：烘焙删掉了一批形态键（该例从 668 条删到 644 条）后，清理场景里残留的两条按索引写的权重覆盖（`m_BlendShapeWeights.Array.data[N]`，索引 448、498，值都是 0），还原后嘴部键冒出 70 与 45 的非零值。
- **机制**：厂商 prefab 的默认权重按索引存，删键后同一索引指向了别的键。冒出来的正是厂商出厂的两个嘴型默认值（70、45）错位落到新索引上；那两条 0 覆盖是故意压住错位默认值的。
- **判据**：还原前逐条读 `PrefabUtility.GetCorrespondingObjectFromSource(smr).GetBlendShapeWeight(N)`；源值非 0 的保留 0 覆盖（或改 prefab 源）。验收是脸部网格的全部权重为 0（或等于定稿值），不是「覆盖条数为 0」。
- **修法**：恢复那两条 0 覆盖。
- **适用条件**：一个 Milfy 工程；任何按索引存储权重覆盖的情况都要这样查。

## 案例：候选开局全部给满，委托方逐条往回砍了十几轮

- **症状**：第一版候选把每个轴都给满（幼态、鼓脸、三条放大眼睛的键都是 1.0），委托方每一条都往回砍，来回十几轮；放大键被焊进了之后十一轮的基线，眼形只往上探（到 1.3）、从没往下试，最后委托方自己砍掉了 83%。
- **机制**：放大类的键给满很容易「过」；弧度类的键给满往往还不够。两类键的合适起点方向相反，而单向探索会把错误的起点一直带下去。
- **判据**：候选的扫描要双向（往上也往下）；起手值按轴分：放大类从弱起（0.15～0.30），弧度类从满档甚至外推起（1.0～1.5）。
- **修法**：按判据里的分轴起手值重出候选，并把「提案值 vs 定稿值」逐轮记下。
- **适用条件**：一个 Milfy 工程，起手值为该素体的键；换素体只迁移「放大类从弱、弧度类从强」的方向，不迁移具体数值。委托方偏好不同时可能相反。

## 案例：只看定稿值读不出偏好，提案与定稿的差才是信号

- **症状**：想从定稿总结委托方的审美，只看终值得不出规律。
- **机制**：信号最强的是「AI 给满、委托方砍掉」的那些键。例如放大眼眶的 `face_eye_big` 从提案的 1.0 被砍到 0.171，同时委托方自己把放大瞳孔的 `pupil_big` 加到 1.0——要的是大瞳孔，不是大眼眶。这条只看终值看不出来。
- **判据**：保留逐轮的提案值、定稿值与委托方原话；原话只在对话里、没有落盘时，会话结束就没了。
- **修法**：单独建一份逐轮决策与原话记录，作为审美反推的证据。
- **适用条件**：一个 Milfy 工程；委托方的几何画像（例如偏好大瞳孔、不放大眼眶）可以跨素体迁移，具体键值不可迁移。
