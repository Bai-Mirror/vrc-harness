# 参考图解读的案例

## 参考图结论先交独立模型证伪：逐条「支持 / 矛盾 / 看不出」，禁止附和

- **症状**：参考图解读写出的几条结论，经独立核对后被推翻或收窄：「帅气来自眼皮、眼尾与穿搭」的前提被否（三批核对都判五张图没有帅气，全是甜美萌系、地雷系）；「白发实为带紫调的银白」是从 2/5 张推到全体；一件饰品参考图被读成「独立线环叠压」，实为米兰螺旋编织网。
- **机制**：解读者会不自觉地为客户的文字需求在图里找依据，并把少数样本推广到全体；饰品结构在小图里容易看错基元。
- **判据**：送审设计要做到：每条结论单独给出，评审方只能答「支持 / 矛盾 / 看不出」，明写禁止附和；图分批喂；评审方不共享主对话的上下文。评审方自身前后矛盾的条目只作收窄依据。饰品参考图先问一句：基元是闭合环，还是连续丝？
- **当时的修法**（人工作业，供理解机制）：被推翻的结论改写依据（例：白发带紫的决定不变，但依据改成「两比两，用户知情后仍选紫调」）；前提被否的方向改为实验组并如实告知客户。
- **在 Harness 流程里**：本流程尚无参考图解读阶段；plan.yaml 的 notes 里只写核对过的需求结论，存疑的写明并交用户。
- **适用条件**：全定制单的参考图解读、饰品建模前的参考图读图；两个工程都出现过。
- **证据等级**：多工程验证

## 参考图计数按角色，不按张：同框的第二个角色会把「5/5」算错

- **症状**：「5/5 张有白发」「4/5 张有兽耳」这类计数被核对推翻：一张图里有第二个同框角色（黑色卫衣、无兽耳、非白发）；另一张是氛围参考，两个角色都是深色发，头上是恶魔角不是兽耳。
- **机制**：把整张图当成一个角色计数；没有先标出哪张图、哪个角色才是本单要做的角色。
- **判据**：解读前先给每张图标注「本单角色是哪一个 / 这张是不是氛围参考」；所有计数都以角色为单位，并写成「k/n 张」。
- **当时的修法**（人工作业，供理解机制）：计数重做；氛围参考图不参与五官与配色的计数，只参与风格元素（该例为蕾丝百褶裙、吊袜带、爱心发夹、颈圈等甜美洛丽塔与地雷系元素）。
- **在 Harness 流程里**：本流程尚无参考图解读阶段；遇到时写明计数口径，停下交人。
- **适用条件**：客户给多张参考图、其中混有多人图或氛围图的订单。
- **证据等级**：单一案例（候选）
