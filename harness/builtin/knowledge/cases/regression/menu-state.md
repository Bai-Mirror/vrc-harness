# 回归阶段案例：菜单串档与状态缺失

## 耳尾轮盘某档是空档：组合矩阵与构建期复验都没查出

- **症状**：耳尾轮盘的「猫耳尾」档拨过去没有任何变化；三十格组合矩阵与一次构建期烘焙复验都判正常。
- **机制**：该档的 clip 与关档的 clip 效果集合完全相同，猫耳、猫尾两个物件在三档里一次都没出现，也就是漏写了曲线。资产非空、能播、文件哈希不同，按文件比对查不出；渲染矩阵里「档位没接线」与「容器被服装关掉」渲出来一样，两路检查还各自给出「挂在服装子树下」这个自洽但错误的根因，照着挪容器后档位依然是死的。
- **判据**：把每档 clip 归约成「路径、属性、值」集合两两比较；grep 该物件是否在任何菜单资产里被提到过。
- **修法**：补写缺的曲线，并检查该物件的父链是否被别的层关掉。
- **适用条件**：多档轮盘与 N 选一开关的验收。

## 换了衣装，上一套的头饰还在：BoneProxy 逃出服装根

- **症状**：切到另一套衣装后，上一套的黑蕾丝发箍与珍珠吊坠仍戴在头上，还穿透了新衣装的贝雷帽；编辑期怎么检查都正常。
- **机制**：该服装的头饰组（4 个渲染器）挂了 MA BoneProxy，构建期被搬到 `Armature/…/Head/` 下；换装 clip 只写服装根的 `m_IsActive`，关不掉它。编辑期 BoneProxy 不生效，手动开关、编辑期渲图、按源层级的组合遍历都复现不了。这条是独立视觉评审在不知道设计意图时指认出来的。
- **判据**：烘焙体里该件最终父链上已没有原服装根，且合并后控制器里没有曲线控制它或其新父链的 `m_IsActive`。
- **修法**：每一个换装 clip 都显式写它的 `m_IsActive`（源路径即可），本套 1、其余每套 0；重新烘焙，并用真动画数据摆状态重渲验证。
- **适用条件**：服装里带渲染器的件挂了 BoneProxy。

## 回读与两千多格遍历全过，渲图里就是不出来：父物体无主

- **症状**：把一套耳尾接进头部轮盘第 1 档后，生成回读全过、2496 格组合遍历全过、所有权审计全过，渲图里耳尾就是不出现。
- **机制**：两个网格的父物体是关着的，没有任何一层写它；闭式判据只看被写的路径本身，不看祖先。
- **判据**：对默认态要写 1 的路径逐级查祖先，是否有关着且无人管的。
- **修法**：把父物体一并写进该档的曲线表；生成器加祖先自检，遇到无主的关闭祖先就抛错。
- **适用条件**：把已有物件接进新的轮盘档或开关时。

## 发型轮盘 0.3333 落进了下一档：Motion Time 边界要按 m_StopTime 算

- **症状**：审查时把发型轮盘设为 0.3333，本应是第 0 档，实际显示的是下一档的发型。
- **机制**：该轮盘用 Motion Time 驱动 clip，clip 的 `m_StopTime=1.0166667` 而不是 1；参数 0.3333 映射到 clip 时间 0.339，已越过 1/3 处的关键帧。真实边界约 0.3279。
- **判据**：档边界 = 关键帧时间 ÷ `m_StopTime`；取值用区间中点 `(i+0.5)/n`。
- **修法**：审查与脚本取值一律用区间中点；档位表写分数，不写四位小数。
- **适用条件**：Motion Time 驱动的轮盘。

## 厂商衣装轮盘最后一档永远选不到：循环 clip 的 1.0 回绕

- **症状**：厂商衣装轮盘拨到最右，显示的是第 0 档；最后一档（素体基础装）怎么也选不到。
- **机制**：厂商的换装 clip 有五个关键帧，分别在 0、¼、½、¾、1，且 `m_LoopTime: 1`；循环时参数 1.0 回绕到第 0 档。
- **判据**：新接手的 Motion Time 轮盘先查 `m_LoopTime` 与关键帧分布。
- **修法**：复制一份 clip 改为等分、关闭循环，不原地改厂商资产；末档区间写成 `[lo, 1]`（不循环）或 `[lo, 1)`（循环），不用 1.0 做档值。
- **适用条件**：厂商或用户自建的 Motion Time 轮盘。

## 拆掉三层后，同步开销只少了 2 bit：漏扫 Motion Time 参数

- **症状**：删除素体一个发型、拆掉只为它服务的三层后，构建后同步开销只从 254 降到 252。
- **机制**：按「转移条件 + BlendTree」只找到两个 Bool；另外三个 Float 是被拆三层的 Motion Time 参数（`m_TimeParameter`），没被扫到，仍以原价（24 bit）留在同步清单里。
- **判据**：拆之后全文 grep 参数名；最后看构建后的同步参数清单。
- **修法**：参数口子扫全：转移条件、状态的 time/speed/mirror/cycleOffset 参数、BlendTree（含嵌套）、Driver、场景里 PhysBone 与 Contact 的 `parameter`。
- **适用条件**：删物体、拆层之后回收参数。

## 菜单上有开关，拨了没反应：层权重为 0 或路径被优化器改名

- **症状**：菜单里有某个开关（例如胸型），拨动时参数在变，模型没有任何变化。
- **机制**：两类最常见：①该层默认权重为 0，且没有任何 LayerControl 给它抬权；②clip 里的路径在优化器删除或改名物体后解析不到，成了死参数。
- **判据**：烘焙后逐层读 `m_DefaultWeight` 并对照全部 LayerControl；在烘焙克隆上做「参数 → 层 → clip 曲线路径」解析，0 条可解析即死参数。
- **修法**：没人抬权的层设权重 1（有意按需接管的保留 0 并确认 LayerControl 指向正确）；死参数改用优化后仍存在的路径，或把相关物体排除在优化之外。
- **适用条件**：构建后才出现「有开关无反应」时。

## 几十格组合渲图都判「未见穿模」，默认态却有两副耳朵

- **症状**：66 格组合渲图全部判「未见穿模」，交付前才发现默认态头上是一副猫耳加一副素体熊耳。
- **机制**：评审判据只问穿模；两副耳朵几何上不打架，却是语义冲突。
- **判据**：按位置统计默认态开着的来源数，大于 1 即失败；给评审的问题要问「这个位置是否只有一件」。
- **修法**：把同一位置的全部来源收进一个轮盘（0=关、每档一件、默认一档），再重跑组合。
- **适用条件**：头顶、耳、尾等一个位置只该有一件的部位。

## 某个位置一件都不显示：两条方向相反的压制互相压没

- **症状**：某种组合下，头顶位置什么都没有；逐条检查压制规则，每条单独看都对。
- **机制**：冲突表里同时有「选了配饰 X → 关衣服件 Y」与「开了衣服件 Y → 关配饰 X」，同时成立时互相把对方压没。
- **判据**：冲突表按无序对计数，「甲压乙」与「乙压甲」同时出现的对数必须为 0；用真动画数据遍历「衣装档 × 冲突开关」，断言每个位置至少有一件显示（故意的全关档把该档本身算进去）。
- **修法**：定一条全局优先级链（例如头饰 > 服装头部小件 > 耳朵），只压低优先级一侧。
- **适用条件**：多件配饰与服装部件互相压制时。

## 构建前量的参数开销，与上传时的不一样：只跑了 NDMF

- **症状**：编辑器里手动跑 NDMF 构建后读到同步开销 398 bit（超过 256），上传却正常；另一次读到 254/256，以为「已经压过了」。
- **机制**：VRCFury 的参数压缩挂在 SDK 预处理回调上，不在 NDMF 的 `ProcessAvatar` 里；只跑 NDMF 读到的是压缩前的数。压缩只在超过上限时才启动，254/256 是真实的未压缩开销。
- **判据**：读任何 `CalcTotalCost()` 都先问它是压缩前还是压缩后。
- **修法**：克隆头像后按 `callbackOrder` 逐个运行所有 SDK 预处理回调再读开销；报告里并列「NDMF-only」与「完整链」两个数，并标明哪个是上传判据。
- **适用条件**：装有 VRCFury 的头像。
