# 面捕：Kipfel 配 Fermata 面捕补丁的冲突案例

## 面捕闭眼破面：顶层合并层恒写捏脸 clip，把值挪到分侧键也没用

- **症状**：Kipfel 头像用 Fermata 面捕补丁时，面捕闭眼（`EyeClosed`=100）眼睑出现锯齿破面；第二个模型的视觉核对判为阻断级。
- **机制**：
  1. 捏脸写在脸部网格 `Body` 的 20 个键的静态值上，并由 FX 第 0 层的脸部默认 clip 维持；Fermata 闭眼时只清零分侧的 `_left`/`_right` 眼键，双侧的捏脸眼键仍在，与闭眼叠加后破面。
  2. 场景里还有一个 MA Merge Animator（合并进 FX，`layerPriority` 999，Write Defaults 与 FX 对齐）在 FX 最顶层恒播同一个捏脸 clip，下层的任何清零都会被它盖掉。
- **判据**：
  - 改捏脸前先问：写这些键的层里，谁在 FX 最顶层？
  - 内存中试改（静态值与 clip 都改写到分侧键）后在 Play 逐档读分侧键：31 档里闭眼、手势下分侧值仍恒为原值，说明方案无效。
  - 分侧改写的几何等价检查：9 个眼键 |Δ双侧 −(Δ左 + Δ右)| = 0 mm，左右无重叠；静态烘焙差 0 mm，渲图差 0 px。
  - 28 个面捕状态下捏脸 21 个键值全不变，也说明面捕没在清捏脸值。
- **当时的修法**（人工作业，供理解机制）：停掉「只把值挪到分侧键」的方案，改顶层合并层本身：把它恒播的单一 clip 换成按眼睑参数淡出分侧捏脸值的混合树，原控制器与 clip 保留不动。
- **在 Harness 流程里**：本流程尚无面捕阶段；审查发现面捕与捏脸冲突时，写明写键的层与层序证据，停下交人。
- **适用条件**：Kipfel + Fermata 补丁（补丁版 FBX 与原版 MD5 不同，FX 已并入 FacialTracking/OSCmooth 层）；工程里 Triturbo 的 FaceTrackingAddon 已导入但未装配。捏脸由静态值加顶层合并层实现。
- **证据等级**：单一案例（候选）

## 面捕闭眼破面的修法：捏脸值随眼睑参数淡出的混合树

- **症状**：需要面捕开时闭眼不破面，同时睁眼外观与交付时完全一致。
- **机制**：把双侧捏脸眼键拆到分侧键，并让分侧值随该侧眼睑闭合按比例淡出，就不会与闭眼形态叠加。
- **判据**（Play 31 个状态验收）：眼睑 0.7–1 时逐键差 0，0.75 时渲图差 0 px；0.6→0 时分侧值 = 原值 × (1 − EyeClosed/100)，最大误差 0；单眼眨眼只淡出闭的那只眼；面捕关闭与手势时等于原值（55.2）；手势叠加值 110/85/90 → 55.2。
- **当时的修法**（人工作业，供理解机制）：
  1. 原控制器与 clip 不改，全部做副本：4 个 clip（睁眼、左闭、右闭、双闭）= 捏脸 clip 副本，9 个双侧眼键写 0，分侧写原值或 0，其余 12 条曲线逐条相同。
  2. 新控制器只有一个 WD On 状态，动作是 1D 嵌套混合树：`EyeTracking_GestureControl` 0 → [`EyeTrackingActive` 0 → 睁眼，1 → `EyeLidLeft` × `EyeLidRight` 四角]，1 → 睁眼；新增 4 个 Float 参数，默认值与 FX 同名参数一致。
  3. 顶层合并层与同物体 Animator 改指新控制器；脸部静态值 9 个双侧键 → 0，分侧 = 原值。
  4. 之后把三棵眼睑树的「睁眼」阈值从 0.7 收窄到 0.21，只在破面区间淡出：批处理 Play 实测 22601 个状态全部符合期望，稳态最大误差 4e-06。
  5. 「手势闭眼时也淡出」的追加改动被撤回：已渲染的 8 种满闭眼手势里，旧版（捏脸值 75.1）都没有可见破面，新版反而在手势过渡帧出现眼形跳回默认、平眼睑半睁的怪帧；用户看过新旧逐帧对比图后拍板撤回。
- **在 Harness 流程里**：本流程尚无面捕阶段；这一修法要新建控制器与混合树，写明方案与验收口径，交人实施。
- **残余**：右手、双手手势里厂商表情用 `eye_close` 闭眼时未全测；Eye Lid LR Sync=1 时 Fermata 用 2D 同步树，左右差大时淡出略不同步；半闭 0.4 时双眼皮线与睫毛轻微交叠（修前同样存在）。
- **适用条件**：Kipfel + Fermata 面捕补丁（补丁版 FBX，FX 已并入 FacialTracking/OSCmooth 层），捏脸由脸部静态值加 FX 顶层合并层实现。
- **证据等级**：单一案例（候选）

## 面捕补丁自动提取的脸部材质：缺二层与 matcap，造成脸颈色差

- **症状**：面捕版头像脸偏黄、脖子偏白，舌头配色也跟着不对。第二个模型的视觉核对确认色差。
- **机制**：面捕补丁版 FBX 导入时自动提取了 `Body_skin.001`、`Hair.001`、`Body_alpha.001` 并挂在脸部槽 0/1/3，这些材质没有厂商贴图方案（Twinkle）的二层、matcap、rim 设置。这是装配问题，不是面捕方案与贴图不兼容。
- **判据**：逐槽读脸部渲染器引用的材质，与身体所用的厂商 PC 材质逐属性比对。
- **当时的修法**（人工作业，供理解机制）：
  1. 槽 0/3 改用厂商 PC 材质 `Body_skin`、`Body_alpha` 的副本，副本与原件逐属性比对只改 `_StencilPass` 2→0；FBX 的 .meta 不动。
  2. 不能直接用原 `Body_skin.mat`：它的模板值 33 会让 `Hair_fakeshadow` 叠画在前发上，看起来像「前发透过」，用户明确不要。
  3. 槽 1 实为眉毛，先换成发色材质后对比度太低，用户看图后改回 `Hair.001`。
  4. Play 读材质确认副本带贴图方案设置、`_StencilPass` 为 0；修前修后同机位对照。
- **在 Harness 流程里**：改色阶段只按 plan.yaml 的 recolor.targets 动方案指定的部位；脸部材质槽问题本流程没有对应通道，遇到时写明证据，停下交人。
- **未解**：Play 下单独换材质时像素几乎不变，读到的材质名带 `(LLC Clone)` 后缀，疑为插件在 Play 时克隆了材质，未查清；整体色调要在私密上传后复看。
- **适用条件**：Kipfel + Fermata 补丁 FBX，lilToon 材质。
- **证据等级**：单一案例（候选）
