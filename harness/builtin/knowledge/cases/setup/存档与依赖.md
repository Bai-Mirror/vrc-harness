# 存档与依赖案例：存档能不能打开，比存档多大重要

## 案例：拉回的旧工程启动几秒就退出：依赖指向工作区外的本地目录

- **症状**：Unity 启动几秒后退出，返回码 1，日志里只有一句 `Project has invalid dependencies: … jp.lilxyzw.liltoon: The file [<某个本地目录>\liltoon\package.json] cannot be found`。拉回的一批 10 个旧工程里，有 4 个已经打不开。
- **机制**：`Packages/manifest.json` 用 `file:` 指向工作区外的本地目录，路径里还带着旧账户名；换机器、目录挪走、云盘没同步，工程立刻打不开。旧存档包带着 `Library/` 时，这个问题被掩盖了。
- **判据**：归档前跑 `grep -E '"(file:|https?://)' Packages/manifest.json`，有命中就必须先转成 VPM 版本号再打包。
- **修法**：包体落到 `Packages/<包 id>/`，优先用工程自己 `Library/PackageCache/` 里的那一份（当年真正构建用的字节），没有才从版本相同的兄弟工程拷；`Packages/manifest.json` 里那一行删掉（VPM 管的包不进 UPM manifest）；`Packages/vpm-manifest.json` 写 `dependencies` 与 `locked` 两处版本号；`packages-lock.json` 里对应条目清掉，让 Unity 重新解析；原文件留备份。用不上的死依赖直接摘掉，不硬凑版本（一例依赖 AAO 1.9.8、本地没有这个版本，而场景里一处 AAO 组件都没用）。
- **适用条件**：早期用 `file:` 声明依赖的工程；任何要归档或换机器打开的工程。

## 案例：两个工程从同一个 #master 拿到了两个不同版本的 lilToon

- **症状**：两个工程的 manifest 都写着 `"jp.lilxyzw.liltoon": "https://github.com/lilxyzw/lilToon.git?path=Assets/lilToon#master"`，都能打开、不报错；实际一个解析出的是 2.3.2，另一个是 1.10.3。
- **机制**：分支依赖能打开，只是因为 `Library/PackageCache/` 里还留着当年 clone 的副本；删掉 Library，就再也复现不出同一份代码。
- **判据**：同上的 manifest 扫描；查当年真正用的是哪个版本，读 `Library/PackageManager/ProjectCache`（文本）。
- **修法**：按 ProjectCache 记录的版本转成 VPM 版本号，包体取工程自己 PackageCache 里的那一份。
- **适用条件**：用 `git#<分支>` 声明依赖的工程。

## 案例：从 ProjectCache 读版本，把 AAO 1.9.8 读成了 3.2.1

- **症状**：为转换依赖读 `Library/PackageManager/ProjectCache`，某个工程的 AAO 版本被读成 3.2.1，实际是 1.9.8。
- **机制**：该文件里每个包条目的 `version:` 字段在 `name:` 之前；正则从 `name:` 往后找版本，取到的是相邻下一个条目的值。
- **判据**：解析后拿一两个已知版本的包核对；`source:` 字段是 `UnityEditor.PackageManager.PackageSource` 枚举，可顺带核对来源（3 为 Embedded，即 VPM 装在 `Packages/` 里的；4 为 Local，即 `file:` 指到工作区外；6 为 Git）。
- **修法**：按条目边界解析，版本取同一条目内、`name:` 之前的那个 `version:`。
- **适用条件**：解析 Unity 包管理缓存文件时。

## 案例：旧「副本」里 7 个材质比新包还新，看着像丢了活：其实是一次失败的移动端转换

- **症状**：清理旧存档时逐文件比对，发现某个旧「副本」里有 7 个材质比新包更新，看起来像是新包丢了一部分工作，不敢删。
- **机制**：比对内容后发现，这 7 个材质被批量换成了 `VRChat/Mobile/Toon Standard`（着色器 GUID `e765db0afa7ecfc44ade2e4e2491f65a`），渲染队列钉成 2000——那是一次失败的移动端转换，不是要保的内容。
- **判据**：用 `7z l -slt` 列出每个文件的 CRC32，按 `(路径, 大小, CRC)` 三元组比；差异只在可再生物（`Library/`、`Assets/*__Generated/`、`Packages/*.temp/Builds/`、插件升级后删掉的旧版源码）时可删；有独有的非再生内容时，先弄清是什么。
- **修法**：确认是失败转换的残留后，按可删处理；删除仍属不可逆操作，交人确认。
- **适用条件**：清理 7z 格式的旧工程存档时。
