# Harness 执行模型：各执行方阶段共用

本文件随 Harness 正式流程的每个执行方阶段注入。其余知识多数按「操作者自己开 Unity、改场景、自己提交」写成；与本节冲突时，以本节为准。

## Harness 正式流程里执行方能做什么

Run 使用 Runtime 冻结的保留、AI 或接受手动脸型；制作不等草稿。手动输入仍经补偿、FBX、Unity 检查和渲染。接受、换版、回退、改模式由续接事务采用：旧 Run 保持快照，同字节也失效旧证据；安全点按基线与当前批准方案建立后继，face 以下重做。缺基线按冻结素材重建，不重新规划或丢弃未知修改；旧合同仅经正式选版采用。保留原工程和交付，分别展示要求、进度与交付。Blender 仅采纳造型键值和获准范围，拒绝网格与受保护键改动；模型不得代写交接或批准。

- **只写 `allowedWrites`，写的是设计输入**：写边界由沙箱在系统层强制，越界写入会失败，或被判越界。各阶段交的东西：plan 写 `_harness/plan/plan.yaml`；setup 调用冻结工具 `setup-project`；outfit 可依据 setup 的实际对象观察写 `Assets/_Harness/Outfit/local-operations.json`，由 Runtime 消费精确材质槽属性/已授权贴图引用、预制体子件挂接、子对象局部变换；recolor 调用 `generate-recolor-candidates`，缺公共材质时用已接通的 `inspect-material-dependencies` 观察，并在本层 `dependencies.json` 提出同已确认输入目录的来源及 SHA；Runtime 复核当前目录授权、来源版本和 GUID 后只恢复派生层。已有眼部遮罩但关闭时，可按阶段 goal 用 iris_layers 提出带原材质 SHA/遮罩/开关证据的副本启用，由 Runtime 对照当前方案和真实素体槽校验；虹膜可按启用的眼部贴图图层识别，只改该层，不能删除 eye 要求或改整张脸代替；menu 写 `Assets/_Harness/Menu/design.json`；optimize 写 `Assets/_Harness/Optimize/design.json`；两轮回归修改上游设计输入；package 写 `_harness/delivery/diagnosis.json`。局部操作字段以当前阶段 goal 为准，不按对象名猜地址、不改原件。当前局部操作没有网格/捏脸烘焙能力。
- **不做的事**：不开 Unity（沙箱不给写 `Library/`、`Temp/`，编辑器起不来），不存场景，不烘焙，不清 `Temp/UnityLockfile`，不 `git commit`（`.git` 只读；HEAD 一动就判越界）。也不装编辑器桥，不跑 vrc-get 或 ALCOM。
- **Unity 由 Runtime 在你退出后跑**：你以退出码 0 结束后，Runtime 才在受限写入的环境里启动 Unity（执行方不能直接写工作区以外的位置），在空场景里运行本阶段的冻结工具（导入与编译、装配、改色、生成菜单、构建、回归、Play 探针），日志写在 Run 目录的 `unity-N.log`。锁也由 Runtime 管：启动前先判断进程，陈旧的锁由它自己清。编译错误、读数和失败原因随检查结果注入下一轮。
- **产物每次重建，直接改动都会丢**：outfit、recolor、menu 的工具每次都从上一层产物整层重建本层（重新实例化、从原件重抄材质、删掉旧控制器与 clip 再生成）；setup 每调一次 `setup-project`，都按基准重置 `ProjectSettings/`、三份包清单和基准 VPM 包目录，并重写导入记录。你在场景、预制体或生成物里的手改，下一次运行就没了；改的若是上游层的产物，还会让上游检查失效，上游阶段重跑后再次覆盖。
- **脸型候选按形态键设计**：face_design 依据实际源观察与用户目标给出2–5个原有形态键组合候选，不直接推顶点，不替用户选定；键范围不足应显式提出扩展并验证影响。具体选择由 Runtime 保存并向 face 工具提供可信摘要，表情补偿、烘焙、FBX回导和褶皱/破损检查由受管工具执行与独立量测。工程技术检查与实际正/侧效果确认分开，保留原脸不要求无必要确认；生产任务不能写批准、图片或完整资格来替代用户决定。未知眼部、遮挡或穿插覆盖不冒充通过，也不把当前工具不足写成永久素材禁令；应保留缺口、继续诊断或在已有授权内提出修订。
- **脸型质量发现继续审阅**：新配方完整记录自交、塌陷、褶皱和眼球露出变化，不用质量发现作为停止条件；与原版同状态比较并提供毫米/近景像素估算、同机位特写。明显可见可针对性修一次，其他交用户看图判断。Runtime 要求独立补偿与观测完整，不能把有发现说成质量通过；同类三次停止只计技术性失败。
- **脸型临时导入与停止**：受管 Unity 同路径比较由 Runtime 在开工前冻结源与候选 SHA、备份和导入元数据；事务期间来源观察保留原版身份，并显示预览暂时不可用、恢复后可再看。轮询、取消及收取已运行单元不重新核验施工前候选图片。停止进程树后仅恢复完全匹配授权的事务，异常保留为技术审阅，不能用停止接口批准外观或覆盖无关编辑。受管范围内可核实的新 Unity `.meta` 是技术副作用；既有元数据修改、删除或无关改动仍须审阅。
- **机制说明与当前工具合同分开**：知识里描述的场景操作、组件挂法、API 调用属于机制与案例；通过当前已接通的局部操作或其他冻结工具表达施工，Runtime 执行后以真实重载读数检验。当前工具没有的动作是明确的待接通能力，不能伪造执行或将实现限制当永久产品边界。
- **能用的证据**：工程里的 YAML 文本（预制体、clip、控制器、`.meta`），清点与导入报告，上一轮的检查结论，以及 Run 目录里的日志、照片、`coverage.json`、`perf.json`。渲图、几何量距和 Play 由 Runtime 在后续步骤里测；本阶段报告写「交 Runtime 测」，既不写成缺口，也不写成已验证。
- **修不了就停**：某条检查只取决于厂商资产或方案（例如尚无受管修法的厂商动画曲线），你在本阶段改不动时，写明证据后停下交人，不要反复重试：每次重试结果都一样，只会耗光重试预算。交人时写进本阶段产出契约的字段（方案的 `notes`、诊断的 `blockers`），写清要人改什么（方案、Manifest 还是基准工程）。
- **阶段工具版本与素材身份分开**：正式采用后，Runtime 保留各编译器最近的来源绑定；后续阶段未部署的前序编译器不因此变成素材漂移。每个 Run 的冻结版本与 prepare 写权仍按当次选择，不能把历史采用记录当额外写权；未核对的字节仍拒绝。
- **工具可在未开工阶段正式采用**：Harness 的阶段工具采用入口支持尚未创建 Task 的已定义阶段，也支持已停止且未接受的阶段；仍须无活动执行、锁或未核清改动，并核对来源、合同和 token。采用仅影响后继 Run，不改变依赖、检查、写权或 Gate，执行方不能把采用记录当作成果批准。
- **生成配方与导入回执**：配色工具将数值和换行规范成可重放字节，方案文件的 1.0 与 Runtime 的 1 不造成假漂移；真实数值或字节编辑仍由独立回放拒绝。装配工具在本轮导入局部操作回执及其 `.meta`，后继阶段不承担前序漏导入。空槽观察保留普通未激活/禁用网格；关闭且没有 Animator、描述符或 MA 动画启用写者的粒子渲染器可用于非可视逻辑，不计作可见空槽。带启用写者或当前启用的粒子仍计入，不能把这项静态观察冒充 Play 全状态验证。
- **验收以 Runtime 的独立观测为准**：观测只由 Runtime 的步骤和观测器产生，你预写的观测和覆盖记录会被清掉或覆盖；「调用过工具」「日志里写了完成」都不算通过。
- **暂停和验证器故障不是工程返工指令**：安全点暂停后不会新增派发，已派发的授权步骤由 Runtime 收尾、回收并独立核验；未能确认的执行保留锁和恢复状态，不盲重做。独立验证器的 `error` 不能由你改工程、改验证器或自写通过来修复；Harness 保留原错误，在制作工具更新后经正式保存与复验入口接续。真实违规、缺少产物或普通未测指标仍可按既有授权与预算修复。

## 局部方案复核与返工

装配发现原方案未覆盖写者时，AI 可在既有目标及素材授权内，通过 outfit goal 的 shrinkkey_review 操作提交局部修订。完整实际写者和顺序、来源观察、源资产、无冲突值及三态预期由 Runtime 校验；只登记技术方案补充，不改变原方案批准、接受脸型或旧证据，也不代表三态实测。多宿主须解释先后及最终胜者。缺证据应补探查/返工；超出授权或需外观取舍时给出中文具体选项，交已有确认入口，不让用户修改 YAML。
