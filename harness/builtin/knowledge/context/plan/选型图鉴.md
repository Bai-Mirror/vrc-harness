# 方案阶段：给客户挑素材的选型图鉴

方案声明由客户从图鉴里挑件（`client_gallery: true`）时适用。图鉴＝图＋中文名＋风格标签＋可勾选，客户挑完把清单发回。每节可单独注入。

## 选型图鉴：HTML 与 PDF 两份各自能承诺什么

- **职责**：做出客户打得开、勾得动、能把清单发回来的图鉴，一次发两份：单文件 HTML（主推）和可勾选 PDF（兼容件）。
- **权威输入**：已完成兼容判定的候选池；客户使用的聊天工具及其限制。
- **决策边界**：只做图鉴与回收，不替客户挑。
- **为什么是两份**：客户看不懂文件夹名，也不会翻 Booth；给图、中文名和风格标签才挑得动，勾选回传比截图省一轮来回。只发一份的代价是客户打不开或勾不了，多一轮来回（按天计）；两份都做的代价是 PDF 管线多花的时间（按小时计）。
- **两份的能力不同**：

| | 单文件 HTML | 可勾选 PDF |
|---|---|---|
| 缩略图 | WebP 480px、质量 74，base64 内嵌 | 换 320px 重建一版，压体积 |
| 交互 | 品类筛选、搜索、点图放大、勾选计数、「复制清单」 | `/Btn` 勾选框＋一个 `/Tx` 多行备注框 |
| 做不到 | — | 一键复制清单：要 PDF 内嵌脚本，只有 Adobe Reader 执行，Chrome、Edge、WPS、手机端都不跑 |
| 聊天工具内置预览 | 能开 | 只能看、不能勾 |

- **两份的文案分开写**：PDF 版不许承诺网页版才有的功能。
- **零外链是硬约束**：不依赖任何 CDN，不用 Google Fonts，字体只走系统字体栈。违反的症状是客户那边页面空白或字体卡几十秒，而你自己的机器上一切正常。
- **体积**：一次实测 187 项约 5.5 MB（每项约 30 KB），是「转发得动、又看得清风格」的点。图再大，单文件超出聊天工具的转发上限；再小，蕾丝、花纹这类细节看不清，客户挑不动。条目远多于此时，先把 WebP 降到 320px，再考虑按品类拆文件（拆了客户容易漏看一份）；拆之前先量目标聊天工具的单文件上限。
- **怎么验证**：HTML 里 `src="http`、`href="http`、`@import`、`fonts.googleapis` 命中数为 0（PDF 专用的那版 HTML 例外，它故意带勾选位链接）；勾 N 项后「复制清单」输出 N 行；PDF 抽出的文本里「复制清单」命中数为 0。
- **禁止**：PDF 版文案承诺复制清单；引用任何外链资源。
- **产出**：单文件 HTML 与可勾选 PDF 两份，以及各自的说明文案。
- **升级给人**：客户用的聊天工具打不开两种格式之一时，问清对方能用什么再改。

## 选型图鉴：候选池、来源标签与缩略图

- **职责**：确定图鉴里放哪些件，每件带图、带来源标签。
- **权威输入**：清点结果中的兼容结论；客户素材包与素材库命中（由清点提供）；`.booth-meta.json` 的结构化字段。
- **决策边界**：不自行扩大候选池；「待骨骼比对」的件先比完。
- **前置**：每件都已有兼容结论（支持／不支持／待骨骼比对／项目依赖）。「待骨骼比对」的件先比完再进图鉴，不要先放进去再说；判为「项目依赖」的件（包内只有 VPM 安装入口）没有可挑的外观，不进图鉴。
- **候选池**：客户素材包里支持本素体的件，加上清点结果提供的素材库命中件。方案阶段不自行扩大候选池。
- **素材库命中按结构化字段筛，不要全文搜索**：`.booth-meta.json` 的 `avatars[]`（每项有 `name`、`source`、`confidence`、`status`）为主判据；`files[].avatars[]` 是最强信号（包里真的带该素体的分包）；`variations[]`、`booth_tags[]` 作补充。
- **路径处理**：商品名带空格、全角括号和 emoji，管道处理要用 NUL 分隔（`xargs -0` 等）。漏一个，目录名就会被切成多行；实测出现过 164 对真值 56 的错数。
- **来源标签**：每张卡标明「客户自备」或「制作方追加」，交付时两者要分开打包。
- **缩略图**：每项取商品目录 `images/` 下的商品图，WebP 480px、质量 74，base64 内嵌。
- **怎么验证**：条目数＝客户包兼容件数＋素材库命中数；每条来源标签属于两种之一；判为「不支持」的件在图鉴数据里命中数为 0；每项至少 1 张图；总体积（用 `os.path.getsize` 量）与「30 KB × 条目数」同数量级。
- **禁止**：把「不支持」或「待骨骼比对」的件放进图鉴；手工拼接目录名。
- **产出**：候选条目数据（id、中文名、风格标签、来源标签、缩略图）。
- **升级给人**：候选池为空或远超客户能挑的量时，先与人确认范围。

## 选型图鉴：PDF 勾选框的做法与回收核对

- **职责**：做出每个条目都有真实勾选框的 PDF，并把客户回传的清单对回图鉴。
- **权威输入**：320px 版 HTML 与条目 id 清单；客户回传的清单。
- **决策边界**：不手补坐标；回传清单原样保存，不改客户的选择。
- **做法**：
  1. 用 320px 缩略图重建一版 HTML，每个勾选位渲染成 `<a href="https://x.pick/<id>">` 链接。
  2. 用无头 Chrome 的 `--print-to-pdf` 出片，它会把链接原样输出成链接注释。
  3. 用 pypdf 遍历各页 `/Annots`，把这些链接**就地替换**成 `/FT /Btn` 勾选框：给足 `/AP` 的 `Yes`／`Off` 外观流和 `/MK`；AcroForm 打开 `NeedAppearances`。
  4. 另加一个 `/FT /Tx` 多行备注框。
- **为什么绕这一圈**：让 Chrome 替你算坐标，链接注释的矩形就是元素在页上的真实位置。自己算勾选框位置要跟排版硬对齐，版式一改全废。
- **怎么验证**：`/FT /Btn` 数＝条目数，`/FT /Tx` 数＝1，残留 `x.pick` 链接数＝0（pypdf 遍历计数）；用 pymupdf 的 `widgets()` 逐个置为 True 再 `get_pixmap`，与置为 False 的渲染图相减有像素差；PDF 文本里没有「复制清单」。
- **禁止**：勾选框数对不上时手补坐标。先列出哪些 id 没出现在 `/Annots` 里，回去改版式。
- **发出与回收**：两份一起发。HTML 的说明写「勾完点复制清单发回」，PDF 的说明写「勾完存档发回」。回传清单原样保存；清单里每一项都要能在图鉴数据里找到 id（找不到的数为 0）；选中项回填素材应用表的「用途」栏。
- **产出**：带勾选框与备注框的 PDF；回填后的素材应用表「用途」栏。
- **升级给人**：回传清单里有图鉴外的项、或选中项之间互相冲突（例如两套只能装一套）时，交人与客户确认。
