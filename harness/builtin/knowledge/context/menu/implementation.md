# 菜单阶段：实现方式、控件形态与默认值

## 用 MA 反应式组件切换衣装：适用条件与接线检查

**职责**：素体干净、服装自带 MA、且厂商参数层与要控制的属性互不重叠时，用 Modular Avatar 的声明式组件实现衣装与部件切换。

**组件分工**：
- MA Menu Item：菜单控件本身，可以自动生成参数；与同一物体上的反应式组件配合，构成一个开关或一个轮盘档。
- MA Object Toggle：所在物体处于激活状态时，把目标物体设为指定的显隐。
- MA Shape Changer：所在物体处于激活状态时设置或删除目标网格的形态键，物体失活即不生效，天然跟着部件走。每个条目写目标网格（`AvatarObjectReference.referencePath`）、`ShapeName`、`ChangeType = Set`、`Value = 100`。防穿模的身体收缩键应挂在需要它的衣服部件上，不要留在厂商换装动画里：那类动画只要厂商参数为开就一直在播，穿别的整套时身体也被收掉。
- MA Menu Installer：把插件或厂商子菜单挂进 `installTargetMenu` 指定的子菜单。
- MA Parameters（`ModularAvatarParameters`）：声明参数的同步类型、默认值、是否存档、是否本地。

**决策边界**：MA 生成层的先后由 MA 决定，与厂商层抢同一属性时不好压；存在重叠、需要精确层序或组合条件时，改用自己生成的动画层。

**禁止**：
- 用 Object Toggle 显式列「反向条目」来实现多套衣服互斥却不维护：每加一套衣服都要回填全部反向条目，漏一次就两套同开。互斥优先用单参数轮盘。
- 只解析 `VRCExpressionsMenu` 资产就判断「缺项」或「参数悬空」：MA Menu Item 的控件不在菜单资产里，要连同它一起解析；构建后自动参数的名字可能带 `__MA/AutoParam/…` 前缀，以构建后的菜单与参数表为准。

**产出**：每个菜单控件对应的 MA 组件、参数名、目标物体与形态键清单。

**验证**：构建后读合并后的菜单与参数表；每个 Shape Changer 的目标网格上确有该键。脚本读 Shape Changer 的序列化数据时字段名是 `m_shapes`（脚本 API 属性名是 `Shapes`），读错会对所有服装报「收缩键 0 条」。

**升级**：必须覆盖的厂商属性在 MA 路线下压不住时，报告冲突属性并改走生成层；不修改厂商或插件预制体。

## 生成动画层的结构约定：状态、转移、参数与合并设置

**职责**：自己生成 FX 层时，采用一套在多个工程沿用过、便于回读与审计的结构。

**层与状态**：
- 每个部件开关一层，两个状态 On/Off；AnyState 转移 `If 参数 → On`，`IfNot 参数 → Off`。
- 每个轮盘一层，N 个状态；到第 i 档的 AnyState 转移条件为 `参数 > i/N`（i>0 时）且 `参数 < (i+1)/N`（i<N−1 时）。恰好落在边界上的值两边都不成立，会停在原状态，所以程序取值与默认值一律用区间中点 `(i+0.5)/N`。
- 所有转移：时长 0、无 exit time、固定时长、`canTransitionToSelf=false`。
- 生成的状态关闭 WD，并按「每个状态写满本层拥有的属性」生成曲线。
- 每层 `defaultWeight` 显式设为 1（修改层数组后要把整个数组回写，改副本无效）；默认状态设为默认参数对应的那一档。
- 单关键帧 clip 写成从 `t=0` 到 `t=1/60` 的常量曲线。

**参数**：内部参数名带工程唯一前缀、稳定不变，与显示名分离；每个轮盘一个 Float，每个部件开关一个 Bool；能直接用厂商参数的开关不另建参数。

**合并**：生成的控制器用 MA Merge Animator 合并到 FX（`layerType = FX`）；路径模式 Absolute（`pathMode = MergeAnimatorPathMode.Absolute`，路径相对头像根）；不跟随头像的 WD 设置（`matchAvatarWriteDefaults = false`）；合并后删除挂载的 Animator 组件（`deleteAttachedAnimator = true`）；`layerPriority` 取足以排在需要压住的厂商层之后的值，并以构建后的层序号核实。

**菜单树**：根菜单下按用户任务分子菜单（例如换装：衣装轮盘、发型轮盘、部件子菜单、配件子菜单），厂商子菜单以引用挂入；插件的 Menu Installer 按功能路由（灯光类归外观，姿势与手势类归动作）。

**禁止**：调用 `AnimatorController.AddLayer` 后不设权重（新层默认权重 0，曲线写不出去）；同一个参数既有生成层又有手写补丁层各写一份。

**验证**：回读控制器，层数、每层权重、状态数、转移条件和参数默认值与设计一致；连续生成两次，结果逐项相同。

**升级**：厂商结构要求偏离这套约定（例如必须用 Int 分档）时，在设计记录写明理由。

## 同一位置多件饰品与戒指：控件形态

**职责**：为饰品类功能选控件形态，并把同一位置的全部来源收进同一个控件。

**规则**：
- 同一位置只有一件饰品用 Toggle。
- 同一位置有两件及以上（两种光环、两条项链、几副耳朵）改成一个轮盘：0=关、1=饰品一、2=饰品二……互斥由档位保证，多个 Toggle 互相压制带来的作用域切碎、压制方向写反、死锁风险一起消失。
- 聚合控件的作用域按语义封闭：一个位置的所有来源（素体自带、每套服装自带、每档发型自带、外购配饰）都进同一个控件，不按「长在谁身上」拆到不同菜单项。来源清单由场景枚举，并逐件单独渲染确认是什么；名字像耳朵的可能是发夹，名为 `Ring` 的可能是头顶光环。
- 戒指默认做两个控件：一个开关；一个「戴哪根手指」的轮盘，0–7 依次为左小指、左无名指、左中指、左食指、右食指、右中指、右无名指、右小指（不含拇指），默认 6（右无名指）。位置轮盘不管开关。实现为八根手指各一份副本、各自贴合，轮盘切换激活哪一份；每根手指的位置与缩放单独微调，不能一套变换套八根。这是默认惯例，方案另有要求时以方案为准。

**禁止**：为同一位置的多件饰品各做一个 Toggle，再用压制层互相关。

**产出**：每个位置一行：来源清单、控件类型、档位表。

**验证**：按默认参数求值后，每个位置默认显示的来源不超过一件；轮盘逐档渲染，每档只出现该档的饰品。

**升级**：同一位置的默认档、是否允许叠戴属审美决定，方案未写时询问用户。

## 默认值与同步：一份设计数据生成所有落点

**职责**：为每个菜单参数确定默认值、是否存档、是否网络同步，并让控制器、参数声明、编辑期场景三处一致。

**本流程里**：参数与默认值都由 Runtime 生成：衣装轮盘的默认档来自方案 `default_outfit`，control 的 Bool 默认值来自 `design.json` 的 `default`，`saved` 来自方案。默认穿哪套、默认开哪些部件，方案或需求没写时按默认动作定，并写进说明，不停下询问（menu 阶段没有等人的闸门）。Runtime 目前把衣装轮盘的默认值写在档边界 `d/N`（控件取值是中点 `(d+0.5)/N`）：这是已知的实现口径，`design.json` 改不了，发现时记进说明，不当作本阶段缺陷反复重试。

**做法**（自己生成参数时）：
- 轮盘 Float 的默认值取默认档的区间中点 `(d+0.5)/N`。判断「是否处于关档」的阈值写 `1/档数`，不写 0.01 这类常数：三档轮盘的关档取值是 0.167，写 0.01 会把关着的配饰当成开着，一直压住衣服部件。
- Bool 默认值等于用户第一次加载时该部件的可见状态；默认关的部件（备选的长裤、原型本就关着的领子等）显式列入默认关清单。
- 同一个默认值同时写进控制器参数的默认值（`defaultFloat`、`defaultBool`）和 MA Parameters 条目（`nameOrPrefix`、`syncType`、`defaultValue`、`saved`、`localOnly`）或 Expressions Parameters 的默认值，两处由同一份设计数据生成，不手写两份。
- 衣装、发型、部件选择一般设 `saved=true` 并参与同步；只给自己看的参数设为本地（MA Parameters 的 `localOnly`，或参数表里 `networkSynced=false`），本地参数不计入同步预算。
- 菜单引用的每个参数都要在场景的 `ModularAvatarParameters` 里声明，声明的每个同步参数都要有菜单入口或驱动者：两个方向的差集都为空。
- 厂商用「空 clip＋WD=ON」表示的默认，还原的是构建那一刻场景里的物体状态。不要靠维持场景状态，在排在厂商层之后的自己的层里显式写。

**禁止**：维护一份与动画数据无关的手写「默认开哪些」清单；让两个脚本各自写同一个默认值。

**产出**：参数表，列出名称、类型、默认值、saved、同步或本地、菜单入口、消费者。

**验证**：构建后参数资产里的默认值与控制器默认值逐项相等；按层序把默认参数选中的 clip 应用到编辑期场景后，看到的就是交付首帧。

**升级**：默认穿哪套、默认开哪些部件由用户决定；本流程里方案未写时按默认动作定并记进说明。

plan/0.3 优先消费 avatar_config，独立配饰组不会因同位置而自动变成轮盘。Float 区间为 [i/N,(i+1)/N)，最后一档含 1；不能用两个严格不等式留下等值死区。


plan/0.3 的默认值只取已提交 avatar_config：Float 用处于本档区间内、量化到 127 档后仍在本档的代表值；Int 将默认成员映射到 0，Bool 消费成员或共享开关的显式默认值。不要套用旧方案的 default_outfit 或 d/N 默认口径。

多组回归读取不可变来源的默认形态、MA BlendshapeSync 精确引用与映射、ShapeChanger Set 恢复及 Delete 的实际 primitive 集合。静态组合和原生增量事件都检查形态；同名身体网格不自动建立同步关系。source_shape_state_complete 必须为 true；来源、键、构建映射或未知动画消费者不完整时阻断，不能把 unknown 写成零。旧 key_follow 同名诊断只属于旧方案门槛。

来源几何、删除掩码所需位移与默认权重在构建前冻结；构建产物的共享 Mesh 或更新后的记录不能成为新期望。成员所有权条件保留普通值，临时 Unity 上下文销毁不得改变选择条件。没有构建前来源快照时无法认证。

当前来源审计对共享参数的自动菜单值分配、作者动画与 Set/Sync 目标重叠、未建模的宿主祖先激活动画或 reactive toggle 返回 unknown 并阻断；不得套用「自动值一律为 1」或把常量 Set 的初始映射当成所有动画覆盖的运行值。相关的 2D 混合树同样不能由只支持 Direct/1D 的模拟器认证；依赖扫描包含嵌套状态机的入口与迁移条件。

单写者 ParameterDriver 也可能影响业务：依赖闭包追目的参数、Copy 来源和中间状态机参数；相关 Driver 尚未执行，返回 unknown 并阻断覆盖认证。来源厂商菜单和已批准 menu.tree 从构建前声明独立对账，删除子菜单、改名或移组均失败；参数存在不能代替入口和布局证据。单成员 Int 编译常量状态，不能因只有一档而启用 Float Motion Time。

菜单对账的自动分配没有通配豁免：按冻结的来源参数类型、默认值和全部 MA MenuItem（含不安装到菜单的保留值）推导分配值，参数和值均精确比较。当前只证明恒等参数映射；私有生成名称、非恒等/前缀重映射、声明冲突、值耗尽或同源重复实例分配歧义返回 unknown 并阻断。menu-tree-readback 保存来源、期望分配值和映射；不得从构建后控件反推期望。此菜单分配证明不扩展形态审计对共享自动条件的执行能力。
