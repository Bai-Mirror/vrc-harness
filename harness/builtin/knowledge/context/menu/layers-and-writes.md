# 菜单阶段：层序、写法与 Write Defaults

## Write Defaults 不可赌：一个属性只让一层写，并在该层每个状态写满

**职责**：生成动画层时，让结果不依赖构建后 Write Defaults（WD）的实际取值。

**机制**：WD=OFF 时，一个状态没写的属性保持前面层的结果，「空状态＝透传」成立；WD=ON 时，一层里被本层任一状态写过、而当前状态没写的属性，可能被写回默认值并盖掉前面的层。构建后的 WD 不一定是你设的值：头像上有 VRCFury 的 `FixWriteDefaults` 且处于 Auto 模式时，它按整份 FX 里 WD on/off 状态的多数票统一改写，厂商 FX 与常见插件大多是 WD on，票数上几乎必然判 on，连手写的 WD=OFF 层一起改。AAO 等优化器还会合并、改写层，实际语义只能在构建产物上实测。

**本流程里**：生成层由 Runtime 做：WD 关，每个状态写满本层拥有的属性，每条属性只归一个 control。你不设计层；这里的机制用来判断厂商层与 VRCFury 改写会不会影响结果，Play 实测由 Runtime 在 regression_pre 做。

**做法**：
- 一个属性只让一层写；这一层的每个状态都显式写满它拥有的全部属性（显示写 1、隐藏写 0），多个条件用同一层的多个状态加转移条件表达。这样 WD on、off 结果相同。
- 等价成员共享物理根时，互斥选择可能在所有档位都保持该根开启，只切换成员材质。完整曲线可以恒为 1；不能为了凑 ON/OFF 人造关闭态。Runtime 只在每个业务 clip 都有与可读代理一致的二值曲线、业务所有者唯一且无额外写者时，移除已证明冗余的 MA 延迟输出。
- 依赖「空状态透传」的写法（独立压制层的空默认态、只在一侧写的非对称写法）只在确认构建后该层 WD=OFF 时使用，并在 Play 里实测「开、关、切走再切回」三步。
- 检查头像根上有没有 `FixWriteDefaults`：场景 YAML 里搜 `class: FixWriteDefaults`，`mode: 0` 表示 Auto。

**禁止**：凭推理断言「WD on 一定会坏」或「一定没事」。实测中出现过 VRCFury 判 on、AAO 优化后若干依赖透传的档位仍然正常的情况，也出现过厂商 WD=ON 空状态把属性还原成场景当前值的情况，两个方向都要以构建产物为准。

**产出**：设计记录写明每个生成层的 WD 设定，以及构建后 WD 的实际来源（是否被 VRCFury 改写）。

**验证**：用真动画数据做静态等价模拟时，按 WD on、WD off 两种语义各跑一遍，两者结果一致才算通过；不一致的每一格都要在 Play 里复核。

**升级**：某个功能只能靠透传实现、又无法在构建产物上实测时，把风险写进交付说明，交用户确认。

## 生成层的层序：部位开关排在整套切换之前

**职责**：需要自己生成 FX 动画层（要与厂商参数层交互、要精确控制先后）时，决定层的先后。

**机制**：同一属性被多层曲线写时，后面的层覆盖前面的层；构建后 WD=OFF 时，一个状态不写某属性，就把前面层的结果原样透传。

**本流程的层序正好相反**：Runtime 把衣装轮盘层放在这份控制器的第 0 层，部件层依次追加在后面。被 BoneProxy 搬走的件（`outfit.json` 的 `bone_proxy_visuals`）由轮盘独占，不要写进部件控件：部件层排在后面，默认开时会盖掉轮盘的隐藏，出现「换了衣服帽子还在」。

**推荐层序**（自己生成层时）：部位开关 → 整套切换 → 发型 → 配饰冲突压制 → 派生状态（按遮挡门控、派生形态）。理由：
- 选素体默认装的那一档，整套层不写素体服装网格，部位开关的值原样透传；
- 选外挂整套时，整套层把素体服装网格写成关，覆盖部位开关；
- 外挂服装自己的部件由服装根门控，部位开关对它的子件自由生效。

**与厂商层的先后**：要压住某个厂商层写的属性，生成层必须合并在它之后。真实先后只看构建后控制器里的层序号（序号大者在后、后写者胜），不按 `layerPriority` 数值或物体层级推测。

**决策边界**：上述透传依赖 WD=OFF。构建后 WD 可能被改写时，把相关属性收归单层所有者，每个状态写满，多条件用同层多状态与转移表达。

**禁止**：把一个属性从甲层挪到乙层却不删甲层里的写入。两个写者的结果只取决于层序，症状是某个开关「怎么点都没反应」，而参数面板上参数确实在变。

**产出**：设计记录列出生成层的顺序，以及每层拥有的属性清单。

**验证**：构建后打印 FX 各层名称与每层 clip 写到的路径集合，核对顺序与所有权；逐套渲染确认没有两层布料互相穿插。本流程里构建与渲图由 Runtime 做，你核对 `design.json` 里没有把 `bone_proxy_visuals` 收进部件控件。

**升级**：需要压住的厂商层在构建后仍排在生成层之后、又无法调整时，报告具体层名与序号，交用户取舍。

## 「切换时关一次」与「开着期间一直压」是两种写法

**职责**：处理「戴头饰要收帽子、戴腕饰要收长袖口、戴戒指要收手套」这类配饰与衣服部件的冲突，以及「切到某档时顺手关掉另一件」的需求。

**先分语义**：
- 切换时关一次：关一次，用户之后还能再打开。在触发状态上用 Parameter Driver 改被关部件的参数。若写成在切换 clip 里写被关部件的属性，它会被永久压住，之后再也打不开。
- 开着期间一直压：配饰开着就一直压，配饰一关自动恢复。让被压属性的所有者层把配饰参数纳入条件（被压件显示 ⇔ 自己的开关开且配饰关）；或在确认构建后 WD=OFF 时单开一层压制，默认态不写任何曲线，压制态只把被压件写成关。若写成 Driver，用户手动开回来就又穿模。

**冲突表**：按同部位列嫌疑对（头：光环、头饰 × 帽子、发型；手腕：腕饰 × 长袖口；手指：戒指 × 手套；背：翅膀、挂件 × 外套），逐组合渲图确认真的冲突才写进表。厂商开关常常一次写好几个物体，被压件的清单要从厂商 clip 读全；只按名字列，挂在主件上的小零件（如两颗铃铛）会留在原处浮着。

**禁止**：同一对冲突写成两个方向（甲压乙、乙又压甲），同时成立时会把该位置压空；用 Driver 实现持续压制；把被压件的属性写死在配饰自己的切换 clip 里。

**产出**：冲突表每条注明压制方向，以及它在全局优先级链上的位置；说不出位置的条目是多余的。

**验证**：关掉配饰后被压件自己回来；用真动画数据遍历「衣装档 × 冲突开关」全组合，每格断言该身体位置至少有一件在显示，零死锁格。故意设计的全关档（例如兜帽档要求不戴耳机也不露耳朵）要把兜帽本身算进该位置，否则误报。本单没有声明任何部位时不适用：`menu.mode: preserve` 的原菜单保留路线里 `menu.json` 的 `parameters`／`conflicts` 都是空的，没有格可遍历，不记死锁格；但声明了部位却一个都定位不到仍然算失败。

**升级**：压制方向或优先级链需要审美判断时交用户决定；组合遍历出现死锁时回到冲突表查压制方向，不改生成器去掩盖。
