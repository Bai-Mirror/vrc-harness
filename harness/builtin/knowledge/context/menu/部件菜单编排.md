# 菜单编排：部件开关的粒度、归属、默认值与厂商参数

写给执行 menu 阶段的 AI，依据装配阶段的部件理解（是什么、可见条件、视觉权重）编排部件开关。每节独立成立。

## 菜单决策依据的优先级：用户明示、用户纠正、惯例、厂商偏好

- **职责**：给部件开关的粒度、归属、默认值、文案做决定时，明确各类依据谁压谁。
- **优先级**：用户明示 ＞ 用户纠正 ＞ 既有惯例 ＞ 厂商的菜单偏好。
- **厂商排最后只管「偏好」**：哪几件是一组、参数 `true` 是显示还是隐藏，这类**事实**以厂商目录下的 clip 与菜单资产为准；本工程或上游生成的曲线、场景里的菜单项不算厂商事实。
- **旧工程的实做**：用户本人旧工程里的做法只当正反皆有的样本，不等于用户要求；转述而查不到原话的「用户要求」按惯例对待。
- **每条建议带依据**：菜单与冲突建议写明依据来源与级别；视觉权重、默认值、彩蛋只写「建议＋理由」，标「待用户定」。
- **分区与命名**：菜单分区与命名出 2 个候选给用户拍板。
- 技术设计引用已接受配置与有效决定；审美歧义通过现有方案修订/决策入口解决，不写 pending，也不由技术产物自行改变菜单语义。
- **升级给人**：两个同级依据互相矛盾（例如两个工程里用户的口径相反）时，并列写出交用户选。

## 三轴到默认菜单处理：开关粒度只由视觉权重决定

- **粒度由权重定**：

| 视觉权重 | 开关粒度 |
|---|---|
| 卖点 | 单独开关：在所属分类的分区下单列一项，占独立参数 |
| 点缀 | 跟它挂着的本体走（装饰同开），或并进同位置的配件组 |
| 基础层 | 并进身体部位组开关（内衣、袜……），跨套共用 |
| 未定 | 经现有方案修订/决策入口取得决定；不擅自实现一个候选 |

- **可见条件只管三件事**：默认值、贴图档位、冲突检查。

| 可见条件 | 管什么 |
|---|---|
| 常露 | 默认值；贴图按「主图不降到 2048 以下」（性能检查的红线） |
| 外层脱了才露 | 写清被哪件盖住；过遮挡门与让位检查 |
| 只在姿势或视角露 | 冲突检查要过对应姿势 |

- **反例**：某大胆套装里的乳贴，在默认造型中只从束身衣上缘露一条边和前扣，脱了束身衣才全露——属于「外层脱了才露 × 卖点」，仍然单独开关。若按可见条件分路，它会被并进部位组，正好与用户口径相反。
- **分类与粒度分开**：同是「内衣」，卖点级的乳贴单独开关、不与内裤同开关，而素体自带的基础内裤并进内衣组。
- **证据**：由一个用户明示的实例推广而来，推广本身待验证；用户未定时两案并列。

## 部位分类表（衣物类）：判据与默认菜单处理

判类以穿法定，不以名字定；判据里的名字只是线索。分类不直接决定开关粒度。

| 类 | 判据 | 默认菜单处理 | 例外 |
|---|---|---|---|
| 整套 | 一套衣服的根 | 整套轮盘占一档（RadialPuppet＋Float） | 厂商形态变体（兜帽戴/放、款 A/B）各占一档，不进部件开关 |
| 外套 | 同一身体段的最外层，去掉后露出别的衣物（夹克、开衫、马甲、最外层背心裙） | 部位开关「外套」，跨套共用 | 厂商参数同时管内层收缩时，驱动厂商参数，不只写网格 |
| 上衣 | 躯干上的中层或贴身层，外面还能再穿外套（衬衫、贴身上装、按穿法归这里的束身衣） | 「上衣」 | 领带跟衬衣；外套开而衬衣没有收短键时隐藏衬衣 |
| 下装 | 腰以下的外穿衣物（裙、裤、短裤） | 「裙·裤」 | 厂商在两条裙间二选一：开时不写，关时两件都写 false |
| 内衣 | 最贴身、覆盖胸或下身的层（文胸、内裤、乳贴） | 「内衣」 | 整套自带内衣时由整套层点名关掉素体那份，不加开关；卖点级贴身件单独开关，分类仍记内衣 |
| 袜 | 套在腿脚上的织物（短袜、长袜、连裤袜） | 「袜子」 | 能叠在任意套外的全身丝袜作为素体级配饰，默认关；到脚的丝袜要带脚型键 |
| 鞋 | 包脚、决定脚角度的件（含鞋套） | 「鞋子」 | 任意整套都能换的加装鞋：服装顶层独立开关，开时隐藏当前鞋 |
| 手部 | 手、前臂上的件（手套、袖套、绷带） | 「袖·手」 | 厂商示意二选一的长短两副：另加切换开关，默认长 |
| 头部 | 戴在头上的件（帽、发箍、服装头部小件、服装自带兽耳） | 「头部件」 | 同位置来源 ≥ 2 时用头部轮盘 |

- **本流程里的例外栏**：整套的形态变体只能在方案里各列一套；厂商参数管内层收缩时登记厂商 ON/OFF clip 为 `vendor_clips`，不能驱动参数；「隐藏衬衣」「开时隐藏当前鞋」只在被让位的件没有自己的开关时能做（写进 `disable_when_on`）；整套层点名关素体那份做不到（素体件只能靠方案 `hide_body_parts` 永久剔除）；头部轮盘做不到，只有衣装一个轮盘。做不到的写明并交人。
- **外套与上衣怎么分层**（候选判据）：同一身体段上，把它去掉后露出另一件衣物的，它是外层；两件互不遮挡的，按厂商展示图的穿法定。
- **「胸衣」拆开写**：文胸（罩杯式内衣）与束身衣（束腰的衣物）是两类；乳贴、贴片既不是文胸，也不是束身衣。

## 部位分类表（配件与非衣物类）：判据与默认菜单处理

| 类 | 判据 | 默认菜单处理 | 例外 |
|---|---|---|---|
| 颈／身／嘴 | 挂在颈、身上或叼着的配件（项圈、项链、包） | 按位置聚合的配件开关 | 叼在嘴上的单独一组；厂商一个参数管几件（包＋名牌＋玩具）时一起开关 |
| 腿饰 | 腿上的非袜件（吊袜带、腿环、腿绷带） | 「腿饰」 | 显隐由鞋、袜组合决定时，新开一层当唯一所有者 |
| 身体改形 | 形态键而不是衣物（收缩键、束腰类键如 `Waist_thin`、乳头键、脚型） | 不做菜单项；挂在触发它的件上（Shape Changer）或写进声明层 | 胸围由用户定基线；束身衣是衣物，即使带束腰键，也按穿法归上衣或外套 |
| 机关／玩法 | 厂商私密菜单、道具 | 原样引用厂商菜单 | 按彩蛋与厂商机关的规矩处理 |
| 美甲 | 手甲、脚甲 | 常驻无开关，或由美甲插件自带菜单（按用户习惯） | 被鞋袜、手套遮住就隐藏，露趾例外 |
| 素体自带件 | 素体默认装、耳尾 | 整套 0 档＝素体默认装，可逐件脱，按部位并进部位开关 | 厂商备选件（如大胸版外套）不进开关组 |

- **本流程里**：「腿饰」由鞋袜组合决定显隐、「身体改形」挂 Shape Changer 或声明层、「美甲」随鞋袜手套隐藏、「素体自带件」整套 0 档与逐件脱，都做不到（没有组合条件，素体对象进不了部件开关）；写明并交人。
- **另一条轴**：装配方式（整套、自带 BoneProxy、环状、带骨架配饰、贴面、抱持、骨架内静态件）与本表互不替代。
- **跨工程不一致时**：同类件在不同工程里归类不同（内衣开关粒度、颈饰归属等），建立本工程菜单时写明取哪种，不默认照搬。

## 决策一：单独开关，还是并进部位组

- **默认并组**：部件开关按身体部位聚合、跨套共用（惯例）。
- **「单独开关」指什么**：在它所属分类的分区下单列一项，占独立参数。不新建按名字命名的跨套开关；等第二套同类件出现、也判为卖点之后，再议要不要合并成跨套开关。
- **单独开关的条件**（满足任一）：

| 条件 | 例 |
|---|---|
| 用户点名 | 某套的乳贴；加装的高跟鞋；叼在嘴上的道具单独一组 |
| 视觉权重＝卖点 | 推广自一个用户明示的实例，推广本身待审 |
| 厂商已单独开关，且它有视觉权重 | 厂商私密菜单里单独的「贴片」开关 |
| 追加件／替代件 | 额外的长裤：开时让掉短裤、靴、袜，关时三件回来（要在 Play 里按真实顺序验证还原） |
| 同部位两副、厂商示意二选一 | 长短两副手套 |

- **本流程里**：追加件的让位只在被让掉的件（短裤、靴、袜）没有自己的开关时能做，写进追加件 control 的 `disable_when_on`；它们各有部位开关时，要么放弃让位并写明穿模风险，要么交人。按真实顺序验证还原由 Runtime 的回归做。
- **反方向**：一个开关不许一次脱掉几个部位的件。例：开衫、裙、鞋都挂在「外套」上，点一下只剩泳衣——要拆开。
- **升级给人**：卖点判定未定时，「单独／并组」两案并列交用户。

## 乳贴类贴身件与「文胸归上衣」的冲突（候选取舍）

- **冲突**：有的工程定「文胸一律归上衣、内衣开关只管下装」，理由是遮胸门按开关判断时，「外套关、上衣关、内衣开」会把裸胸误判成被遮住。
- **理由已失效的条件**：遮胸门改成按**可见件显式列表**判断后，不再依赖开关归属，这条理由就不成立。
- **乳贴类件不适用「文胸归上衣」**：乳贴不是文胸；用户明示过的口径是「分类为内衣，但不跟内裤一起开关」。
- **候选取舍**：乳贴在「内衣」分区下单列一项，不新建跨套的「乳贴」开关；同时把它加进遮胸门的显式列表（`when` 列表）——不加的话，乳贴可见时乳头键仍按裸态写 100。
- **既有工程的相反做法**（贴片并进内裤开关、胸口绷带归上衣）改不改由用户定，不自动回改。
- **证据**：单一用户明示加推理，待跨工程验证。

## 决策二：跟整套走的内容

- **整套的形态变体**（兜帽戴／放等）占整套档位，不归部件开关。
- **素体件的让位**写进整套层的曲线，不加开关、不占参数位。本流程的整套层由 Runtime 生成、只写衣装根，写不进素体件：外购整套下都不需要的素体件由方案 `hide_body_parts` 永久剔除，要按套切换的做不到，写明交人。
- **被 BoneProxy 在构建期搬走的件**，整套 clip 要显式写它的显隐——构建后它已不在原父物体下，靠父物体的显隐管不到。本流程里 Runtime 已按 `outfit.json` 的 `bone_proxy_visuals` 把它们写进轮盘层；不要再把它们写进部件控件，部件层排在轮盘层之后，会盖掉轮盘的隐藏。
- **验证**：每个整套档位下，被让位的素体件与被搬走的件都按预期显隐。

## 决策三：什么时候用轮盘，配色怎么切

- **整套与发型**：RadialPuppet＋Float。末档必须选得到：厂商 clip 为循环（`loopTime=1`）时，Float 取 1.0 会回绕到第 0 档，素体基础装这类末档就选不到；做一份 `loopTime=0` 的副本。
- **同位置来源 ≥ 2**：用轮盘，由档位保证互斥（例：头部饰品轮盘）。
- **同风格耳尾**合成一个轮盘。
- **配色**：同构配色（只差材质）用换材质＋配色轮盘，不复制预制件实例（有用户明确要求过）。发色、瞳色是否做运行时切换，按工程问用户；服装配色要不要运行时切换没有通则，也按工程问。部件记录只写「变体机制是换物件／换材质／换贴图」。

## 决策四：默认值与开关语义

| 件 | 默认 | 依据 |
|---|---|---|
| 部位开关 | 穿 | 惯例 |
| 头部饰品 | 关（露耳） | 某工程用户明示 |
| 追加件（额外长裤、颈丝带） | 关 | 惯例 |
| 玩法件（抱抱熊等） | 关 | 惯例 |
| 有渲染风险的件（如 RenderQueue 3000 的腿部玻璃） | 关 | 惯例 |
| 全身丝袜内搭 | 关 | 某工程用户明示 |
| 卖点件 | 用户未定前，跟厂商预制件的默认 activeSelf 与展示图里的穿着状态走，标「待定」 | 候选 |

- **同一菜单里开关语义要统一**：例如一个菜单里八个开关统一为「点亮＝脱掉」（用 `Inverted`）。跨工程已经不一致（有的 1＝穿，有的 0＝穿、打开＝隐藏），所以记录默认值时写「穿／脱、显／隐」，不写 0／1。

## 决策五：接厂商参数，还是直接写网格

- **厂商参数层管着的件，一律驱动厂商参数**；复用厂商 ON／OFF clip 时全部曲线都要带上。只写 `m_IsActive` 会出现「网格没了、身体还瘪着」——厂商的收缩曲线被漏掉了。
- **本流程里**：驱动厂商参数做不到（厂商参数名会被拒绝，也没有 Driver），唯一的路线是把厂商 ON/OFF clip 登记为 `vendor_clips`，Runtime 会带上全部曲线；代价是厂商原菜单里对应的开关对这些属性不再起作用，写进说明。
- **名字像、但没验过效果的厂商参数不接**，保留厂商原菜单，让用户自己用。
- **厂商菜单引用，不复制**；例外：经用户同意，复制一份删掉失效项。
- **厂商开关的位置**：有的厂商不用 MA MenuItem，而是随预制件附带一份 VRCExpressionsMenu 资产（`menuToAppend`），再加上 `MA_Animator/` 目录里的 FX；两处都要读。
- **事实以厂商为准**：哪几件是一组、参数极性，按厂商目录下的 clip 与菜单资产定；「厂商排最后」只针对菜单偏好。

## 决策六：菜单文案与交付说明

- **文案**：中文部位名；以用户的叫法为准——改名只改显示名，参数不动（例：「眼下红」改为「腮红」）。
- **条件写在括号里**：如「爱心眼开（面捕专用）」。
- **交付说明要写的**（本流程里写进 `design.json` 的说明字段，随 `menu.json` 交到打包诊断）：违反直觉的归属（件被移出原部位开关）、没生效的互斥；素材包外补装的件（例如设计需求要兽耳而素材包里没有，从自有素材补装）单列来源。
- **同一件两个入口**（厂商私密菜单一个、本方部位开关一个）时，写清谁是所有者。

## 彩蛋与厂商机关：保留厂商菜单，没点名的不主动加

- **定义**（候选）：不属于常规部位开关、要主动发现或组合才出现的效果——厂商机关、状态形态键（ずらし、ほどき 这类「错开／解开」）、组合造型预设、隐藏或特殊配色、接触触发。
- **规矩**：
  - 厂商机关不重做、不拆进部位开关；厂商给了机关或私密子菜单（常命名为 `Private`），默认保留厂商菜单。
  - 用户没点名的效果不主动加；可选玩法件没请示不装。
  - 设计需求要、素材包里没有的件，从自有素材补装并做成菜单项，交付说明单列来源（本流程没有补装通道，写明交人）。
- **放进菜单**（候选）：引用厂商菜单，按套装名收进一个子菜单；`installTargetMenu` 必须设——为空时 MA 会把它塞进头像根菜单。私密／成人项集中在一个子菜单，不和外观混放。默认关。本流程里厂商菜单原样留在原位，Runtime 不调整 `installTargetMenu`，彩蛋只列素材、写进说明。
- **商品层清点**：逐条问——厂商给了机关或私密子菜单吗？有状态形态键吗？能组合出有辨识度的造型档吗（卖点件是这类组合的原料）？配色里有风格特殊的吗？都不成立就写「无彩蛋素材＋理由」，不为填栏而编。
- **升级给人**：每一条要进菜单的彩蛋都先问用户；清点结果只列素材，不自动进菜单。

## 脚甲压制门：鞋开或袜开都要压，露趾款例外

- **规则**（属用户偏好）：脚甲随鞋袜遮挡而隐藏；连脚袜同样盖住脚趾，所以压制条件是「鞋开 **或** 袜开」，露趾款例外。
- **写法**：动画转移里的多个条件之间是**与**，写不出**或**——「压制」要写**两条**转移（鞋开一条、袜开一条）；「不压制」那条一条就够。露趾档要单独开口子，不进压制条件。
- **验证**：鞋开袜关、鞋关袜开、全关、露趾鞋四种情况逐一读回脚甲显隐。
- **适用条件**：用户采用「脚甲随鞋袜遮挡」的惯例时；用户若要求美甲常驻或由插件菜单管理，按用户的来。

## 冲突检查单（工程层）：C01、C04、C05、C12、C15

这几条取决于具体头像、别的套和菜单，在工程里做。

| ID | 问句 | 做法 |
|---|---|---|
| C01 | 这个位置还有谁？素体、各套、各档发型、外购配饰都列上 | 先按位置枚举全部来源，再逐件单独渲图确认（例：素体默认态头上已有两副耳朵，66 格渲图却全判「未见穿模」） |
| C04 | 冲突属于哪类？甲：切换时顺手关；乙：开着期间一直压；丙：同位置互斥 | 甲用参数驱动改参数；乙单开一层写属性；丙定优先级链、只压一侧 |
| C05 | 它在优先级链上排哪？有没有反方向那条？ | 「A 压 B」「B 压 A」同时出现就是错（例：头饰 ＞ 服装头部小件 ＞ 耳朵，删掉反向那条） |
| C12 | 它的显隐由几个开关组合决定吗？ | 新开一层当唯一所有者，并从原部位表里删掉（例：脚踝绑带，鞋或袜任一开就显示） |
| C15 | 验收有没有「该位置全关」那格？跑没跑组合？ | 档位 × 冲突开关全组合遍历，死锁格为 0 |

- 截图填冲突表，烘焙后量交付态；「全关」格常常是唯一能暴露归属错误的格。
- **本流程里**：C04 只能用「把被关件并进开关」这一种乙形式（被关件不再有自己的开关）；甲（Driver）与 C12（多开关组合的所有者层）做不到，写明交人；C01 的逐件渲图由 Runtime 的回归照片代替。

## 部件与菜单的未决事项：默认动作

下表仅为历史设计线索。实际实现引用已接受配置与有效决定；未确定语义先通过现有方案修订/决策入口取得决定，不写未决条目，也不擅自实施候选。

| 未决项 | 默认动作 |
|---|---|
| 卖点件是否单独开关（推广到新套装） | 单独、并组两案并列，标「待定」 |
| 视觉权重定级 | 按候选判据给级并标「候选」；算出的级与用户定过的级不符时，回报「判据待改」，不改用户定的级 |
