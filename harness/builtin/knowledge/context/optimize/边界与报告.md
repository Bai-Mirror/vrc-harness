# 优化的边界与报告口径

## 优化的边界：外观与功能优先于性能数字

优化只做不改变交付外观与功能的改动。以下做法越界，未经用户同意不做：

- 把主图降到 2048 以下（Harness 的检查会阻断）；主图降档而没有审美确认；主图的 A/B 被独立评审看出差异仍然降档。辅助图与 Cubemap 例外：档位是硬上限，看得出差异也要降到档位，写明风险交人。
- 为了评级减面或删内容——减面改的是客户自备的资产。
- 为了让死参数检查归零而删功能；用缩小或排除包围盒的办法掩盖 AABB 超界。
- 把设置不同的 PhysBone 强行合并，改变抓取、摆姿或手感。
- 按名字或「当前看不见」判断物体没用就删。死重按引用判；两个常见假阳性别删：SPS / VRCFury 的插槽标记（如 `_Gimmick/Gimmick_SPS/**`，构建期按组件配置引用，不走动画曲线，引用判据看不见它们；一例 16 个渲染器合计才 736 顶点，不值得冒险）；缩放为 0 的占位物（厂商预制体常见，enabled 也 active 却画不出东西，还常带空材质槽——别去「修」它）。

守住边界的做法：

- **本流程里你只写 `Optimize/design.json`**：AAO 由 Runtime 挂上并固定为安全配置，贴图导入设置由 Runtime 在构建副本里按 `texture_plan` 套用，PhysBone 只能写 `remove_duplicate` 或 `remove_noop`；改错了就改 `design.json`，Runtime 每次都从改色层重建。不要改厂商资产，不要启动 Unity。下面几条是自己开 Unity 时的做法，供判断。
- 删错或改错时，用 `PrefabUtility.RevertPropertyOverride` 精确回退那一项，不用撤销栈。
- 每个改动后回读并做骨架自检：Head 与 Foot 骨世界 y 之差与基线相差 <1 mm，且 `Animator.isHuman` 为真；造型变形或静止姿态被弹开，就回退最近的动骨或骨架改动。
- 删完物体扫一遍空材质槽（渲染成洋红）：遍历渲染器的 `sharedMaterials` 数 null，必须为 0。
- 只有性能数字没达标、而外观与功能都正确时，报告真实瓶颈，由用户取舍。

## 多套服装必然 VeryPoor：面数是锁死项

- PC 端面数的 Poor 阈值是 7 万。实测：四套衣服加三套发型共 391,865 面；五套衣服加三套头发共 600,962 面。多套服装的头像综合评级必然 VeryPoor，这属正常，不是做坏了。
- 要降只能减面，而那是改客户自备的资产，必须客户同意。
- 评级被面数锁死时，贴图与动骨优化仍有真实收益：一例构建后贴图内存 153.8 → 110.6 MB，贴图一项从 VeryPoor 到 Poor，综合徽章仍是 VeryPoor。
- 交付说明里必须写清评级为什么是 VeryPoor、原因是面数，并尽早告诉客户。本流程的交付说明由 Harness 生成，这条由打包阶段的诊断写进 `performance_tradeoffs`。
- 贴图档位（主图不低于 2048、辅助图 1024、Cubemap 512）自用工程同样适用，不因为「评级反正是 VeryPoor」就放弃。

## 优化报告的读数口径：前后快照、逐项归因

- **本流程里**：前后报告就是 build_pre 与 build 两次构建的 `perf.json`，由 performance 阶段对比；你读 build_pre 的 `perf.json` 写设计，不自己出报告。
- **固定顺序**（自己开 Unity 时）：出基线报告 → 逐张列贴图找异常 → 改导入设置 → 挂 AAO → 再出报告对比；每步留一份报告，前后两份进交付。
- **量的必须是构建后的克隆体**：编辑期的性能面板与报告是构建前的数。生成报告时在调用侧把目标对象名一并记下（报告工具不一定自己打印），以证明量的是克隆体；在源场景上量的作废重来；量完销毁克隆体，场景里残留的烘焙克隆为 0。
- **每个数写明取自哪个文件快照**，不从滚动日志里凭印象取。工具改过导入设置又复位时，日志里会有多个 before 读数，引最后一次（复位后）的：一例日志依次是 649.3 → 671.0 → 160.7 MB，汇报表引了作废的 649.3，真值是 671.0。
- **逐项对比基线并写原因**：任何一项差异解释不了就不交付，把叠在一起的改动拆开重跑。
- **验收项**：贴图内存低于基线，且没有默认平台条目为 RGBA32 的残留；PhysBone ≤ 256 且无重复；AABB 在 5×6×6 m 内；AAO 后逐件复检材质错位与接缝；Console 无 Error 级 NDMF 日志；骨骼、形态键、蒙皮网格不高于基线；面数不高于基线，下降部分能归因到 AAO 删除的永远关着的渲染器。本流程的性能检查更严：可见面数（总面数减去从来不可见的面数）必须与优化前相等，有任何变化都会阻断；遇到时逐个渲染器归因，写明交人。
- 平台覆盖类改动编辑器验不出来，报告里标「本项未经真机验证」。
