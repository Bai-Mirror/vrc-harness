# 配色：颜色来源、贴图判型与共用材质

## 改色开工：需求里的每条颜色都要先对上来源

**职责**：把需求里的色彩描述落成可复跑的配方与可挑选的候选。

**权威输入**：需求问卷（色调、撞色、各部位颜色、风格偏好）；已导入的素体贴图包与服装材质；厂商说明书。

**本流程里**：recolor 阶段只支持按 `hair`／`eye`／`outfit:<id>` 做 HSV 调色（lilToon 上写 `_MainTexHSVG`，方案范围：色相 −180～180、饱和 0.5～1.5、明度 0.7～1.3）。换贴图、掩膜改色、异色瞳、渐变、叠色层、改 PSD 源文件都没有落地通道；需求里出现这类要求时写明交人，应在方案阶段拦下——本版独立发色轴只落厂商已有的配色（银灰、金两档），程序生成的发根到发梢渐变不提供（`决定记录/D-120`），不得用纯色或近似档冒充。超出范围的压暗或提亮同样交人。

**决策边界**：
- 每条颜色需求对上一个来源：改颜色参数（服装配色；Harness 对 lilToon 写 `_MainTexHSVG`，其他 shader 改 `_Color`）；换素体贴图包里的某张图（眼睛、妆容、身体）；或按掩膜改色（睫毛、眉毛这类没有现成配色的）。
- 服装配色与素体贴图是两件事：前者改颜色参数，后者是换整张图。问卷里的「眼睛颜色」「头发颜色」多半要靠素体贴图包落实，漏掉就是一条已下单的需求整个没做。
- 只有生成候选图的那一步需要 Unity；量图集、写配方可以离线先做。

**禁止**：问卷缺色调、撞色、各部位颜色、风格偏好中的任何一项时自行猜测；让某条颜色需求没有来源就进入候选。

**产出**：需求 ↔ 来源对照表（每条需求一行：部位、目标、来源类型、具体文件或材质）。

**验证**：没有来源的颜色需求 == 0；问卷点名的眼睛、头发颜色各自有来源。

**升级给人**：问卷缺项需要回问；某条颜色需求找不到任何来源。

## 替换贴图判型：按 alpha 不透明占比分整张底图与叠加层

**职责**：动手之前量清每张替换贴图，是整张重绘，还是只画自己那一块、其余透明的叠加层。

**权威输入**：替换贴图与素体原图的 alpha 通道；厂商说明书。

**决策边界**：
- 不透明占比与素体原图相当 → 整张底图，直接换 `_MainTex`。
- 明显更低 → 叠加层。优先离线合成（alpha-over）进底图：合成出来是什么就是什么，能直接开图核对，也不多占一层采样。挂到 shader 的第二层（`_Main2ndTex`）要伺候 `_Main2ndTexBlendMode`、`_Main2ndTexAlphaMode`、`_Color2nd` 一堆开关，结果还依赖 shader 版本。
- 厂商说明书指定了挂哪个槽的，照做；说明书写明作画时哪些形态键开到多少的，也照开，否则画上去的图案与几何对不齐。
- 有厂商遮罩、只改颜色时，可以不改像素，用 lilToon 的叠色层。

**禁止**：不量占比就决定挂法。

**产出**：图集清单：每张图的不透明占比、类型（底图／叠加层）与挂法。

**验证**：每张替换贴图都有「占比＋类型」记录；合成后开图核对。

**升级给人**：说明书与实测结果矛盾时。

## 共用材质：改色前列出每个材质被哪些网格共用

**职责**：防止改一个材质时，把不相干的部件一起改掉。

**权威输入**：遍历所有渲染器的 `sharedMaterials` 得到的「材质 → 网格」清单。

**本流程里**：修改参数或贴图时，Runtime 按「渲染器 × 原材质」各复制一份再改，共用材质不会被连带改到别的套；但 `outfit:<id>` 会改该套下全部渲染器，套内共用同一材质的各件一起变色。纯选择厂商材质只替换指定服装内命中槽的引用，可以共享原资产；独立回读核对计划 GUID 与实际绑定，不把这种共享当作修改副本的隔离失败。

**决策边界**：服装的一个材质槽常被多个网格共用。实测例子：`Outfit01` 被衬衫、短裤、袜子、马甲、靴子五个网格共用；`Outfit02` 被包、内衣、帽子、眼镜、猫尾共用；`Shoes` 材质同时用在绷带、鞋、袜上。要改的材质共用网格数必须为 1；否则只把副本或覆盖图挂到具体网格的具体材质槽上。

**禁止**：直接改共用材质或厂商材质原件。

**产出**：材质共用清单。

**验证**：修改材质副本沿用流程的隔离判据；纯选择厂商材质沿用流程的计划可执行性与实际绑定判据。

**升级给人**：需求必须整体改一个共用材质才能达成时。
