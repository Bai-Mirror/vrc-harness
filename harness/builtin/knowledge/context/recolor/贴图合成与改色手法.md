# 配色：配方脚本、按掩膜改色、异色瞳与渐变

## 配色配方脚本化：参数集中在文件头，幂等，配方入库

**职责**：让配色结果可以重跑、可以复现。

**权威输入**：图集清单；逐件规则表。

**本流程里**：配方由冻结工具 `generate-recolor-candidates`（`recolor.py`）生成，参数只来自方案和用户修改意见；它已按能力包清单冻结，检查 `recipe_script_tracked` 以它为准。执行方不另写配方脚本，也不做 git commit（执行方沙箱里 `.git` 只读）。

**决策边界**（人工作业时）：
- 配方写成脚本，参数集中在文件头的常量里，改一个数就能重跑。图集是二进制，通常不进版本库；配方丢了，结果就没法复现，所以配方要入库。
- 带相对运算的批处理（例如「向目标色混合 50%」）一律做成幂等：用状态文件记录已处理的项；先 dry-run 出改动明细表，确认分寸后再 apply，而且只跑一次。
- 不要往 `.mat` 里塞标记注释，有被 Unity 序列化器改写的风险。

**禁止**：非幂等的脚本重复 apply（重跑一次就二次漂移）。

**产出**：配方脚本；状态文件；dry-run 明细表；回读自检的输出。

**验证**：同一输入重跑配方，输出哈希不变；第二次 apply 没有漂移；配方已在版本库里。

**升级给人**：某个外部步骤无法做到幂等，又必须重复执行时。

## 按掩膜改色：先找厂商遮罩和源文件，掩膜来源要可证

**职责**：给没有现成配色的部位（睫毛、眉毛之类）改色，例如素材包的色系里没有需要的银白。

**权威输入**：厂商遮罩；分层源文件；素材包里同一部件的多个色档。

**决策边界**：
- 先后顺序：厂商遮罩（可用 lilToon 叠色层，零像素改动）→ 分层源文件（PSD、CLIP）→ 都没有，才在压平的贴图上做。没遮罩不等于只能在压平贴图上做像素手术。
- 在压平贴图上做时，掩膜来源必须可证、不能手描：包里自带的掩膜（例如某张眉毛掩膜的一个通道就是两道眉弓）；或两个色档相减（差值超过阈值的像素就是该部位，前提是它落在独立的 UV 区、掩膜干净）。
- 改色用保亮度着色 `new = target × (lum / mean_lum)`；直接填单色，会得到一坨没有笔触的色块。
- 自己派生的遮罩贴图，导入时关掉 sRGB（`importer.sRGBTexture = false`），否则通道值会被 gamma 拧一遍。

**禁止**：手描掩膜；平涂单色；有源文件时仍在压平图上做像素手术。

**产出**：掩膜（附来源说明）、改色结果与回读数据。

**验证**：掩膜覆盖范围与目标部位的 UV 岛对得上；回读的颜色达到目标，且笔触明暗仍在。

**升级给人**：只能在压平图上改、并且会影响笔触或画风时，先征得同意。

## 异色瞳：先证明两眼在 UV 上分离，回读用眼色层自己的 alpha

**职责**：做左右不同颜色的眼睛。

**权威输入**：眼色层贴图与它自己的 alpha 通道。

**决策边界**：眼色层的左右眼通常是两个完全分离的 UV 岛（两岛的不透明像素数可以分毫不差）。确认分离之后，按中缝的列切开，左右各取一色即可，不需要手描蒙版。

**禁止**：用合成后整张图的 alpha 当取样掩膜。那样会选进一大片肤色，两边量出同一个肤色值，看起来像「没生效」，其实是判据取错了。

**产出**：合成图；左右两半的取样颜色。

**验证**：合成后回读，两半确实不同色；取样掩膜用眼色层自己的 alpha。两半同色说明方向或掩膜错了。

**升级给人**：两眼在 UV 上不分离、需要手工分区时。

## 竖向渐变：方向靠分列投票，t 逐列归一化

**职责**：落实「上浅下深」这类竖向渐变要求（例如眉毛、发梢）。

**本流程里**：本版没有生成渐变贴图的通道，发根到发梢渐变未提供（`决定记录/D-120`，并入 dev.1.2b）；本节只是人工离线作业的手法记录，不能据此在方案里承诺渐变档，也不得用纯色或近似档冒充。

**权威输入**：该部位顶点的 UV 与世界坐标；原图的亮度分布。

**决策边界**：
- 方向不能猜。PNG 的第 0 行在顶部，Unity 的 UV 原点在左下，两次翻转很容易绕晕；图集里各岛的相对位置也说明不了脸上的方向。判法：取 UV 落在该部位的顶点，按 u 分列，算每列的 `dY/dv` 斜率，再投票。整体相关系数会被弧度冲淡，分列之后多数列同号，结论才干净。
- t 要逐列归一化，不能用全局包围盒。眉毛是一道弧，按全局的行来算，会让弧的两端整条落进「上」或「下」。
- 亮度缩放要压制：原始笔触本身可能就上浓下淡，直接乘 `lum/ref` 会把想要的渐变正好抵消。

**禁止**：凭图集里的位置判断方向；用全局包围盒算 t。

**产出**：渐变结果；上下两段的实测亮度。

**验证**：上下两段的实测亮度真的分出高低，且方向与需求一致；分不出高低，就是方向或掩膜错了。

**升级给人**：分列投票的结果不一致（同号列不占明显多数）时。

## 两色拼瞳：分割线对准源图自带的暗带

**职责**：把两张同系列的瞳孔贴图上下拼成撞色时，让交界不露痕迹。

**权威输入**：各张源图逐行的明度剖面（逐行取 alpha 内像素的 V 均值）。

**决策边界**：拼之前先打出源图自己的明度剖面，把羽化区对准剖面的最低点。同系列瞳孔图常在同一位置自带一条暗带（虹膜上方的上眼睑投影阴影），撞色的过渡藏在这条自然阴影里就看不出来；分割线落在亮区，明暗差没有东西遮，会直接暴露成一道生硬的水平暗色断层。上一轮定的分割线如果「看着挺好」，先查它是不是正好踩在暗带上，再决定要不要动。

**禁止**：为了让某个颜色多占一点就随意移动分割线。

**产出**：明度剖面；分割线与羽化区的位置。

**验证**：羽化区覆盖暗带；同机位渲图交评审，没有「水平断层」类的指认。

**升级给人**：需求要求的颜色比例与暗带位置冲突时。

## 撞色选色与明度补偿：先算色相角差，别在线性空间做补偿

**职责**：挑选两种撞色、处理交界处的明度。

**权威输入**：两个主色的色相角；混合方式。

**决策边界**：
- 两色之间的过渡带会经过色轮上两者之间的所有色相。两个主色的色相角差 >180° 就是走长边，过渡带必然经过对比色区。例如粉＋金会绕经红、橙，中间掉成砖褐色的泥色；粉＋蓝经紫走短边，过渡干净。先算，再画。
- 线性混合 `out = a*w + b*(1-w)` 之后，再「把亮度拉回两端的线性插值」是数学上的恒等式：亮度是 RGB 的线性函数，`lum(a*w+b*(1-w)) ≡ lum(a)*w + lum(b)*(1-w)`，增益恒为 1。真要改交界明度，要在非线性空间做（对 V 或 L\* 单独加偏置），或者换分割线的位置。

**禁止**：写完补偿不验证就当生效。

**产出**：色相角差；过渡带的采样值。

**验证**：补偿类操作写完，拿补偿前后两张图做逐像素差，差为 0 就是空操作；过渡带的饱和度没有塌下去。

**升级给人**：需求指定的两色必然走长边时，说明后果，请用户选择。
