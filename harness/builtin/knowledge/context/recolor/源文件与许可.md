# 配色：分层源文件与来源许可

## 有 PSD 或 CLIP 分层源文件时，优先改源文件

**职责**：需要改贴图内容（不只是调颜色参数）时，选一种可控、可复现的改法。

**权威输入**：厂商的分层源文件；厂商导出的成品贴图。找源文件的地方：包内的 `PSD/`、`CLIP/`、`原本/` 目录；素体包 `Textures/` 下的分色变体；同一素体的其他妆容商品。

**决策边界**：
- 用可控的传统方式改：`psd-tools` 加 numpy 读图层、算渐变映射、合成导出。PSD 图层的 alpha 就是覆盖率，在源图层上改色天然干净。厂商有时在源文件里留好了默认隐藏的渐变映射图层，可以直接用。
- `psd_tools.composite()` 的合成结果可能与厂商导出的成品对不上；合成之前先拿成品 PNG 对照，量出差值。
- 源文件可能是另一种画风（扁平硬边与厂商成品的柔边不同），换之前先跟用户确认。
- 确实没有源文件，才回到压平的贴图上做；算法是把墨色当覆盖率重新合成，不是色相平移。

**禁止**：用生成式模型重绘贴图。生成模型控不住 UV 对齐，也控不住跨部件的配色一致，改完的图往往接缝对不上、颜色不统一。真要用（例如补一小块图案）：提示词严格限定、多模型交叉查证，并且只用在不影响 UV 接缝的小块区域。

**产出**：改过的源文件与导出图；自合成与厂商成品的对照差值。

**验证**：自合成与成品的差异已知、可接受；UV 接缝处没有错位；同机位渲图确认。

**升级给人**：源文件画风与当前贴图不同；不得不用生成式补图时。

## 贴图与 shader 的来源许可：查不清就不进交付

**职责**：保证交付件里的每张贴图、每个 shader 来源清楚、引用可解析。

**权威输入**：素材来源登记（哪个包、哪张图、哪个版本）；材质引用的 shader GUID。

**决策边界**：
- 分层源文件按「哪个包、哪张图、哪个版本」集中登记，不要散在各工程里。
- shader 的 GUID 必须能解析：字体或付费 shader 的引用解析不到，材质就是洋红；交付前用 GUID 反查一遍。
- Patreon 分发的 shader、工程模板带来的私有 shader、付费贴图，逐单查来源，不进交付件。
- 「看起来一样」不能当来源证据。

**禁止**：把来源查不清的贴图或 shader 放进交付件。

**产出**：来源登记表；交付材质的 shader GUID 解析结果。

**验证**：交付材质引用的 shader GUID 全部可解析；来源不明的项 == 0。

**升级给人**：来源查不清、又必须使用时，由用户拍板。
