# 配色：lilToon 参数判据

## lilToon 叠色层：用厂商闲置遮罩只染局部

**职责**：材质是 lilToon、厂商留有遮罩、只需改颜色时，不改一个像素地局部改色。

**权威输入**：厂商遮罩贴图（常放在 `Textures/_etc/Mask/` 之类的目录）；材质参数。

**决策边界**：`_UseMain2ndTex`、`_UseMain3rdTex` 是带遮罩的叠色层。不少厂商已经把遮罩画好（例如只盖眼球圆的、只有眉毛笔触的、发网的），开一层就能只染该部位：
- `_UseMain2ndTex = 1`
- `_Main2ndTex` = 那张遮罩本身（它的 alpha 决定作用范围）
- `_Main2ndBlendMask` = 同一张
- `_Color2nd` = 目标色（alpha 为强度）
- `_Main2ndTexBlendMode` = 按枚举值填
分工：有厂商遮罩、只改颜色 → 叠色层（零像素改动、可逆，改 `_Color2nd` 就能出档）；要换整张图，或没有遮罩 → 离线合成。

**禁止**：按遮罩的名字假定作用范围。先量 alpha 覆盖率，再对一下目标部位的 UV 岛面积；名为 Eyebrow 的遮罩可能只有一道眉、不含睫毛。

**产出**：叠色层参数；遮罩覆盖率读数。

**验证**：遮罩覆盖率与目标部位的 UV 岛面积相符；同机位渲图确认只染到了目标部位。

**升级给人**：遮罩的覆盖范围与需求部位不符，又没有分层源文件时。

## lilToon 叠色层混合模式：枚举值去源码查，乗算提不亮

**职责**：给叠色层填对混合模式，并按目标调深浅。

**权威输入**：lilToon 源码里的混合模式枚举；厂商材质原本的设置。

**决策边界**：
- 混合模式枚举：Normal(0)、Add(1)、Screen(2)、Mul(3)，出处是 lilToon 的 `lilLanguageManager.cs` 里的 `sBlendModes`。方案写「乗算」，却按语义顺序猜填 0，得到的是 Normal，也就是直接替换：整只眼被平涂成一个色盘，虹膜层次与瞳孔花纹全没了。厂商自带的脸材质在这个槽上可能用的就是 3。
- 乗算永远提不亮。「颜色有点深」时把 `_Color2nd` 往白靠是错的：乗算只能压暗，往白靠只是让压暗量趋近 0，回不到基底之上。结果是 HSV 的 V 几乎不变、只有 S 下降，也就是去饱和；肉眼分不清「变淡」和「变灰」，一测 HSV 就露馅。
- 想真提亮：换 Screen(2)，代价是把虹膜洗白、瞳孔与虹膜的对比糊平。想少压暗、保住结构：乗算加降低 α（多数时候最好），但它提不亮，只是压得少。

**禁止**：按顺序猜枚举值；用「往白靠」来提亮乗算层。

**产出**：混合模式、α 与调整前后的 HSV 读数。

**验证**：调深浅前先说清要动的是 V 还是 S；出数报 HSV 三个分量，不只贴 hex。

**升级给人**：「提亮」与「保住虹膜结构」不可兼得时，各出一档让用户选。

## lilToon 颜色读数：贴图值、材质文件数值与渲染结果不是一回事

**职责**：判断颜色、描述颜色时读对口径。

**权威输入**：实际渲染，或按 shader 参数推算的结果；工程的色彩空间设置；lilToon 的功能开关设置。

**决策边界**：
- 渲染时还有一层放大：贴图上看着闷的红，渲染出来可能是艳的，因为 `_MainTexHSVG` 的饱和度与 `_EmissionColor` 会再放大（出现过饱和 1.75 叠加自发光 1.414 的组合）。调色按贴图值调，但用模拟或实际渲染验收，不要看贴图缩略图下结论。
- 工程是 Linear 色彩空间（`m_ActiveColorSpace: 1`）时，`.mat` 文件里存的是 linear 浮点，Inspector 显示的是 sRGB；照着文件里的数字描述颜色会错得离谱。
- 「某个功能开关关着」在查证之前不能当结论说出口。第二层贴图看着没生效时，先查 `ProjectSettings/lilToonSetting.json` 里的对应开关（如 `LIL_FEATURE_MAIN2ND`），再看那张图的原始像素；出现过开关其实开着、只是原图本来就是闷的棕色的情况。

**禁止**：拿缩略图或 `.mat` 里的原始数字直接描述颜色；凭猜测报「开关关了」。

**产出**：带口径说明的颜色读数（渲染或推算、色彩空间）。

**验证**：颜色结论附渲染图或参数推算过程。

**升级给人**：渲染结果与需求色的差距无法用参数解释时。

## lilToon 跨大版本升级：材质迁移不可逆，先备份

**职责**：工程需要升级 lilToon 大版本时，保住可回退的材质状态。

**权威输入**：当前的材质数组与 `.mat` 文件；lilToon 版本。

**本流程里不升级**：lilToon 版本由 setup 阶段的冻结 VPM 锁定（`setup-project` 从基准工程复制），各阶段都不升级包，recolor 也写不了 `Packages/`。看起来需要升级时，写明原因交人。

**决策边界**（人工作业时）：lilToon 跨大版本会单向迁移材质，迁移不可逆。升级前先备份当前的材质数组与 `.mat`，再升。

**禁止**：没有备份就升级。

**产出**：备份位置与升级前后的版本号。

**验证**：备份可以还原（抽查几个材质的参数与升级前一致）。

**升级给人**：升级是否必要不清楚，或升级会影响交付兼容性时。
