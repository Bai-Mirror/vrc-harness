# 装配后的默认显隐与重叠取舍

本文件给装配阶段的执行方：装配完成后，默认状态下每个部件显不显示，由执行方依证据决定；哪些取舍必须交给用户，哪些必须自己按部位核对。每节独立成立。

## 装配后的默认显隐：按证据决定，按后果分流

- **职责**：装配完成后，默认状态下每个部件显不显示由执行方决定。本节的取舍口径对任何素材组合都成立，不认资产名、目录名或厂商命名习惯。
- **先读清单再决定**：装配完成后 Runtime 会写出默认状态下实际可见的部件清单与部件两两之间的重叠量距（互接触面积、最近距离、来源是不是同一件），并附素体自带衣物的成组证据；阻断检查会把「同位叠放」拦下。执行方先读这份清单，再决定默认显隐，不凭经验在方案阶段预判，也不靠名字猜。
- **清单里有身体部位**：每个可见部件都归到一个身体部位（头／颈／胸／腰臀／上臂／前臂／手／大腿／小腿／脚；蒙皮网格按累加权重最大的人形部位，无蒙皮的按父级链上最近的人形骨骼；两样都对不上的记「其他」）。摘要另有一节把这些件**按部位、再按来源**列出。判据只量面与面贴在同一位，量不到「同一槽位放了几件」；**按部位分组的那一节就是给你数这个用的**：同一个部位下出现同一来源或不同来源的多件同类件时，先看它、再定谁留谁让。
- **两条阻断读数**：`visible_overlap_pairs`（同位叠放）与 `visible_interpenetration_pairs`（衣物之间看得见的互穿）。两条都要读到 0 才通过；读数是 `null` 表示**没量完**（不是 0），按失败处理并报告。
- **可恢复的显隐 vs 永久的剔除**：执行方决定的是**可恢复的默认显隐**——关闭后仍能按套打开，用 `object_state`；构建时整棵剔除素体自带件（永久、不能按套恢复）仍由方案决定并批准。若要连构建一起排除（厂商测试或辅助网格），再给 `object_state` 加构建排除。
- **每条关闭都要写理由**：每条关闭必须写明依据（是读数里的哪一条、为什么保留另一件）。空理由或没有理由的关闭不被接受；判据只报「哪几层在同一位置、各自多可见」，不给「该关哪个」的结论，理由由执行方给。

### 执行方可以自己决定的

- **同一来源件内的尺寸／体型版本只留一个**：同一件衣服把多个体型版本放进同一个来源时，按**素体网格的实际形态键权重**取一个，并用**厂商自己的体型键动画**（同一条曲线同时写了哪些件的哪几个体型键）确认哪些网格属于同一族。不要按几何贴合度取：多个版本互相近乎重合，贴合度差异落在网格噪声里，方向还可能反着。
- **厂商测试／辅助网格一律关闭并排除出构建**：结构与量距表明它是穿模警告、测试或辅助网格（与正式版本几何近乎重合、厂商没给它开关）时，关闭默认显示并排除出构建。判定看结构与量距，不看名字。
- **成组关系从素材包自己读出来**：素体自带衣物的分组证据是①同一素体包里多个预制体的非身体渲染器集合差集，②厂商开关动画里被同一条曲线一起开关的件。按组处理，不按名字。
- **素体自带成套衣物 vs 外购服装同部位**：保留订单点名购买的那一件，关闭素体自带的那一组（组按上面的证据定）。素体自带的那一组是厂商为「原装穿着」准备的，被外购整套替换时通常整组让位。

### 要交给用户的

- **跨来源的同部位叠穿**：多个来源件在同一部位、同一半径互相遮挡（例如几层腿部袜子、几件上衣），取舍取决于订单目标与审美，不是几何能定的。执行方按订单点名的件取舍；**取舍会改变用户要的外观时，写进本轮提交的 `user_review` 清单**，交给用户确认，不自己拍板就算完。
- **里层那件是订单点名要露出的**：衣物之间的互穿要关掉里层那件时，先看订单是不是点名要它露出；是就不要自己关——保留这一件，并在配方的 `interpenetration_decisions` 里对这一对写 `ask_user`、`rationale` 与 `review`（指向下面那条编号取舍的编号），它会进交付说明的「需要你确认的取舍」。

### 衣物之间看得见的互穿：怎么读、怎么处理

- **这是另一条读数，不是上面那条的放大**：`visible_interpenetration_pairs` 数的是「里层衣物从外层衣物里穿出来、而且在画面上看得见」的对数。上面那条读的是「两层贴在同一位」（接触面积 ≥1 cm²），两件相交很浅时它可以低到不报——所以不要因为 `visible_overlap_pairs` 是 0 就以为衣物之间没有互穿。
- **怎么读**：摘要的 `visible_interpenetration` 一节给 `layer_reach_mm`（判里外层用的贴近长度）、`poke_reach_mm`（**穿出深度的量程**）、`inner_ratio`（里层判定所需的比例）、`min_vertices`（进入决定的最小确认顶点数，也是缝线噪声界）、`guard_depth_mm`／`guard_vertices`（护栏）、`depth_probes_mm`、`depth_tolerance_mm`、`views`，以及逐对的证据行：`layer`（里层件）、`outer`（外层件）、`candidates`、`confirmed`（渲图确认的顶点数）、`visible_pixels`（**渲图里看得见的像素量**，按机位去重）、`depth_max_mm`／`depth_median_mm`／`depth_counts`（**穿出深度分布**）、`depth_at_least`（**最深只到量程上界时，读作「至少 depth_max_mm」**，不是实测值）、`body_part`／`outer_part`（各自量到的部位）、`layer_source`／`outer_source` 与 `layer_role`／`outer_role`（**来源与它在订单里的角色**，如 `hair`／`outfit`）、`out_of_bounds`（是否越护栏）、`decision`／`decision_valid`／`decision_note`（你写的决定与是否生效）。一节顶部给 `counted_pairs`（仍在阻断的对数）、`undecided_pairs`、`out_of_bounds_accepted_pairs`、`ask_user_pairs`。几何只提候选，**看得见**由渲图确认：全部可见时该像素最前面必须是里层件而且在那个顶点自己的深度上，关掉里层件后同一像素露出的必须是外层件——三条同时成立才算。`valid=false` 或读数为 `null` 表示这次没量完。
- **Runtime 不替你判断，但要求你逐对判断**：每一对达到 `min_vertices`（8）的确认对都要在配方的 `interpenetration_decisions` 里写一条三选一。三个决定的含义与写法：
  - `close`：可恢复的关闭（`object_state`，`active: false`），配方里必须真有这条操作，并写 `rationale`（依据哪对读数、为什么关这一件）；
  - `accept`：按准则接受、不打扰用户。必须写 `criterion`（你依据哪条准则）与 `evidence`（你看了哪项证据），且这一对**不能越护栏**；
  - `ask_user`：保留并请用户确认。写 `rationale`（为什么要用户看）与 `review`（指向 `user_review` 里那条编号取舍的编号，例如 `T1`）；方案只写在那一处，这里不重复写。它会进交付说明的「需要你确认的取舍」。
  ```json
  {"objects": ["<里层件路径>", "<外层件路径>"], "decision": "close",
   "criterion": "订单点名的件优先保留 / 同一部位重复只留一件", "evidence": "confirmed=64, depth_max=0.96mm, visible_pixels=…",
   "rationale": "…"}
  ```
  没有决定、决定与测量对不上（`close` 却没有这条关闭、`accept` 没写准则、`ask_user` 没写理由）的对，以及**越护栏却写了 `accept`** 的对，都会计入 `visible_interpenetration_pairs`；`decision_valid` 与 `decision_note` 会告诉你哪一条没成立。**每轮的决定表要对着最新一次可见清单重写**：多关几件之后，某一对可能从「低于最小量」变成「达到最小量」而需要决定（本轮 A 上就漏过一次 `Coat↔黑丝`，判据照旧把它算成阻断）。
- **护栏只挡明显越界**：`out_of_bounds=true` 指确认顶点数超过 `guard_vertices`（128）、或确认样本的实测深度超过 `guard_depth_mm`（2 mm）——成片翻出（裙子、裙摆）一定会因顶点数越界，那种不许用 `accept` 放过，只能 `close` 或 `ask_user`。两个界取得宽松，不是按某个头像调到刚好通过；界内仍由你按准则判断。**深度读到量程上界时按「至少」理解**：`depth_max_mm` 是确认样本到外层最近三角面的带符号距离（局部表面间距），只在量程 `poke_reach_mm` 以内有效；`depth_at_least=true` 表示最深样本只到量程上界，`depth_max_mm` 只是下界，真值只会更深——这种对不能 `accept`（深度没被量到护栏以内），要么 `ask_user`，要么证实它是薄相交后再定。
- **准则**（边缘情况列不完，下面是判断的依据，不是清单）：① 按正常观看距离看不看得出来；② 订单点名的件优先保留；③ 同一部位重复的只留一件；④ 改变订单方要的外观时才问用户；⑤ 关掉贴身里层之前，先看它外面那层下面是不是直接就是身体——是的话优先 `accept` 或 `ask_user`：关掉可能让回归阶段看到身体从外层穿出（PF4／GI2 在 A 上实测，关掉胸口里层后领口下露出 2 个顶点；这是实测出处，不是判据）；⑥ 订单把一个整套列为**配饰**、另一个列为**服装**，两者在同一部位冲突时，**配饰套装里的服装件让位**：关掉配饰套装里与主服装冲突的**服装件**（裙、鞋之类）并写明理由，配饰套装里的**纯配饰件**（头饰、链饰、刀具之类）照常保留——配饰套装的身份来自订单，不是「它里面有裙子」就当成服装。判断不了的（例如两边都是纯配饰，或订单没写角色）仍按下面的编号取舍交用户。
- **订单方给的三个示例＋一条配饰让位例子**：全身丝袜与鞋子、外套只隔**薄薄一层**的相交**没关系**（`accept`，criterion 写「薄薄一层」）；袜子与全身丝袜**位置重叠**时**关掉袜子**（`close`，属于同一部位重复）；**头发与外套的相交默认不管**（`accept`，criterion 写「头发默认不管」；`outer_role`/`layer_role` 会告诉你哪一方是订单里的 `hair` 来源）。**配饰让位**（准则⑥）的例子：订单把一整套列为服装、另一整套列为配饰；配饰套装里的裙子与高跟鞋跟主服装的外套、靴子在同一部位（腰臀／脚与小腿）冲突，就关掉配饰套装里的裙装与高跟鞋（准则⑥，理由写清「订单把该套装列为配饰、另一套装列为服装」），配饰套装里的头饰照常保留。哪一件是服装、哪一件是配饰，从方案条目与建档的 `role`／清点里读（见下面「角色是认出来的」）。
- **角色是认出来的，不是猜的**：来源在订单里的角色按方案条目认（plan 的 outfit 角色 → 清点 `role` → item 路径里产品自己的分类目录 `taxonomy.ts`），认不出来记 `unknown` 并在注记里写明——那是给你的一条证据，不是替你决定。
- **里外层是量出来的，不是按名字定的**：一件衣服的顶点大多数落在另一件的**里侧**时它才是里层；系在外套外面的腰带这类外层设计，顶点大多数在外侧，不会被当成穿出。**深度的口径要说清**：`depth_max_mm` 是确认样本到外层最近三角面的带符号距离（局部表面间距），量程 `poke_reach_mm` 以内是实测；它不等于「穿过面料的深度」，量程之外的更深处这次没有量到。
- **不许**：放宽阈值、改判据、把最小量调小来让读数变绿；用「看起来没事」代替证据；拿 `accept` 当消音器——越护栏的对只能 `close` 或 `ask_user`，写不出准则与证据就该关掉里层或问用户。
- **每个要用户看的取舍都编号、带可执行方案**：一条取舍写一项，字段是 `{id, question, detail, options, recommended, current}`——`id` 是稳定编号（`T1`、`T2`…，一次运行里只出现一次），`question` 是问句（「哪一件留下」），`detail` 是依据（同部位同半径、各自关掉后画面怎么变），`options` 是 2–4 个方案，每个方案写 `{id: "A", label: 说明这个方案, operations: [可恢复操作]}`，其中 `operations` 就是「用户选它就在配方里做的那些操作」——只能是 `object_state` 的 `active` 开关（可恢复，写 `rationale`），「保持现状」写成空数组，**不能**把构建排除（永久剔除，那是方案的事）写成选项；`recommended` 指向你推荐的那一个方案编号（只能是**一个**字符串），`current` 指向本轮产物**实际用的**那一个方案编号。交付说明会按编号列出各方案并标出「推荐」与「当前」，用户回一句「T1 选 B」就能改。**Runtime 会校验**：方案数不在 2–4、编号重复、方案引用的对象不在观察里、方案里用了不可恢复的操作、推荐不是一个、`current` 与配方里实际生效的操作对不上，都会拒收整份配方。`interpenetration_decisions` 里 `ask_user` 的对用 `review` 指向这条编号，选项不再写第二处。三段都用简体中文，用户看得懂。
- **重做意见里写了编号就照那条方案执行**：用户在重做意见里写「Tn 选 X」时，读上一次回执（`user_review`）里该编号的方案 X，把它 `operations` 里列的 `object_state` 原样写进本轮配方，把该条的 `current` 改成 X；**其余取舍保持不变**，不要顺手改动没被点名的编号，也不要重新解释用户想要什么效果。编号与方案以上一次回执为准（不要凭记忆或自己的措辞重建）。用户没有写编号时，按上面的准则自己判断，只有会改变订单方要的外观时才新开一条编号取舍。

### 判据抓不到、执行方要按部位自己核对的

- **判据只量「面与面贴在同一位」，量不到「同一槽位放了几件」**：接触面积小但在同一部位重复的情况，量距判据抓不到，执行方要按身体部位自己数。例：
  - 订单买了发型时，素体自带的头发与发饰属于被替换的一组，按上面「素体自带成套衣物」处理；
  - 两件外购服装各带了一双鞋（或同部位的同种件）同时穿着时，同一部位只能留一双，按订单点名或主服装取舍，并把取舍写进 `user_review`；
  - **腿部同一部位的贴身件（袜子、裤袜与全身丝袜）**：全身丝袜盖住整条腿，与袜子／裤袜**必然位置重叠**（这与「薄薄一层穿出」不同——那是深度问题，这是同槽位重复），保留订单点名的那一件（例如点名的「全身黑丝」），把其余来源的贴身件用 `object_state` 关掉并写明理由；有取舍空间时一并写进 `user_review`。

### 禁止

- **禁止**：用关闭部件来伪造「冲突已解决」；关闭订单点名要的那一层（例如客户点名全身黑丝却关掉黑丝）；把需要用户决定的审美取舍伪装成技术决定写死；不写理由就关闭。
