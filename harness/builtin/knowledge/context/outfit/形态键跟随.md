# 服装装配：衣物跟随身体形态键

写给执行 outfit 阶段的 AI；排查部分也供回归修复阶段使用。每节独立成立。

## 身体键会被驱动时，逐件核对贴身衣物的跟随机制

- **职责**：身体的某个形态键会被菜单或动画驱动（胸型轮盘、BlendTree、脚型档）时，确保贴身衣物和饰品跟着变，而不是浮起或陷进去。
- **不看图就能答的三问**：
  1. 身体上哪些键被写？（把驱动放到两端各跑一个状态，读身体网格上的值）
  2. 每件可见的贴身衣物有没有同名键？这些键在两端**跟没跟着变**？
  3. 没跟着变的件，是不是有意固定的？例如包带按大胸调好、默认体型下贴合正常——固定件要单独看图确认，不一律同步。
- **三种失效机制**，修法不同：
  - 衣物有同名键，但没人同步：同名键就是厂商预期你去同步；很多厂商预制体不自带 MA BlendshapeSync，也没有说明书。修法：每件加一个 MA BlendshapeSync，`ReferenceMesh` 指同一头像根下的身体，逐个绑定件上存在的同名键（本地名＝源名）。**装配阶段已经自动补**（`D-139` ②，`OutfitStage.SyncBodyShapeKeys`）：装完每件衣物渲染器后按下面的静态筛逐件补，补了哪些写进装配记录 `outfit.json` 的 `blendshape_sync`（**件、键、跟随的网格、为什么补**）、回执 `Assets/_Harness/Outfit/local-operation-receipt.json` 的 `blendshape_sync_added`（配方输入是 `local-operations.json`，回执在 `local-operation-receipt.json`），以及观测 `clothing.install` 的 `blendshape_sync_followed_keys` 与 notes；现有判据 `blendshape_sync_keys_exist`（`blendshape_sync_missing_keys == 0`）把补出来的绑定一并验，参照键或本地键缺一个就阻断。
  - 有 BlendshapeSync，但参照键在当前素体版本上不存在：静默空转，改指实例上的参照键。装配补的绑定不会落进这一类：参照网格是**写着这个键的那块素体网格**，两端键都查过才绑。
  - 衣物本来就没有这个键：给衣物补帧。
- **自动补的边界**：件上已有的 BlendshapeSync 绑定、Shape Changer、动画曲线任意一条算「已有驱动」，不重复补（同一渲染器只加一个 MA BlendshapeSync，多条绑定写在里面）；身体那侧只有「可能不为 0」的键才补——被任何已装件的 MA Shape Changer `Set` 写、被厂商动画曲线里非零的键写、或素体网格上默认权重就不为 0。只被 `Delete` 写、恒为 0、没人写的键不补。只读结构，不认资产名/目录习惯/层名/骨骼名：唯一使用的同名关系就是厂商本来就与身体共用的那个形态键名，素体身份仍按方案 `body_prefab`（`AuditBodyPick`）。
- **生效必须在构建后读回**：MA 的 BlendshapeSync pass 排在 Reactive Components（应用 Shape Changer）之后，所以 Shape Changer 的 `Set` 先生效、同步随后读到身体的值；装配产物里组件存在不等于生效。构建后要读件上该键的**实际值等于身体的值**才算数（A 上是 `regression_key_follow_pre`/`regression_key_follow` 的 `key_follow_value_delta_max` 与 `key_follow_geometry_p95_mm`）。
- **剩下三类仍然没有通道**：改指参照键、给衣物补帧、以及件上**没有**这个键的情况都要改产物，而 outfit 层每次由 Runtime 按方案重建，回归阶段改了也会在上游重跑时丢掉。这类候选仍按静态筛写明哪套、哪件、哪些键，交人；两端读数由 Runtime 在回归阶段给出（同名键值差）。
- **多个头像根**：工程里有多个头像根（例如普通版与面捕版）时，每个根各做一遍。
- **取舍**：开襟外套不挡胸、里面的件已同步时不必再管——驱动拉满时渲图，肤色穿出像素为 0 就不动；别人调好的固定值件不动，除非拉满时看得出问题。
- **静态筛查规则**：衣物与身体键名求交集 × 身体上被写的键 × 衣物上没有写者 → 候选清单。装配阶段自动按这条式子补（口径见上）；人工作业时先按它列候选再动手。
- **验证**：修后在驱动 0／默认／1 三档读回，衣物键值与身体逐值相同；拉满时渲图无整片穿出。默认体型下常常几乎看不出问题，所以必须拉到两端验。
- **升级给人**：固定件与跟随件的取舍拿不准时，给出两端渲图请用户确认。

## 厂商 BlendshapeSync 的参照键在当前素体版本上不存在：实例上改指，不改厂商预制件

- **症状**：装上服装后，衣服的胸、腰类形态键停在厂商默认值（常见 100），和身体对不上，衣服离身或穿模；MA 不报任何错误。
- **机制**：`ModularAvatarBlendshapeSync` 某条 binding 引用的参照键（`Blendshape`）在当前素体版本的参照网格上找不到——例如素体更新后键名多了后缀。组件存在，但同步静默空转。
- **检查**：逐条列出每个 BlendshapeSync binding：参照网格上是否存在该参照键（`refMeshHasKey`），衣物本地网格上是否存在目标键。任一不存在即为空转，必须阻断，不能放行。
- **修法**（人工作业时）：在**实例**上把参照键改指素体上的对应键（名字最接近、同一部位），不改厂商预制件。
- **本流程里改不了**：实例改动会被重建覆盖，`blendshape_sync_missing_keys` 每次重试都阻断。写明哪套、哪条 binding、参照网格上有哪些候选键，交人（换预制件、换素体版本或改方案）。
- **禁止**：直接把衣物键手设为 0 或某个固定值——那样身体体型一变，衣服就不跟了。
- **验证**：反向验证——把身体键推到 100，衣服键应跟到 100；推回 0 也跟回。
- **升级给人**：素体上找不到同一部位的对应键，或有多个候选键无法判断时，列出候选交用户确认。

## 衣物缺身体的某个键：在 Unity 里给原网格副本加帧

- **触发**：身体某个键会被驱动，而某件贴身衣物或饰品**没有这个键**，于是身体一变它就浮起或陷进去（例如乳贴类件在缩胸时外浮数毫米）。
- **首选做法**（编辑模式，场景里真实的骨骼下）：
  1. 身体该键取 0、取 100 各 `BakeMesh` 一次，得到世界空间位移场；
  2. 衣物 `BakeMesh` 一次；每个衣物顶点取身体最近 4 个顶点的位移做反距离加权，得到世界位移；
  3. 用衣物的蒙皮矩阵 `Σ wᵢ·(worldToLocal·boneᵢ.localToWorld·bindposeᵢ)` 的逆，把世界位移换回网格空间；
  4. `Instantiate(原网格)`，`AddBlendShapeFrame(键名, 100, 位移, null, null)`，存成独立的 `.asset`；渲染器只换 `sharedMesh`（骨骼、材质不动，**不 Apply 到厂商预制件**），再加 MA BlendshapeSync 绑定身体同名键。
- **好处**：基础几何、骨骼权重、bindpose 与原件逐位相同，不存在导出空间问题。
- **为什么不先走 Blender**：Blender 里往返核对为 0，不说明导回 Unity 后正确——导出的网格空间与 bindpose 可能与厂商原 FBX 不同（出现过顶点差到米级、bindpose 差 1.27、位移被缩小 100 倍），而渲染器用的仍是场景里原来的骨骼，结果蒙皮偏了约 71 mm。
- **可查问句**：换上新网格后，身体键为 0 时衣物 `BakeMesh` 的世界坐标和原网格逐顶点差多少？必须 ≈0，否则别往下做。真要在 Blender 里做（比如要雕细节），验收一律在 Unity 里按这条比，不认 Blender 内部的往返数字。
- **升级给人**：补哪些键、补到什么程度属于造型决定时（例如是否给贴身件补「大胸」一侧的键），先交用户拍板。

## 补帧的验收：三档量距与零档逐值相同

- **量法**：编辑模式，身体与衣物都用 `BakeMesh`，量衣物到身体的最近距离分位数（p50 等）。
- **判据**：新衣物在身体键 0／默认／100 三档下，都应与「0 档原件」同一量级；0 档新旧逐值相同。例：某乳贴补帧后 p50 为 1.33 → 1.28 → 1.13 mm，而原件在 38 档（该工程的默认值）为 5.74 mm、100 档为 14.48 mm。
- **Play 里**：只读回键值（衣物键跟着身体走），不要在 Play 里换网格做对照——构建后骨骼数组可能被重排，量到的是垃圾值。
- **跨工具核对**：Unity 的形态键索引不含 Basis，比 Blender 的 shape_keys 索引小 1——按名字对，不按索引。服装自带骨架导入后骨骼改名或合并时，按骨骼名兜底匹配。
- **产出**：三档量距表、新网格资产路径、绑定的同步键清单。
