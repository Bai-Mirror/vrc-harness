# 服装装配：部件理解（是什么、何时可见、多显眼）

写给执行 outfit 阶段的 AI；菜单阶段也会引用其中的结论。每节独立成立。

## 部件理解先于菜单与收缩键定稿

- **硬门**：菜单与收缩键不得在部件理解（三轴、分组、冲突检查）补全之前定稿。装配本身不因缺部件理解而停工：可以先挂上并确认渲染，再补部件理解，最后定收缩键与菜单。
- **顺序**：探测组件 → 判兼容 → 挂上并确认渲染 → 取部件图与清单 → 三轴与冲突检查 → 收缩键 → 菜单。
- **取图不改场景**：取图过程只读场景，取图前后层级（可比层级哈希）一致。
- **做不到时**：渲图工具不可用时，先用现成渲图与厂商 clip 填「是什么」「厂商自带开关」两项，视觉权重写「未定」，菜单建议标「待部件理解补全」。本流程的 outfit、menu 执行方都没有渲图与视觉复核工具，一律按这一条办；菜单阶段没有等人的闸门，照默认动作出一份 `design.json`，未定项写进说明。
- **产品层与工程层分开记**：部件是什么、厂商分组、可见条件、权重候选、彩蛋素材属于这件商品本身，可跨工程复用；档位号、参数名、优先级链、全组合验收与本工程用户的拍板属于本工程。用户在某个工程拍的口径可作为下一个工程的默认，但可以被推翻。
- **部件清单应包含**：渲染器路径、网格、三角数、材质与主贴图、默认 activeSelf／enabled 与父链、主导骨前 5 及其计算口径、形态键、厂商开关引用；套装级：厂商菜单树、参数、颜色变体的材质差异。清单条数应等于该套的渲染器数（含骨架内 MeshFilter 静态件）。
- **不许照抄弱证据**：网格不可读时，主导骨会退化为「骨骼到包围盒距离」口径，由它推出的「相关身体部位」不许照抄；覆盖部位按「在身上」渲图写，敏感件按几何写。
- **厂商开关引用要过滤**：清单里的开关引用若混有本工程生成的曲线或菜单项，只保留厂商目录下的那部分作为厂商事实。

## 部件取证的图种：仅部件、在身上、整套有／无

| 图种 | 内容 | 用途 |
|---|---|---|
| 仅部件 | 身体也关，只留该部件 | 看形状、材质感；判断是不是敏感件 |
| 在身上（正、侧、背） | 只开该部件＋素体身体，别的全关 | 看贴／穿在哪、盖住哪段身体 |
| 整套有／无 | 整套按厂商默认开关，有／去掉该部件，同机位；按部件取景与全身取景各一；部件在背面时补背面 | 判可见条件、它给整套贡献了什么 |
| 厂商展示图 | 商品页图片，以及包内 `preview`、`sample`、`商品画像` 等目录 | 判是不是卖点、在哪些造型里露出 |
| 商品说明与标签 | 商品页描述与标签 | 厂商点名了哪些部件、风格标签、是否说明了隐藏身体的方式 |

- **整套有／无不能单独判权重**：被外层盖住的件，有／无两张几乎一样。小件、被盖住的件，权重看厂商展示图与特写。
- **图上印的字只该是数值**（三角数、色值）：模型读数字准、自己量不准；商品名、渲染器路径、材质名这类身份信息不该印在图上，已经印了就在送审前涂掉。
- **输出目录不分素体的工具**：给另一个素体重拍会覆盖原图，重拍前先看目标目录是否为空。

## 每个部件填三轴：是什么、可见条件、视觉权重

- **职责**：装一套衣服时，先弄清每个部件是什么、什么时候看得见、在套装里多显眼，再定菜单与冲突处理。三格都要填；填不出就写「未定＋缺什么证据」，不许空着，也不许用名字补。
- **是什么**（证据从强到弱；本流程没有渲图工具，从②起取证）：①盲标渲图（仅部件、在身上）；②厂商 clip 里谁和它同开同关（`m_IsActive` 路径，只认厂商目录下的 clip；厂商没有开关机制时写「无＋查过哪里」）；③蒙皮主导骨（口径必须是「蒙皮逐顶点」）、形态键、本件独有的材质名；④厂商展示图、商品说明与标签；⑤物体名、同套两件以上共用的材质名、按「骨骼到包围盒距离」得出的主导骨。只有第⑤类证据时不能下结论。
- **可见条件**：常露／外层脱了才露（写明被哪件盖住）／只在特定姿势或视角露。依据：默认造型渲图；「整套有／无」的差异像素（先涂掉图上的叠印文字再算）；坐、蹲等姿势渲图。不能拿包围盒，也不能拿「它是内衣所以被盖住」来判。
- **视觉权重**：卖点／点缀／基础层。不能拿面积或像素量判（小件也能是卖点），也不能拿可见条件判（被盖住的件也能是卖点）。
- **分类与粒度是两件事**：分类回答「它在穿着层次里是什么」，不直接决定开关粒度；粒度由视觉权重定。
- **产出**：部件表，每件含三轴取值与各自证据；未定项写缺什么证据。
- **升级给人**：视觉权重的最终定级、默认值、彩蛋采用与否由用户拍板；AI 只给候选与理由。

## 视觉权重的定级（候选判据）

以下判据尚未跨工程校准，按候选使用，结论标「候选」。

- **先填套装级两行**：「风格」与「风格标签」（标签取商品页的标签）；部件权重必须引用这两行。标签里有 セクシー、ランジェリー 这类词的套装，贴身件不许默认「基础层」，要逐件重评。
- **套装级比较**：把厂商展示图与各部件「整套有」的图放在一起问：哪几件是画面焦点？按显眼程度排序，各在几张展示图里看得见？逐件单看比不出「哪个更显眼」。
- **定级**：
  - 卖点＝被商品说明或标签点名，且至少在一张展示图里是焦点；或比较轮排前 3，且在半数以上展示图里看得见。
  - 点缀＝看得见，但排名靠后，也没被点名。
  - 基础层＝展示图里看不见。
  - 焦点＝构图主要在展示该部件（特写、居中或占大比例）；全身图里只是穿着出现，不算焦点。
- **校准锚**：用户定过级的件是校准锚。判据算不出用户定的级，是判据错了——改判据，不改用户定的级。
- **口径补丁**（候选）：①商品是素体本身、服装随素体附带时，只拿专门展示这套服装的那几张图比；②「基础层＝看不见」对被裁到画外但常穿的件落不下去，可改为「焦点 0 次且可见少于半数」；③厂商图只有平铺商品图（无人物）时不排焦点，权重栏标「展示图不合格」，只靠商品说明与用户拍板。
- **没有像素阈值**：差异像素只量得出「看不看得见」，量不出「是不是卖点」。没有展示图时写「未定」，并把「并组／单独」两案并列交用户，不自己挑。

## 名字只当线索：认部件的五查

物体名、材质名、开关名都会误导：「skirt」可能是背心裙外层，「Ring」可能是头顶光环，「厚底」鞋可能是低帮，开关参数为 `true` 可能表示隐藏。认一个部件时按下面五查：

1. **先盲标，后对名**：先看不带名字的渲图写「看到什么」，再给名字对照；两者不一致写进「名字线索」栏——不一致本身就是发现。
2. **读厂商 clip**：它和谁同开同关；参数极性（`true` 是显示还是隐藏）。
3. **看厂商菜单怎么分**：厂商单独开关、或放进私密子菜单的件，不并掉。
4. **看厂商展示图和商品说明**：是不是主图卖点、在哪些造型里露出、说明里点没点名。
5. **自查问句**：「把上衣脱光只穿鞋，这东西该在吗？」

- **禁止**：只凭名字把部件归类、并组或写进收缩键归属。
- **注意材质名**：整套共用图集的材质槽名（例如项圈与内裤共用 `corset`、`briefs` 槽）不能说明两件有关系；本件独有的材质名才算中等证据。

## 视觉模型与几何数据的分工

| 问题 | 交给谁 | 原因 |
|---|---|---|
| 图上是什么、贴／穿在哪、什么材质感 | 视觉模型盲标，另一个模型或独立会话复核 | 「有没有／是不是／哪个更 X」适合视觉模型 |
| 显不显眼、是不是展示图主角 | 套装级比较＋商品说明与标签 | 逐件看图比不出「哪个更显眼」 |
| 盖住哪段身体、被不被外层遮住、与邻件距离、有几件、齐不齐 | 几何与数据：主导骨、差异像素、逐顶点距离 | 视觉模型数数、判对齐会确定性失败（出现过 23 数成 24、6 px 错位判成「完全对齐」） |
| 厂商把它和谁分一组、参数极性 | 读厂商目录下的 clip 与菜单资产 | 事实以厂商资产为准 |
| 最终视觉权重、彩蛋、默认值、菜单文案 | 用户拍板，AI 出候选 | 属于审美与偏好 |

- **本流程里**：执行方没有视觉模型与渲图工具。表里交给视觉模型的问题写「未定＋缺图」；「几何与数据」「厂商资产」两行照做（读 YAML、贴图 `.meta`、厂商 clip），照片由 Runtime 在回归阶段出。
- **分歧处理**：两个视觉判读不一致时交用户看图，不自己裁；但属于「几何与数据」一行的（遮没遮住、有没有、什么颜色），先用像素、材质、几何裁，裁得了就写明数据，不必交用户。
- **纹样与印花先查源贴图**：蕾丝还是豹纹、有没有印花这类问题，先顺着材质 `_MainTex` 的 guid 找到贴图 `.meta` 与原图，并检查材质 `_Color` 有没有把它染深。读两个文本文件、看一张图，比多跑几轮模型便宜；贴图找不到（程序化纹理、多层混合）再退到放大渲图＋模型。触发时刻：模型对花纹的说法互相冲突，或与材质名对不上。
- **视觉结论要复核**：「是什么」「可见条件」「视觉权重」都是视觉结论，写进部件表或据此编菜单之前，交独立的视觉复核；送审的是「本方的结论」，不是「工具正不正常」。

## 送给视觉模型的图：去掉身份文字，成对图用同一遮罩

- **为什么**：拍照工具常在图上叠印商品名、渲染器路径、材质名，文件名也带部件名。模型看到这些就会照名字答，正是要防的「望词生义」。
- **做法**：
  1. 做匿名副本：涂黑叠字区，按匿名编号改名（如 `P05_v1.png`）；编号对照表只留在本地，不写进送审文本。
  2. 送审文本里不出现网格名、材质名、商品名；只问「这是什么？贴／穿在身上哪里？和谁连着？在整套里显不显眼？」
  3. 出口判据：把本套全部网格名、材质名拼成一个正则，检索送审文本与输入图路径清单，结果为 0。
  4. 涂完必看：把全部匿名图顶部约 200 px 拼成接触印样看一遍，遮罩带下不许有残字——出口判据只检索文本，查不到图里的残字。
- **遮罩带的坑**：叠字框高度随字数变，整条横带都要涂黑。叠字两到三行时框高约 83～105 px；量出 < 80 说明没量准，改用固定 110 px；量出 > 160 就停下人工看。量框底的参考点若落在人物身上会量错，可改用已知框高，或用两处明暗差找框底。有／无成对的两张图要用同一条遮罩带（取两张量得的较大值）。
- **差异像素**：不涂黑直接相减，会把「有」「无」两个叠印字算进去（768² 的图上每对恰好多出约 418 px）。另一套图曾用 ≤ 253 px 判「看不见」、482 与 686 px 看图定，但没有记录画幅与阈值，不能直接比较。换了画幅要重新标定；标定之前，差异像素只作旁证，不单独据此下「看不见」。
- **没有图像输入时**：执笔模型看不了图，就用程序重建叠字区，断言字底低于遮罩带；或另开一个能看图的会话只检查印样。

## 视觉判读的分批与送审写法

- **分批**：每个部件单独一个会话，每次不超过 8 张；套装级比较单独一个会话。一套服装常有 54～72 张部件图、20 多张展示图，一次全塞进去容易超时，也容易读漏。
- **核验读到**：以工具对每张图的逐张读取核验为准，被拒读的图不算读到；只看会话日志里「有没有调用读图」会漏。
- **分段时**：每一段都要包含「仅部件」图，否则后段只能靠整身图猜（出现过同一顶帽子两段结论不一致）。
- **成对图**：有／无成对图的编号与送审文本的口径要做一致性断言（出现过写反、整批作废重跑）。
- **送审图也要匿名**：送去复核的图同样用涂黑副本和中性文件名，题面不写商品名——叠印的材质名会漏进判定理由，题面里的商品名会被模型当成颜色或材质线索。
- **写明有意设计**：服装自带头饰、内衣＋丝袜造型等有意设计要写明，并附厂商展示图；不写的话，模型会把相邻突出物都算进声明的类别（蝴蝶结、发夹被认成「第二套耳朵」）。
- **问法**：问「这是什么／在哪／哪个更显眼」，不问「有没有两个 X」。盲标与对名分两轮派，两轮对不上要记下来。
- **图种与抬头**：优先送「仅部件」图或同机位拼图；含人物的整套图常被拒答，缩成单句论断、换仅部件图通常能过，还不过就记「撞墙未判」，不反复重试。三联图、仅部件单图、厂商平铺商品图各配各的题面抬头与输出结构，不共用（套错抬头会整批判错）。
- **敏感件**：按几何与「仅部件」图判断是否为覆盖胸部、下身的贴身小片，不按名字判；主导骨含 Breast 或 Hips 只在口径是「蒙皮逐顶点」时可信。模型拒答时退到几何数据与仅部件图，并记下哪几张被拒。

## 部件描述逐项过：别漏小而显眼的金属件

- **现象**：视觉模型写部件描述时，常漏掉小而显眼的金属件——例如球棒棒头两道带刺金属箍与分色、腰带上的一排银色圆铆钉，盲标与对名两轮都没写，抽查时才被指出。
- **写描述时逐项过**：主色／分色 → 材质（皮、布、金属、透明）→ 金属件（扣、环、链、铆钉、刺、吊牌）→ 图案／印花 → 形状关键词。
- **为什么重要**：金属件高光抢眼，对观感权重影响大；缺了会把「点缀」误判成「基础层」。
- **抽查**：每套至少抽 1 个部件，把描述原文与「仅部件」「在身上」两张图交独立视觉复核，问「有没有遗漏明显特征」；补上的内容注明来自抽查。

## 冲突检查单（部件层）：逐件逐条过

每个部件逐条过下表，结论写「C0N：结论＋证据」，不适用写「C0N：不适用＋原因」。编号固定，工程层条目（C01、C04、C05、C12、C15）在菜单阶段处理。

| ID | 问句 | 做法 |
|---|---|---|
| C02 | 位置几乎重合的两件，是装饰还是变体？ | 辅助信号：同一源 FBX＋同骨列表＋只差材质、三角数完全相同、成对后缀——只是信号。定论看逐顶点最近距离中位数：< 2 mm 为变体、互斥；> 5 mm 为装饰、同开。网格不可读时留到工程里量，或读 FBX 量。别用包围盒判（「体积比 0.76＋中心距 1 cm」曾把 GRF 的装饰耳 `Rose_Ears` 判成变体） |
| C03 | 厂商的开关一次写了哪几件？ | 扫 clip 的 `m_IsActive` 路径拿全清单；只收厂商目录下的曲线与厂商菜单项（例：`Toggle-NekomimiHB` 一次写发箍＋两颗铃铛） |
| C06 | 它盖住身体哪一段？ | 按可见件判，不按开关参数（例：兜帽戴起要摘掉耳机与所有兽耳；脚甲随鞋袜隐藏、露趾例外） |
| C07 | 外层开着时，内层或头发要让位吗？ | 用厂商给的让位键，写者挂在外层件上（例：外套开时衬衫 `Parker_on`、头发 `Outer_on`；马甲开时衬衫的脊背让位键） |
| C08 | 收缩键挂在谁身上？ | 挂在真正盖住那一段的件上，不挂整套根 |
| C09 | 鞋袜的脚型？ | 姿态键按鞋跟高度选；删除类只给完全包住的；露趾、露脚背不用删除类 |
| C10 | 这套自带内衣／袜／鞋，会不会和素体那份叠在一起？ | 整套层点名关掉素体那份；判据用差异像素（涂掉叠字后算） |
| C11 | 贴身件跟不跟体型？ | 有同名键就加 BlendshapeSync；缺键就补帧 |
| C13 | 它长在别的件上吗？ | 本档不写 true、其余档写 false（例：兜帽上的垂耳） |
| C14 | 是厂商备选件或二选一吗？ | 备选件（如大胸版外套 `outer_breast_big_open`）不进开关组；二选一（如 `Skirt`↔`Skirt_Jacket`）用「开时不写、关时两件都写 false」 |

- **本流程里**：C11 的「加 BlendshapeSync」已由装配阶段自动做（件上有同名键、没有任何驱动、身体那侧可能不为 0 时补，见 `形态键跟随.md`）；其余做法（外层挂让位写者、挂收缩键、补帧）没有通道：产物只含厂商预制件自带的配置加这一步自动结果，查出其余问题写明交人。C10 由方案的 `hide_body_parts` 决定：构建时永久剔除素体那份，不能按套切换；需要按套切换的交给菜单设计，菜单做不到时交人。
- 身体与脚部形态键（C08、C09、C11）的旧做法未经完整验证：部件层只写「候选键＋候选宿主＋待验」，不写成结论；定论在工程里按几何证据做。

## 覆盖乳头区域的贴身小件：额外三条（候选）

- **对象按条件认，不看名字**：主导骨含 Breast（口径须为「蒙皮逐顶点」，否则看「仅部件」图）、「仅部件」图是小片，不是完整文胸。
- **加进遮胸门**：工程若用「可见件显式列表」（遮胸门的 `when` 列表）决定乳头类形态键，这件要加进列表；没加时，它可见而乳头键仍按裸态写 100。另有用 Delete 删 `Nipple_ON` 区域的旧做法，Delete 不可回退，需用户确认。
- **查胸型键**：身体会被驱动的胸型键它有没有；缺了就补帧＋同步。两头都可能出事：缺「小胸」一侧的键时，身体缩胸后小件外浮数毫米；缺「大胸」一侧的键时，胸型推到大的一侧会陷进皮肤。几何实测优先于渲图印象（出现过渲图记成「陷入」、几何实测为「外浮」的更正）。
