# 服装装配阶段：先建部件图鉴

写给执行服装装配与菜单编排的 AI。依据是两个工程里 16 套外购服装的建档与编排（一个 Kaguya 工程 4 套、一个 Milfy 工程 12 套）。

## 装配前先查部件图鉴，缺则建档

- **职责**：在把一套服装装上头像、编进菜单之前，先弄清它由哪些部件组成、每件长什么样、在身上哪里、厂商给了哪些开关与形态键——凭物体名猜部件会编错菜单（例：厂商叫 `Belt` 的其实是腿饰；形制看错会把分腿短裤当成裙子）。
- **权威输入**：厂商素材包（预制体、FBX、厂商动画与菜单）、厂商展示图、逐渲染器的实拍图（单件在身上三视图、只有该部件、整套有 / 无该部件对比，数值印在图上）、部件清单数据（每个渲染器的网格、材质、主导骨、默认激活、形态键、被哪些厂商开关引用）。
- **本流程里**：plan、outfit、menu 执行方都没有渲图与视觉复核工具，图鉴里要实拍图与视觉盲标的部分做不了：用厂商素材包（预制体与 clip 的 YAML、厂商菜单）、厂商展示图和部件清单数据建一份文本版，形制与视觉权重写「未决＋缺图」，照片由 Runtime 在回归阶段出。这三个阶段都没有等人的闸门：图鉴不全不停工，菜单按默认动作出 `design.json`，未决项写进说明。
- **决策边界**：可以建档、给出菜单建议；部件的审美取舍（默认开关、是否单独成项）按需求方口径，拿不准的列「未决」。
- **禁止事项**：只凭物体名或材质名下结论；写没测量过的精确数值（例：精确夹角）或推断用途；把「可见图内未见」写成绝对否定；两轮标注冲突时只留一说。
- **产出要求**：每套一本图鉴：套装级（风格、部件总表、菜单树草图、厂商机制、彩蛋）＋逐部件详情（位置、材质与颜色、视觉权重、与其他件的冲突、菜单建议、未决）；部件节数应等于清单里的渲染器数，图片数与清单一致。
- **怎么验证**（有视觉工具的流程）：先让视觉模型在不知道部件名的情况下盲标，再对名核对、做套装比较；每条视觉结论由第二个模型证伪，冲突照录两说并标「争议」；抽查若干部件回到原图局部裁切复核。
- **什么时候升级给人**：部件形制或可见条件有争议、影响菜单编排时；敏感部件（近裸、乳贴类）的默认开关与是否外送标注，按需求方口径决定。
