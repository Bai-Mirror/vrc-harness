# 服装装配：厂商变体与第二份实例

写给执行 outfit 阶段（接线部分也供 menu 阶段）的 AI。适用于厂商给了同一套服装的多个变体预制体、方案要求在运行时切换的情况。每节独立成立。

## 同一套的两个变体预制体：先量差在哪，再决定实现方式

- **职责**：厂商给了同一套服装的两个变体预制体（兜帽戴/放、带帽/不带帽、长袖/短袖……），而方案要求在运行时按档位切换时，先确定两份的真实差异，按代价最低的方式实现。
- **权威输入**：两份预制体逐**完整路径**的 dump：`(网格名, 顶点数, activeSelf, 组件列表, 局部变换)`，只打印有差别的行。用脚本比，不看图。
- **判据与实现**（代价从低到高）：

| 差在 | 判据 | 实现 |
|---|---|---|
| 只是激活状态 | 逐路径比 `activeSelf` | 一个开关就够，不需要第二份 |
| 材质 | 比 `sharedMaterials` | 动画换材质数组 |
| 网格（各有各的件） | 比路径集合 | 两组件各自开关 |
| 骨架姿态 | 逐骨比局部变换 | 必须上第二份实例 |

- **禁止**：按名字比。服装里 `Jacket`、`Tops` 这类名字常常既是网格名又是 PhysBone 节点名，按叶子名比会串。
- **产出**：差异表与选定的实现方式。
- **本流程里**：变体只能作为方案 `outfits` 里的独立一套，Runtime 各装一份完整实例（MergeAnimator、Parameters、MenuInstaller 都在，不解包、不删组件），执行方事后精简会被重建覆盖。只差激活状态或网格的，交给菜单阶段的部件开关；需要「容器＋第二份精简实例」或材质切换的，本流程做不到，在方案 `notes` 写明并交人。
- **升级给人**：差异跨了多类（例如既差网格又差骨架），且方案没写清要切换的是哪一部分时，报告差异表请用户确认。
- **例**：某兜帽外套的两个变体共 441 个物体，网格集合完全一致，唯一的差别在骨架：兜帽骨链 23 根里 5 根局部变换不同（兜帽根旋转由约 0.13° 变为 286.07°，即往后倒约 74°；两侧耳朵与缎带根也重摆过），父骨还从 `Head` 换成了挂在 `Chest` 下的一根新骨。

## 变体差在骨架姿态时：只差父骨可用约束，子骨姿态不同就上第二份实例

- **职责**：对骨架差异类变体，判断能否用约束复现。
- **判据**：
  - 只差父骨（挂在哪根骨下）→ 加一个可切换父级的约束即可，不必复制；
  - 子骨的局部姿态也不同 → 作者摆过姿势，约束复现不出来，只能上第二份实例。
- **后果**：硬拿约束去凑，静态站姿看着对，一动就不对（尤其头部转动时）。
- **取舍**：第二份实例只需复制蒙在差异骨链上的少数网格，代价通常很小，不值得为省这点去赌约束。
- **验证**：在动作中（转头、低头）对比两种档位下部件的位置，而不是只看静态站姿。
- **证据**：单一工程（候选）。

## 第二份实例只复制蒙在差异骨链上的网格（按逐顶点权重）

- **职责**：确定第二份实例里需要保留哪些网格，避免整套复制。
- **判据**：
  1. 取变体差异所在的骨链（例：兜帽根及其全部子骨）；
  2. 对每个 SkinnedMeshRenderer，找出 `bones[]` 里落在该骨链上的索引；
  3. 数**权重 > 0** 命中这些索引的顶点数，> 0 的网格才需要复制。
- **禁止**：只看 `bones[]` 里有没有这些骨——挂在骨数组里但权重全为 0 的不算。
- **例**：23 个网格里只有 3 个需要复制：外套本体（14165 顶点中 796 个蒙在兜帽骨上，5.6%）、兜帽耳朵（6862 顶点，100%）、耳朵别针（3056 顶点，100%）。其余 20 个（裙、上衣、袜、鞋、背包……）共用原件那份。代价从「整套 ×2」降到约 +3 个蒙皮网格、约 24k 顶点、24 根骨。
- **产出**：需复制的网格清单，以及每个网格的命中顶点数与占比。
- **注意**：新增的骨链会增加骨骼数，也可能增加动骨组件数，记入性能预算。

## 第二份实例的结构与组件取舍：容器门控

- **结构**：

```
_Outfit/<容器>          ← 整套轮盘只管这一层的显隐
  ├ <原件>              ← 全部网格 + 全部 MA 组件
  └ <变体>              ← 只留受影响的网格 + 骨架
```

- **为什么用容器**：容器关着时，子物体是什么状态都无所谓。这样部位开关、饰品轮盘可以自由写子物体，不会在别的整套档位下把这套衣服放出来。
- **变体那份的组件取舍**：

| 组件 | 处理 | 原因 |
|---|---|---|
| MA MergeArmature | 留 | 新骨链要靠它并进头像骨架 |
| MA MergeAnimator | 删 | 否则厂商的层会合并两遍 |
| MA Parameters | 删 | 否则厂商参数会声明两遍 |
| MA MenuInstaller／MenuItem | 删 | 否则厂商菜单装两遍 |
| 不受影响的网格 | 删 | 白占性能预算 |

- **操作前提**：要删预制体实例的子物体，必须先 `UnpackPrefabInstance`，否则报「Cannot delete GameObject that is part of a Prefab instance」。
- **禁止**：变体那份保留 MergeAnimator、Parameters、MenuInstaller 中的任何一个。

## 第二份实例的接线：部位开关写全路径，轮盘只负责压掉一份

- **机制**：厂商参数（例如 LopEarMine 的 `LEM/Jacket`）只写原件的路径，管不到第二份实例。
- **部位开关**：自己写变体那份的显隐，而且必须用**完整路径**——容器下两份里有同名网格，按叶子名解析会二义。
- **饰品轮盘（或整套档位）**：只负责在两份之间压掉一份——本档不写原件（让厂商开关与部位开关决定），其余档写 false；变体那份反过来。两份都由部位开关放、由轮盘压，**没有任何一层去 force-on**。这样「关了上衣还挂着兜帽」不可能发生。
- **所有权**：同一属性只保留一个权威写入者；显隐由几个开关组合决定时，新开一层当唯一所有者。写入分工写进菜单设计，便于菜单阶段核对。
- **验证**：对所有档位 × 部位开关组合读回两份的显隐：任何组合下两份不同时可见；关掉上衣时兜帽随之消失。

## 第二份实例装完的回读判据：以原件为对照逐路径比

| 判据 | 期望 |
|---|---|
| 容器下的子物体数 | == 2 |
| 变体那份的网格 | == 按逐顶点权重算出来的那几个 |
| 变体那份的 MergeArmature | == 1 |
| 变体那份的 MergeAnimator／Parameters／MenuInstaller | == 0 |
| 与原件逐完整路径比局部变换 | 只在变体骨链上不同，其余 0 处不同 |
| 只在变体里存在的路径数 | == 新增骨链的节点数（例：新父骨 1 根 + 兜帽骨 23 根 = 24） |
| 所有权审计 | 变体那份的网格至少被一层写过「显示」 |

- **禁止用绝对阈值查骨架**：例如「最长骨段 < 500 mm」——骨架根下 `Hips` 的局部坐标就是胯高（某素体约 760 mm），每次都会误报。用原件当**对照样本**逐路径比才对。
- **升级给人**：只在变体里的路径数与新增骨链不符，或原件与变体在骨链以外还有差异时，停下报告，不要继续接线。
