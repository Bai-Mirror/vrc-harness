# 捏脸 30b：烘焙、闭眼补偿、越界检查、导出与覆盖

## 当前正式工具合同（T1e）

新任务使用 `native-fbx/1` 和 `face-compensation/0.2 / regional-additive / 1`。原生读取受管副本的原 FBX；`S = Σ(设计权重 × 原键 delta)`，新 Basis 为 `B+S`。左右眼、每个实际表情独立计算 `c=max(0,1−原表情露出率/原睁眼露出率)`，再写入 `新 delta = 旧 delta − Σ(c×W×S)`。生产入口不再使用 IDW 非线性端点目标；历史读取及其反例测试不代表现行路线。

输入统一为一组原形态键数值与显式范围（原上下限、新上下限）；T1c 复用此接口。所有设计键保留名称、顺序和原 delta，烘焙后数值归零；工具至少把范围扩展到 `−已应用权重`，可撤回基础中的该设计分量。嘴型默认只检查，实际 SDK 口型键不补偿，不将「delta 未变」写成口型视觉通过。

眼部配置由真实 SDK 眼骨绑定、源蒙皮的三轴转动观测、归一混合权重及材质内连通面岛共同建立（`sdk-eye-motion-weighted-island/2`）。三轴各转动 0.12 rad 后精确还原源姿势/键值；位移超过 0.1 µm 数值噪声且直接眼骨影响达到该眼峰值一半的顶点进入候选岛，优先强影响岛，再按投影面积与前后位置选择。0.4 眼骨与头骨混合可以成立，不要求眼骨权重大于 0.5；弱污染、无实际运动或缺测不能形成通过。独立 Blender 进程重读源并重建选面/UV/运动身份，冻结面与 UV 身份；当前原生 FBX 坐标配置是 Z 向上、−Y 向前。选择最大投影面积的眼部面岛（近同面积取前方者），保留相同材质的全部非眼球遮挡面，不用随姿态收缩的取样半径。26/34 mm 是本版本眼周投影平面 smoothstep 满强度/归零半径，和观测范围不同。原版睁眼须明显可见、SDK blink 须显著遮挡；控制失败或没有眼部来源时报告缺测。这个配置不覆盖所有材质/透明纹理结构；三角形面心按源投影面积加权，尚未读取纹理 alpha，不能把它称为精确复刻历史 UV 遮罩。

Unity 独立检测以实际导入面的位置及 UV 角身份回绑上述冻结源面，不重新按 Unity 眼骨权重选面。非原生兼容路径也实测三轴骨运动并按相对混合权重选择，禁止固定 0.5 权重门槛。实际 FBX 导入可合并或重映射蒙皮影响，新选的眼骨面岛可能只是被挡住的小装饰面。当前原生坐标转换必须通过全部源取样面/遮挡面覆盖核对，位置或 UV 缺失仍报技术性失败；睁眼与源 blink 控制仍必需。私有任务的补充纹理 alpha 采样须单列方法、采样点数与局限，不冒充已接入 Runtime 的全材质算法。

源姿势是否只是导入数值噪声，按全部键归零后的实际蒙皮与静止骨姿势位移判断，冻结噪声线为 1 µm；不以无单位矩阵元素差直接阻断。探针精确还原位移/旋转/缩放原通道，不把观测写入源文件。超过噪声线的真实源姿势仍要求受支持配方。顶点与表情状态偏差按冻结的 0.1 mm 级判断；非脸部、UV/骨权重、骨层级和实际蒙皮姿势仍单独检查。独立 FBX 回读先确认源与输出的索引面连接完全一致；一致时逐原索引核对几何与全部键 delta，避免容差内近重合点的最近距离匹配人为置换连接。重排路线仍独立核对面绕序、角 UV、材质及权重，不以接近的位置替代拓扑。近退化边在源长度 ≤0.1 mm 时改查新长度是否越过这一绝对尺度；一般边仍查比值。保留新增自交、面积塌陷、翻转、二面角/褶皱检查，不在失败后临时提高阈值。检查半权重与完整状态；眼球露出率记录 0、0.5、0.6–0.9、1.0。历史 0.65%→0.75% 仅作为全权重新露出增加 0.10 个百分点的参考标记，不能代替用户接受或推成所有素材的视觉定律。

Blender 桥接每个真实子进程默认 3600 秒，按实际 contract 的 blenderTimeoutSec 及有界 AVH_BLENDER_TIMEOUT_SEC 配置执行；821 键的完整独立回读可能超过旧 900 秒。该上限不覆盖任务总预算或取消/截止约束，不删质量状态、不以超时当验证通过。执行合同变化生成新冻结修订，失败/部分产物保留，不能改写已有回读或凭新时限复用未验证候选。

原生 FBX 的 basis 坐标与默认形态通道是两种事实：只有烘焙的目标设计键归零，保留键和非目标网格原默认权重须保留到 FBX DeformPercent，不能因统一归零改变身体/衣物的继承外观。独立 Blender 回读分别核查目标及所有非目标默认值，Unity同原路径比较仍严格验证默认值及实际蒙皮，不忽略失败。

持续执行约定：质量发现不是停止条件。新冻结配方的 `quality.findingPolicy=user-visual-review` 收集全部读数；每项与原版同表情同权重比较，估算毫米穿插/近景像素并提供同机位原版/新版特写。明显可见的可针对性修一次后复查；看不出或拿不准的标为需用户看图判断并继续。只有数据错、引用断、导入失败、工具崩溃等技术性失败计入同类三次停止。Runtime 必须确认补偿公式与质量/眼球露出观测完整，质量是否无发现和最终外观接受分别记录；不能把继续推进写成质量通过。历史严格配方及其失败证据不改写。

Unity 在受管副本用同一路径、同 `.meta` 和导入器比较完整新旧 FBX，再恢复基线供前后预览。待接受 Prefab 直接引用候选完整 FBX，重新挂原材质并核对骨骼和形态键索引，停止生成独立 `FaceMesh.asset`。候选导入须复制实际源的完整元数据并保留候选自己的 GUID；`EditorJsonUtility.FromJsonOverwrite` 会漏掉形态键法线和材料映射等配置，不能据此宣称导入器一致。既有输出的候选元数据保持冻结。FBX/blend 按版本保留。交付要求是覆盖交付副本中原 FBX 路径、保留原 `.meta` 并再次核验；用户明确授权时可在外观接受前完成隔离交付副本覆盖，仍须标明等待用户接受。未执行这项交付事务时必须如实报告，不能把临时比较或候选引用说成正式覆盖已完成。

实际正侧面对比和半闭/全闭眼特写每态先 BakeMesh 再渲染，并绑定真实不同的蒙皮坐标摘要，防止 Camera.Render 使用旧缓存。Runtime 核对图片、状态、来源与产物版本；选择 Gate 与最终接受 Gate 分开。诊断固定选择不是用户选择，数值/图片生成不是接受；流程停在等待用户看图接受。

以下保留历史制作经验，适用范围与当时工具/工程相关。历史删除设计键、统一 0–100、按接触距离判闭眼或要求另一模型评审的条款不覆盖上述现行决定；没有当前工具消费者的自动动画重写、透明 UV 遮罩或接受后交付步骤不能宣称已完成。

## 30b 前两步：留三个还原点，再做精确重建式烘焙

**职责**：定稿后，把「用户直接拉到某个值的几十个形态键」烘进基础网格，而不破坏表情。

**权威输入**：用户明确说「定稿了」的键值表；厂商原版 FBX；捏完未烤的 blend。

**决策边界**：
- 还原点三个：覆盖前的 FBX、捏完未烤的 blend、烤了未补偿的 blend（例如 `*_unity_original.fbx`、`*_sculpted_prebake.blend`、`*_baked.blend`）。FBX 是二进制，通常不进版本库，出事只能靠还原点。捏脸的各阶段 blend（捏完未烤 → 烘焙前备份 → 已烤 → 已烤已补偿，外加法线修正版）从开工起就放进一个固定的捏脸工作目录，别等到 30b 才建。
- 要烤的键：非零、且不是为了看效果自己设的键（例如为看清脸临时设的 `pupil_off`）。自己设的键烤进去后，再被动画推到 100，会双重应用。
- 烘焙用精确重建，不用累加：先取出每条键相对旧 Basis 的原始位移，改 Basis 并同步 `mesh.vertices`，再用新 Basis 加原始位移重建其余每条键。

**禁止**：缺任何一个还原点就继续；用 `+=` 式累加烘焙。

**产出**：三个还原点；烘焙清单 `{键名: 烘焙权重0-100}`。

**验证**：三个文件都存在且非空；`Basis` 与 `mesh.vertices` 的最大差 == 0 mm（两者在 Blender 里分开存储，必须一致）；烘焙清单条目数 == 清点出的键数。

**升级给人**：定稿状态不明确（没有明确的「定稿了」）；还原点无法建立。

## 30b 闭眼补偿：按眼分开，做加性抵消

**职责**：捏脸改了眼睛大小或上睑位置后，让闭眼、眨眼、笑眼这类闭合表情仍然闭得拢。

**权威输入**：厂商原始网格上的各闭合类键；捏脸位移 S；眼部卡片与皮肤的面。

**决策边界**：
- 为什么要补：烘焙把 S 并进 Basis，各键的 delta 原样保留，闭合键的位移是按原始眼睑位置设计的，于是捏大的那份被原样带进闭合状态。Blender 形状键存绝对坐标、Unity BlendShape 存相对 delta：在 Unity 侧改基础网格对多数表情天然有效，需要补偿的是闭合类表情。
- 算法是加性抵消：`新delta = 旧delta − c·W·S`；在 Blender 里（形状键存绝对坐标）写成 `新键 = 新Basis + 原始位移 − c × 掩膜 × S`。W 是以眼心为中心的 smoothstep 掩膜，把补偿限制在眼周；c 是这条键在这只眼上的闭合程度：全闭键接近 1，半闭键居中；算出 c ≤ 0 的（睁大类）直接跳过、不做补偿，不能按负系数去加位移。
- 按眼分：上睑顶点按 x 正负分两簇，各求质心当眼心，各建一个掩膜，各算各的 c。单眼键（如 `blink_L`、`ウィンク`）的闭合度是两眼平均后的稀释值，用对称掩膜会把没闭那只眼的捏脸一起撤销。
- c 的判据用眼球露出率（从视线方向做射线遮挡，看卡片有多少没被皮肤挡住），不用眼睑收敛度（上睑下移量＋下睑上移量）。一种换算是 `c = 1 − 该键露出率 / 睁眼露出率`。闭合键的筛选与 c 都在厂商原始网格上算：在已经烘坏的网格上算，坏得最狠的键反而会被判成「不是闭眼键」。

**禁止**：乘性放大闭合位移（它在跟一个恒定的撑开量拔河，治不了）；用对称掩膜处理单眼键。

**产出**：每个（键, 眼）组合的 c 与掩膜参数；补偿前后的露出率表。

**验证**：单眼键作用后，没闭那只眼的捏脸量不变；补偿后各闭合键的露出率回到厂商水平。露出率判据本身先用已知答案验一遍：睁眼应明显高，厂商全闭键应接近 0，半闭键（ジト目）应显著大于 0。

**升级给人**：补偿后仍闭不拢或出现锯齿、尖刺，渲图交用户与第二个模型确认。

掩膜尺寸按素体标定：规程标定值为以眼心 30 mm 内满强度、50 mm 处衰减到 0（来自一个 Kaguya 工程），换素体要按眼周尺寸重标，确认它不会撤销眉、嘴的捏脸。

## 30b 全量形态键检查：烘焙量加动画峰值不超过 100

**职责**：确认烘焙后没有表情因叠加超出 0–100 而破形，也没有静息表情重复写被烤的键。

**权威输入**：烘焙清单；全工程 `.anim` 的 `blendShape.*` 曲线；Modular Avatar ShapeChanger 的 Set 值；场景与 prefab 的 `m_BlendShapeWeights`。

**决策边界**：
- 每条 `blendShape.X` 取曲线峰值，加上该键的烘焙量，>100 即外推越界。修法：写入值改成 `100 − 烘焙量`；多关键帧的曲线整条按比例缩，不能只改峰值那一帧。
- 静息表情里写了被烤的键，是双重叠加，要清掉。
- 形态键外推过（t 超出 0–1）就必须重跑本步，不能沿用上一轮的扫描结果：烘焙量变大，越界条数会跟着变多。
- 扫描源不止 `.anim`：ShapeChanger 的 Set 值（有的工程用 Set 写脸部数值，也有脚部写 Set 60 的；面板数值不等于实际效果）、场景与 prefab 的 `m_BlendShapeWeights`（烘焙默认值也存在这里，有的工程带非零默认权重）。
- 超出 0–100 的值会被 `legacyClampBlendShapeWeights` 钳制（Play 口径为 1，与 VRChat 客户端一致）。

**禁止**：为了「做点什么」去改动画。结果可能就是零越界；查过、确认没有，本身就是产出。

**产出**：三张表：越界表（每条已回算或为空）、「静息表情写了被烤的键」表、「被烤但无动画驱动」表（安全）。

**验证**：越界条数 == 0，或每条都已回算；静息表情写被烤键的条数 == 0。

**升级给人**：必须把外推值留在交付件里时，列出越界条数，在 Play 口径下渲图，请用户逐条判定。

## 30b 导出：先还原材质槽，再导出并做二进制自检

**职责**：把补偿后的网格导出成可以覆盖厂商原版的 FBX。

**权威输入**：厂商原版 FBX；Blender 里的厂商材质数据块（通常还在 `bpy.data.materials` 里）。

**决策边界**：
- 导出前把材质槽还原成厂商原样。为看清脸临时换上的自建材质一旦跟着导出，Unity 侧的材质数组就会错位（典型症状：脸用上了眼睛的材质）。把槽指回原材质数据块即可。
- Blender FBX 导出必改的参数：`apply_scale_options='FBX_SCALE_UNITS'`（默认的 `FBX_SCALE_NONE` 是头号杀手）、`mesh_smooth_type='OFF'`；`add_leaf_bones` 在 operator 里默认为 True，必须显式关掉。
- 不要在 Blender 里复制或重命名材质（会多出 `.001` 材质）。

**禁止**：计数对不上还去覆盖；拿文件大小当哨兵（出现过成功品 26.3 MB、原版 16.5 MB，两者都正常）。

**产出**：导出的 FBX；与厂商原版对照的二进制自检表。

**验证**：与原版逐项相等：厂商材质名的出现次数；`UnitScaleFactor`、`LimbNode`、`PoseNode`、`BlendShapeChannel` 的计数（槽被并掉时 `Model` 节点数也会少一个）；顶点数与顶点索引顺序（面捕 fork 路径不校验这一项）。静态校验拦不住绑定姿势损坏，覆盖后还要在 Unity 里用实际着色器渲染确认。

**升级给人**：计数不一致而原因不明时，不覆盖，报告差异。

## 30b 覆盖 FBX：只换本体，然后重挂材质、扫空槽、服装拆装

**职责**：用自检通过的 FBX 覆盖工程里的原版，并恢复被覆盖动作破坏的场景状态。

**权威输入**：二进制自检通过的 FBX；工程里所有「挂材质」的步骤或工具；已装配的服装清单。

**决策边界**：
- 只覆盖 `.fbx` 本体，Unity 侧 `.meta` 一个字段都不改。
- 换 FBX 会重置场景里渲染器的 `sharedMaterials`：覆盖后必须重跑所有挂材质的步骤，再扫一遍空材质槽。
- 服装已经装配过的：每套服装拆装一次（`ArmatureLockMode.BaseToMerge` 会让外套错位）。

**禁止**：跳过重挂材质。跳过的典型症状是脸用上了眼睛的材质，或外套物体在场景里但完全不渲染。

**产出**：覆盖记录；空材质槽扫描报告；每套服装单独打开时的渲染。

**验证**：空材质槽数 == 0；每套服装单独打开时都能看见（不是「物体在但不渲染」）；在 Unity 里用实际着色器渲染，确认绑定姿势正常。

**升级给人**：覆盖后出现解释不了的错位、不渲染或姿势异常时，回到覆盖前的还原点并报告。

## 捏脸验收：四条数值判据，再用对比渲图证伪

**职责**：给捏脸阶段收工一个可复核的数值卡口。

**权威输入**：厂商原版与捏脸后的顶点坐标；全工程动画；导出前后的 FBX。

**决策边界**：四条数值判据：
- 接缝裂开：原本相距 <0.3 mm 的跨卡片顶点对，变换后的距离不应显著变大。
- 深度变化：`|Δy|` 最大值 < 2 mm，超了就可能穿出脸皮。
- 表情外推：每条曲线峰值＋烘焙量 ≤ 100。
- 导出后二进制自检通过（材质名计数、结构计数、顶点数与索引顺序）。
前两条主要针对叠层卡片的几何变换；阈值以流程阈值表为准。

**禁止**：只报数值就宣布「彻底消除」。数值指标归零不等于肉眼无残留，两者都要报。

**产出**：四项读数表；同机位、同光、同材质的对比渲图（原版／修前／修后）。

**验证**：四项达标；对比渲图交第二个模型做反向评审，它指出的阈值以下的残留要列进报告。

**升级给人**：数值达标但评审或渲图看出残留；数值与观感冲突。

## 受管 Blender 的耗时与中断恢复
