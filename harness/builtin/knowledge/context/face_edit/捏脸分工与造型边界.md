# 捏脸阶段：分工、造型手段与自建键例外

## 捏脸分三段：AI 出候选、人定形、AI 全自动落地

**职责**：把参考图与需求落成当前工具合同支持的 2～5 组可比较形态键候选；选择由 Runtime 的真实用户决定保存，随后由受管工具烘焙、补偿、导出并独立校验。正式入口为 `face-request/0.2`，后端路线为 `native-fbx/1`（Blender 原生编辑原 FBX、同 Unity 导入器/.meta 对比）。数值与范围扩展可由 AI 或后续手动入口提供，角色保护和接受 Gate 相同；不直接推顶点。

**权威输入**：参考图解读里写成「部位＋方向＋幅度」的捏脸方向；形态键枚举清单（脸型类）与实测键义；用户（代表委托方）逐轮的决定与原话。

**决策边界**：
- 30a-1 出候选（AI）：根据实际枚举给出 2～5 组原有形态键权重；Runtime 验证并渲染每组实际效果，未通过的组合不能伪造预览。
- 30a-2 定形（人）：从候选里选，或给修改意见。Runtime 保存经授权用户入口取得的决定；生产 AI 不能代写选择或批准。用户明确委托的代理演练须另标，不能冒充真人审美验收。
- 30b 落地（受管工具）：留还原点、烘焙、表情补偿、全量形态键检查、导出与回导、重挂材质。独立技术读数与最终真实正/侧视效果接受分别验收，数字通过不能替代外观接受。
- 30a 期间 AI 能做：调键组候选并渲图；留还原点、做导出前后的二进制自检；量化验收（接缝裂开、深度变化、表情外推）；把变换写成只改系数就能重跑的脚本；烘焙后的全工程表情外推扫描与修正；并行准备配色候选、菜单结构、补缺素材。

**禁止**：伪造用户取舍或技术通过；绕开当前任务写权修改场景；仅凭意外场景状态猜测是人修改。Runtime 持有写入所有权，漂移先核对真实来源和版本。

**产出**：候选组（每组的键名＋数值＋渲图）；定稿键值表；30b 的还原点、导出 FBX 与各步读数。

**验证**：候选组数与渲图齐全，每组都能对上键名与数值；30b 每一步的后置判据都有本次运行的读数。

**升级给人**：真实外观取舍、新增目标/费用/素材授权及覆盖已接受成果。键能力不足先记录实测缺口并提出可验证的技术修订；内部工具修复不应要求用户修工程或配置。

## 捏脸造型手段：只调厂商形态键的数值

**职责**：用厂商脸部形态键的数值组出造型。厂商已经把「哪个方向的形变是合理的」编码进这些键里，借它的手，不自己发明形变。

**权威输入**：形态键枚举清单；每条键实测的方向与强度。

**决策边界**：
- 允许：调厂商脸部形态键的数值，可以外推到 0–1 之外（先放宽 slider 再赋值，赋完回读）。
- 允许：烘焙后对不平滑的顶点做局部修复。
- 扩展方法：厂商键里确实没有所需方向时，闭式变换可作为技术候选；当前 `face-request/0.2` 不提供自建键接口，须先补工具、权限、独立验证和相应消费者，不能把用户同意当作接口已实现。
- 叠层卡片五官的几何缩放需独立验证层间关系和表情；当前阶段不能以此绕过形态键输入合同。

**禁止**：AI 自行决定顶点位移去「雕」脸；把网格整体重置回原样（会连捏脸一起丢）。

**产出**：当前可执行候选写明实际形态键名＋数值；当前工具无法表达的要求保留为明确缺口和修订依据，不静默删除用户目标，不作为已可执行候选。

**验证**：方案逐条核对键名在枚举清单里；烘焙前后比对，非厂商键带来的位移为 0（自建键例外须有记录）。

**升级给人**：某个方向只有动网格才做得到时，报告厂商键的实测天花板，请用户决定是否启用例外。

历史依据：一次直接顶点造型实验失败，只支持该输入、模型和方法组合未通过，不能外推成所有 AI 永久不能处理三维几何。当前形态键路线由实际工具与验证能力约束；扩展能力须用新的正反例和真实效果证明。

## 捏脸自建键：只允许闭式变换，要有实测证据和用户点头

**职责**：在厂商键做不到的方向上，用写得出公式的变换建一条自定义形态键。

**权威输入**：厂商相关键能力的实测证据（天花板多少、为什么不够）；用户的明确同意。

**决策边界**：禁止的是「凭手感雕顶点」，不是「按闭式公式算位移」。四条规矩：
1. 必须是闭式变换（旋转、缩放、平移＋掩膜），写得出公式，不是逐顶点手调。
2. 叠层卡片式眼部要选对轴：绕深度轴的面内旋转，位移的深度分量恒为 0，层间距不变；绕其他任何轴旋转都会搅乱叠序，直接 z-fighting。
3. 位移按「建键那一刻的混合形状」算：`新键位移 = R(当前混合) − 当前混合`。这样其余键全开时，结果正好是当前脸的精确变换。用户改完别的键后要重建一次。
4. 验收两条：受影响顶点有多少落在掩膜满强度区内、有多少落在区外；再用不受采样漂移影响的判据验证功能没坏，例如闭眼时每个上睑顶点到最近下睑顶点的距离，比较建键前后几档。

**禁止**：用会跟着变形漂移的判据验收。例如按未变形位置定的采样列去量闭合，顶点一旦转出采样列，就会报出一个假的「闭合变差」。

**产出**：变换公式、掩膜定义、两条验收的读数、用户同意的记录。

**验证**：掩膜外受影响的顶点为 0；功能判据在建键前后的变化在可接受范围内，并与用户确认。

**升级给人**：造型取舍和授权范围变化由用户决定；已授权范围内技术扩展先在隔离副本验证。以上是历史方法说明，不授予当前生产任务创建自定义键的能力。

标定示例（单一案例，一个 Milfy 工程）：厂商键压外眼角上扬的天花板是 −13%，自建旋转键做到 −36%；睑缘顶点 89.5% 落在满强度区内、区外 0 个；闭眼距离在旋转 0／1／2 三档为 8.699／8.667／8.907 mm（±2.4%）。
