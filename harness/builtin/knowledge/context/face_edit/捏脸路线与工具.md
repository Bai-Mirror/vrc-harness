# 捏脸：路线、工具分流与排期

## 捏脸路线：默认在 Blender 里烘焙并做闭眼补偿

**职责**：决定定稿的捏脸在哪里、用什么方式固化进网格。

**权威输入**：定稿键值表（是否改了眼睛大小或上睑位置）；方案是否包含面部追踪。

**决策边界**：
- 当前后端路线为 `native-fbx/1`：Blender 原生打开原 FBX 的受管副本，用选定形态键组合烘焙、按左右眼逐表情加性抵消并导出完整 FBX（口型默认只检查）；Unity 用同一路径、同 `.meta`、同导入器作新旧实测对比。工具接通与具体头像端到端验收分别记录，不能互相代替。
- 只设置 SkinnedMeshRenderer 权重或用 AAO FreezeBlendShape 烘进基础网格，不能单独证明表情保留。Freeze 改变基础后，既有表情 delta 可能不再闭合或平滑；是否需要以及如何补偿须依据本次实际源、键组合及表情读数。不要把历史眼睛放大案例的结果预先判给所有输入。
- 「改了 FBX 就装不了面捕」不成立（Triturbo 面捕）：sha256 失配是厂商为「用户改过 FBX」设计的 fork 流程入口，不是阻断。但 fork 只能走 `current_in_use`，它不查顶点数、也不查 hash。

**禁止**：为了保住 FBX 的哈希而放弃闭眼补偿。

**产出**：路线结论与理由（写明是否动了眼睛大小、是否要装面捕）。

**验证**：核对两个真实 Unity 导入的骨骼、UV、骨权重、全部键名/顺序/帧、非脸部和引用/SDK 错误。先验证索引对应，必要时按位置、UV、子网格和骨权重建立一一对应；保留三角重剖差异并检查实际三角质量。bindpose 按绑定姿势和测试姿势的蒙皮后顶点偏差判断，不用矩阵元素门槛。历史 Unity 数据重建 Blender 源或 Python 模拟导入政策的证据仍可读，新任务不能进入该路线。

原生眼面回绑的 UV 精度按该材质实际加载贴图的最大边长取 1/4 texel；没有贴图证据时仍用 1e-6。位置仍用 1 µm。先按完整源多边形的绕序、边界与内部边建立三角组合，再求互不重叠、覆盖完整的面对应；次近完整对应必须超过最近距离的两倍加噪声，否则失败。原版导入可省去精确零长度源边上的零面积三角，只作拓扑记账、不生成采样射线；非零边不能据此省去。该源导入对应容差不放宽新旧导出 UV 等同性检查，也不代表全 shader 遮挡或视觉接受。

独立输出回读同时核对非目标组件的序列化事实。粒子 Gradient 的颜色/Alpha 及各键时间、插值模式、色彩空间均须保持；不能因头像带粒子组件就跳过该属性或放宽非目标修改检查。
原版组件以无穷浮点值表示不设上限时，序列化快照保留正负无穷标记并逐项比较；不能变成有限值、换符号或丢成 null。NaN 仍拒绝，几何/权重/设计输入的有限数值要求不变。

**升级给人**：用户对交付形式或外观有真实取舍时，说明本次已测影响；未测的闭眼结果标为未知。内部坐标、导入或补偿故障由 Harness 诊断修复，不要求用户操作 Blender。

标定示例（单一案例，一个 Milfy 工程）：Freeze 后在 Blender 量闭眼状态下上下睑缘最近距离，从素体默认的 7.37 mm 升到 8.76 mm（+18.8%）。

## 捏脸问题分流：几何量用 Blender 读顶点位移，观感才渲图评审

**职责**：给捏脸里遇到的每个问题选对工具，跟着问题走，不跟着已有脚手架走。

**权威输入**：问题本身的性质。

**决策边界**：
- 几何量（这条键把哪些顶点往哪挪、挪多少、眼尾相对眼头是抬是垂）：使用冻结的观察/目录工具读取实际顶点与形态帧；当前工具在受管 Blender 无界面进程中执行。耗时以当前输入实测，不保证秒级。
- 烘焙、表情补偿、FBX 导出与二进制自检：调用当前已接通的受管 Blender 工具，生产 AI 不能自行启动任意脚本代替。
- 观感（这组数值好不好看、几组之间的差别看不看得出）：实际 Unity 同条件渲图，按任务政策独立评审或用户取舍；多模型不是每个任务的前置要求。
- 多数问题两者兼有：先用几何量把能定死的定死，剩下的才送评审；拿不准时先算几何量（便宜），再据此设计渲图验证（贵）。

**禁止**：用渲图去回答一个几何量问题；拿几何估算代替「成品上看不看得出」。

**产出**：每个结论标明来自读数还是渲图评审。

**验证**：几何结论附位移读数；观感结论附同机位渲图与评审结果。

**升级给人**：读数与渲图结论冲突且解释不了时，保留当前失败证据并报告，不能通过换键缩小已选目标来凑通过。

取舍：判错的代价不对称。把几何量当观感只是慢（出现过十几次批量渲图、二十多分钟，只换来一份看图描述，而无界面脚本几秒就给出位移量与方向）；把观感当几何量，会产出一个自洽但没人看得出区别的方案，一直走到委托方面前才暴露。

## 捏脸排在服装装配之前：换 FBX 会作废装配与配色

**职责**：排期时处理捏脸与服装装配、配色之间的依赖。

**权威输入**：方案里是否含捏脸；捏脸是否会重导并覆盖 FBX。

**决策边界**：正式流程先定脸型再装配与配色，避免相关源变化使下游证据失效。历史覆盖 FBX 曾造成材质数组重置或特定装配机制错位；本次依赖应按实际源、工具和产物摘要判断，不把所有局部脸型修改都泛化成全工程必重做。当前流程的受影响再验仍由 Runtime 安排。

**禁止**：绕过 Runtime 的写入所有权或在原件/已接受成果上试改；候选与预览只能在受管副本按冻结工具生成。

**产出**：排期说明：哪些已做的装配与配色需要在覆盖 FBX 后重做。

**验证**：装配与配色所用的 FBX 是捏脸定稿后的版本；否则明确记录需要重做的项。

**升级给人**：用户要求在捏脸定形前先做装配或配色时，说明返工代价。
