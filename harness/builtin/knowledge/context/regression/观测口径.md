# 回归的观测口径

## 数据先行：看图只做定点复核

- 先让工具把显隐、每个形态键的值、谁在写它读成数据，由数据挑出候选；渲图只对候选做定点复核。视觉查验开销最大，也最不可靠。
- **定点渲图**：先隐藏遮挡物（头发、包、外层衣服；渲图工具的 `hide_renderers` / `only_renderers`），拼 2×2 小图先扫一眼取景，再做比较。本流程的回归执行方没有渲图工具，照片由 Runtime 出（Run 目录的 `photos/`），你按这里的口径判读；要补的机位写进报告。
- **对照要有正对照**：比较「修前/修后」「键 0/100」时，先只渲身体做一组已知会有差异的对照，差异像素要明显；正对照看不出差异时，整组比较无效。
- **不要在 Play 里换网格做对照**：Play 中 AAO 会合并、改名网格并重排骨骼；要换网格就在编辑模式做。
- **视觉结论交独立评审**：题目写成「这是结论，请推翻」，或把候选图与对照图混排做盲测（答案表只留在本地，图片按顺序编号，不在文件名里泄露答案）。评审只挑出取景问题时，重渲后再送，不能当作通过。自己看图容易把「假修复」当成修好了。
- 有多个独立评审时，只采信 ≥2 个评审独立指认的问题；只有一个评审指认的，逐条写复核结论。

## 定妆照穿衣命中：点名 N 件、开了 N 件

- 定妆照与换装照必须点名交付穿搭，并断言「点名 N 件、开了 N 件」：生成记录或规格文件里读得到开的服装档位，点名数与实际开着的件数相等，差一件即失败。历史上多个工程的定妆照「穿衣」命中为 0——图都在，却证明不了交付件长什么样。
- **实现上的三个坑**：「穿衣命中」逐件比 `activeSelf == 动画求值结果`，不比 `activeInHierarchy`——动画写的就是 `activeSelf`，父级整套关着时子件 `activeSelf` 仍为 1、`activeInHierarchy` 却是 0，比后者会假失败；悬空绑定（场景里找不到该物体）单独计数、不计入分母。反过来，问题是「画面里看不看得见」时才用 `activeInHierarchy && Renderer.enabled && 材质非空`。另外，场景里的第二个头像根会被一起拍进去；插件的摆位靶标是真渲染器，会出现在图里。
- **拍交付状态，不拍编辑器裸状态**：编辑器里不驱动动画层时，各套衣服的帽子、猫耳、配饰全都亮着，那是不会交付的状态。先用真动画数据把参数设到目标档位再拍；判断「这一档该显示什么」的依据是动画层，不是场景里当前的勾选。
- 照片目录可能混着多次运行的产物：交付前核对照片对应的服装档位就是交付穿搭，对不上先补拍；补不了就明确写「图不代表交付穿搭」，不要用旧图顶上。

## 越界形态键按 Play 口径判

- 判断外推或越界形态键（权重超出 0–100）的实际效果，一律在 Play 口径下渲图，即 `legacyClampBlendShapeWeights` = 1（钳制开启）。编辑模式的预览可能显示客户端看不到的外推形状，拿编辑预览当客户端结论是错的。
- 编辑模式下钳制位是否开启并不确定（装了 AAO 的工程里观察到为 0），进出 Play 还可能改写 `ProjectSettings.asset` 里的这个字段：进 Play 前后各读一次，被改了就还原并记录（Play 由 Runtime 在构建副本里跑；执行方写不了 `ProjectSettings/`，发现被改写时写明即可）。
- **数据侧检查**：用越界权重探针（`range`）或扫描动画曲线，列出峰值超过 100 的曲线，逐条回算或写明理由。
- 捏脸烤进网格后，表情可能外推越界：改过的表情要查，判定为「安全」的表情也要复检。

## 零命中先证明测到了东西

- 检查结果为 0（穿出面积 0、违规 0、未压缩贴图 0）时，先回答「这个 0 背后测了几个对象、几对配对」。数不出来就按不可判定处理，不写进结论。**永远通过的假判据比没有判据更危险**，它会让人以为查过了。
- **已知的几种假 0**：穿出探针的配对只认请求级的 `poke_covers`（或用 `poke_decl` 指向声明文件），写进 `poke.covers` 会被静默忽略，于是 `pairs` 为空、`patch_count: 0`、`total_patch_area_cm2: 0`，看着和通过一模一样；按 `.meta` 的 `textureFormat` 数 RGBA32，结果恒为 0（绝大多数是 -1 Automatic）；菜单导出报 `done` 但 SDK 字段缺失时可能写出空结果；复核脚本的跨块正则捞到相邻曲线块的值，把早已正确的文件判成「没改干净」。
- **覆盖声明要按实物给**：声明里的每一根骨头都要问「这件衣服真的盖得住吗」。给多了会凭空造出缺陷（给低帮鞋声明覆盖小腿，「小腿露在鞋外」被算成穿出）；给少了会漏测（脚踝没进声明就查不到脚踝）。
- **校验脚本本身也要被校验**：新判据先在已知有缺陷的样本上跑出命中，再拿它判未知样本。

## 读回通过不等于上传后可用

- Play 或构建后的读回通过，不代表上传后能用：GestureManager 能直接驱动 FX 里的任何参数，参数没进构建后的表达参数表也照样「读回正确」。凡新增参数，都要在构建后描述器的 `expressionParameters` 里确认名字存在，或看菜单导出的 `menu_params_undeclared` 为 0。
- **多根工程**（例如面捕安装时克隆出的根）：生成层写的参数引用与数值都要同步到每一个根；只写原件根，克隆根会停在旧的参数表上。
- 用 GestureManager 驱动状态时核对驱动方式：`driver=gesture_manager` 才能验证 VRC 参数驱动器的联动，`driver=animator` 验证不了。
- **构建后口径也不等于游戏端**：远端量化、同步位、镜子与第一人称、其他玩家的视角，都只能在上传后验证，列为客户端待测项，不能写成通过。
- **平台覆盖类改动编辑器验不出来**（贴图预算、压缩格式、网格压缩、着色器剥离、Android/Quest 平台覆盖）：编辑器渲染永远走默认档。要么真机验，要么在报告里明确标「本项未经真机验证」。
