# 回归阶段：菜单串档与状态缺失的定位

## 菜单串档的定位：跨档残留与「切回来又变了」

**职责**：Runtime 报告某个物体在不该出现的衣装档或部件状态下仍然出现，或者状态随切换历史而变时，找出是哪个写者造成的，并在源工程的派生层里修。

**本流程的修复落点**：只改 `Assets/_Harness/Menu/design.json`（`objects`、`disable_when_on`、`vendor_clips`），Harness 会重跑菜单阶段再重建回归；不要直接改 `RouteBClips/`、`OutfitRouteB.controller` 或 `Menu/Avatar.prefab`，它们会被整层重建。下面各条里「在 clip 或自己的层里显式写」「改成 Copy」这类修法本流程做不到：BoneProxy 逃逸应由装配工具记进 `outfit.json` 的 `bone_proxy_visuals`（没记进去就写明交人），不要把它写进部件控件；厂商层自己的 Driver 冲突、空 clip 加 WD=ON 这类问题，design.json 表达不了时写明交人。

**权威输入**：上一轮 Verdict 与状态观测；构建后控制器的层、状态、曲线与 Driver；烘焙体里物体的最终父链；各层 clip 的路径集合。

**按症状查**：
1. 某件在所有衣装档都显示（穿别的衣服还戴着）：先查它或它的祖先是否带 MA BoneProxy。构建期它会被搬到目标骨下，换装 clip 只关服装根关不掉它。判据两条：烘焙体里它的最终父链上已没有原服装根；合并后控制器里没有曲线控制它或它新父链上的 `m_IsActive`。两条都成立即为逃逸。修法是在每一个换装 clip 里显式写它的 `m_IsActive`（写源路径即可，NDMF 会重映射），本套写 1、其余每套写 0。只看自己或子孙带渲染器的件，锚点、动骨挂点逃逸了也无视觉影响。
2. 被收起的件旁边还浮着小零件：厂商开关一次写多个物体，只收了主件。读厂商 clip 拿全清单。
3. 结构相同的两个开关一个正常一个不正常：厂商层用空 clip＋WD=ON，还原的是构建时场景里的物体状态。核对相关物体的 `activeSelf`，在排在厂商层之后的自己的层里显式写。
4. 「切一圈再切回来，关掉的东西自己回来了」、时有时无：多个层用 Driver `Set` 同一参数，结果取决于进入状态的先后。读构建后控制器，数写该参数的层数，超过 1 就改成 Copy（可带范围转换）或收归一处。
5. 轮盘扩档后，关掉某功能时另一件也跟着不能用：压制条件还是「参数 > 某阈值」，把后面所有档一起压了。改成区间；一条转移里的条件只能是「与」，离开区间要两条转移。

**禁止**：删除或合并失败的衣装状态来规避检查；用手动 `SetActive` 摆状态证明修好（BoneProxy 逃逸这类缺陷恰恰在于「关根关不掉它」，手摆复现不了）。

**产出**：根因（哪个写者、哪一层、哪条路径）与修改位置。

**验证**：修完重新构建，用真动画数据摆出失败的那一格及相邻档，确认该属性只剩一个写者。本流程里重建与复验由 Runtime 在你退出后做。

**升级**：修复需要改变用户已确认的部件语义（例如某件的归属从上衣改到鞋袜）时，列出两种做法的代价交用户选。

## 菜单状态缺失的定位：没反应、死档、位置空了

**职责**：Runtime 报告某个开关或轮盘档没有效果、两档效果相同、或某个身体位置一件都不显示时，找出缺失的来源并补上。

**按症状查**（从便宜到贵）：
1. 参数在变、物体不动，且稳定复现：查排在后面的层有没有无条件写同一属性；查该层 `defaultWeight` 是否为 0 且无人用 LayerControl 抬权（补丁脚本用 `AddLayer` 追加的层默认就是 0，MA 合并只把每个被合并控制器的第 0 层强制为 1）；查 LayerControl 是否指向合并后的真实层（按层名核对）；查 clip 路径在优化后能否解析（被 AAO 删除或改名后就成了死参数）。
2. 子物体曲线写了 1 仍不显示：沿父链往上查，是否有祖先关着且没有任何层管它。
3. 两档效果完全相同（死档）：把每档 clip 归约成「路径、属性、值」集合两两比较，并 grep 该物件是否在每一档都出现。漏写曲线的档资产非空、能播、文件哈希也不同，只有这样比才查得出。差异只在贴图的外观档，用属性动画做出来必然相同，要改成换材质引用。只由 Parameter Driver 区分的档在离屏图上相同是预期，要进 Play 验。
4. 轮盘某档选不到或落错档：Motion Time 边界按「关键帧时间 ÷ clip 的 `m_StopTime`」算；循环 clip 上参数 1.0 会回绕到首档。
5. 某位置一件都不显示：冲突表里同时存在「甲压乙」和「乙压甲」。按全局优先级链只压低优先级一侧。
6. 粒子档第二次拨到就没有粒子：动画切的是物体激活，而 `playOnAwake` 只在首次激活时触发。改为物体常开、只切 `ParticleSystemRenderer.m_Enabled`（本流程的部件开关只写 `m_IsActive`，做不到，写明交人）。

**禁止**：用渲染组合矩阵回答「这一档接没接线」。「档位没接线」和「容器被别的层关掉」渲出来一模一样，照着看图得出的根因去挪容器，档位依然是死的。

**产出**：每个缺失状态的根因类别与修改位置。

**验证**：修完先做静态回读（clip 集合比较、层权重、写者计数），再重新构建、用真动画数据逐档复核。本流程里你只改 `design.json`，重建与逐档复核由 Runtime 做。改过动画层之后，之前的组合遍历结论全部作废，要重跑。

**升级**：缺失来自用户工程的其他层或卖家素材、且不在允许修改范围时，报告具体层名、路径与建议，不越权修改。

## 菜单回归的证据口径：烘焙后产物加真动画数据

**职责**：判定菜单类回归结论时，分清哪些观测能作证、哪些不能。

**权威输入**：
- 构建后（NDMF 与各插件合并、优化之后）的控制器：层名、层序号、权重、状态、转移、Driver、clip 曲线路径。「谁压得住谁」只看这里的层序号，序号大者在后、后写者胜。
- 用真动画数据摆出的状态：读合并后控制器，按参数值确定每层停在哪个状态，按层序依次应用各状态 clip 的曲线。这只在各层都是 Override、权重 1、WD=OFF 时等价于运行时；否则按实际权重与 WD 语义模拟，或进 Play。
- Play 中的运行时观测：Parameter Driver、粒子、PhysBone 等只在运行时发生的行为只能这样验。
- 静态回读：clip 的「路径、属性、值」集合比较；每条路径 `m_IsActive` 的写者计数，全工程只应有一个。

**禁止作为证据**：编辑期裸场景与编辑期截图（clip 运行时才生效，BoneProxy 编辑期不生效）；手动 `SetActive` 摆出的状态；离屏渲染里只靠 Driver 区分的档位；「参数面板上参数在变」（权重为 0 的层照常求值、照常触发 Driver，只是曲线写不出去）。

**本流程里**：构建后的控制器、真动画数据的状态与 Play 观测都由 Runtime 取，证据在 Run 目录；你不自己烘焙、不进 Play。

**决策边界**：手动烘焙会在场景里留下一个 `<名字>(Clone)`，出图与统计要排除它，否则取到的是停在烘焙那一刻的克隆体。改过动画层之后，旧的组合遍历与构建期复验结论全部作废。

**产出**：修复说明里每条结论注明证据类型与来源路径。

**验证**：同一结论至少有一条静态回读证据加一条构建后状态证据；两者冲突时以能区分假说的新观测为准。

**升级**：证据互相矛盾（例如回读显示接线正确、Play 里仍不出现）且无法补观测时，停下报告两个假说及各自的证据。
