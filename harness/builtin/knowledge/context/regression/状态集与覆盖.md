# 回归的状态集与覆盖记录

## 回归状态集：轮盘每档、部位单关、全穿全脱与体型两端

适用于 VRChat SDK3 头像的回归（优化前与优化后两轮都适用），菜单含衣装轮盘、部位开关或体型参数的工程。

- **最小状态集**：每个衣装轮盘档位 ×（该档下每个部位开关各单独关闭一次）＋ 全穿 ＋ 全脱 ＋ 胸型等体型参数的两端。只测默认态、或只测「每档全穿」，会漏掉部位开关与档位交叉处的缺陷。
- **本流程里状态集由 Runtime 固定**：T1 只取本单参数的每个取值与厂商每个布尔开关单独翻转，真序列只跑开关「关→开→关」与本单参数「切走→切回」；体型参数两端不在其中。你不发状态请求，读 `coverage.json` 与观测结果；缺的组合写进报告的未测项。
- **连续轮盘的档位口径**：第 i 档按 i/n 定义；测量取档中点 (i+0.5)/n，不取档边界值。边界值落在哪一档取决于舍入，测到的是偶然结果。
- **读法**：逐态比较「全穿」与「单关」的显隐差和形态键差，只看可见件；不可见件上的键值差不算缺陷。
- **参数名取自构建后的菜单导出**：Modular Avatar 自动生成的参数名带哈希后缀，照源工程里的名字写请求会写错。厂商子菜单有没有真的挂进实际菜单树、每个控件的实际值与可达性，也从构建后的导出读，不从预制体推断。
- **用真实动画数据把参数驱动到目标状态再读回**，不要手动 `SetActive`：手动显隐证明不了动画层会怎么写，两者经常不一致。
- **先列写者清单再读数**：每个形态键与显隐由谁写（厂商 clip、MA Shape Changer / Blendshape Sync、本工程生成层），连同封闭件清单与抓屏材质清单一起列出。「件上缺键」「写者挂错件」这两类缺陷只能靠读数对照写者清单发现。清单是快照，回归推翻的结论要回写。

## 两种复位口径都要跑：declared 判状态本身，none 判切换过程

- （本流程里状态请求由 Runtime 发出，下面的口径用来读懂它的结果。）状态请求默认 `"reset":"declared"`：每个状态前把用户可控参数复位成声明默认值（参数驱动器的目标参数不参与复位）。它能隔离状态，用来判「这个状态本身对不对」。
- 复位同时会洗掉上一步的残留，而残留正是切换类缺陷。判「从别的状态切过来对不对」要用 `"reset":"none"`：把一条真实点击顺序写成一个步骤里的多个状态，第一个状态列全量参数，其后每个状态只列变化的那一个参数，按真实点法走一遍、每步读回。
- **串档类缺陷只在真序列里出现。** 实测例：外购衣装档里把部位开关关了再开，素体自带的开衫冒出来；切到某档后素体内裤残留；默认口径下「关鞋子」读回脚部键全 0，用户按顺序点菜单却看到键还开着。
- 最小真序列集：每个部位开关至少跑一次「关 → 开」，每个轮盘至少跑一次「切走 → 切回」，比较首尾状态是否一致。**首尾不一致（串档）与「序列跑不出来」一样计入 `missing_real_sequences` 失败**；串档还逐条留在 `coverage.json` 的 `sequence_drift` 里。
- 用户报告「关掉 X 之后 Y 还留着」「切回来就不对」时，优先用 none 口径复现。
- 读回数值时逐档核对「值 < i/n？」，不要用「整体错位」一句带过；档位含义以本工程的菜单设计记录为准，不从扫描到的取值倒推。

## 按工程类型追加的必测组合（九类换装机制）

在「单开 / 全开 / 全关」这些公共项之外，按工程所用的换装机制逐类追加；一个工程可能同时属于几类。有的资料把这九类记作 T1–T9，与审查工具的 T1/T4 编号无关。

1. **独立开关、无互斥**：开着时点关闭是否回退；与身体键的 Shape Changer 同开时胸、腰是否正确。
2. **Int 多路互斥**（如 3bitInt、KZ ClothChanger）：0→N 每一档；档位之间来回切；参数不在同步表时的表现；与 `Foot_heel`/`Toe_heels` 这类脚型键同档对齐。
3. **连续轮盘**（`Cloth`/`Hair` 这类 Float）：每个整数档；两档之间的 1/4、1/2、3/4；快速来回；值不变而别的开关变化时保持稳定。
4. **插件分组换装**（ClothGroup、FastCloth、MapleCloset 等）：组内单件；组间交叉；同时选两组；插件留下的备份对象不能当交付内容。
5. **逐件 Shape Changer 压键**：逐件查脚底、脚踝、脚趾；两双鞋同开；袜＋鞋＋裙叠加；关掉一件后键是否回退。
6. **无身体适配**（身体没有 `Shrink_*`，场景里 Shape Changer 为 0）：身体本来就有哪些收缩键；多件 `Costume_*` 同穿；换鞋时的脚型。
7. **面捕与原生根并存**：确认唯一活跃根；两个根的材质与贴图是否共享；面捕键与表情动画同时驱动时的嘴与眼；超过 30 MB 的 BlendShare 产物单独核。
8. **PC 与 Quest 双头像**（两个描述器都活跃）：两根各自独立过菜单；Android 端的材质、着色器、贴图槽；Android 端动画层或 Shape Changer 是否缺失；本地 VRCQuestTools 是否真被调用。
9. **AAO/NDMF 优化成品**：改动后用批处理跑完整构建（含 NDMF 及本工程其它预处理）；优化后动画路径是否仍可解析；参数裁剪后基线与 Pico 等场景是否也生效；MergePhysBone 合并后仍能做穿模检查。

## 静照、动态姿势与取景的覆盖面

- **静照**：多套全开时的合并包围盒不超过 5×6×6 m；粒子启用后的 bounds 也要量（粒子会把包围盒撑大，静止包围盒看不出来）；活跃头像根唯一。
- **动态**：行走、转身、跳跃，蹲下、坐下，抬臂、抬腿。静态照查不出走光与甩飞；动骨（头发、裙摆、链子）的观感编辑期不模拟，只能在 Play 里观察。
- **补足视角**：正、四分之三、背、面部这默认四张不够，至少补侧面 90°（前后层次、鼻/耳/发片穿插）、低机位（脚型、鞋底、裙内、脚踝绑带）、俯视（头顶、耳尾、帽子、发旋）、手部（手指穿插、戒指/手套、腕饰）。动态至少补走路、坐下、抬腿各一帧。
- **取景前先问**：这件东西可能从哪一面露馅，那一面在不在画面里？露跟、露趾、开口件要有后视或正侧视，前侧四分之三看不出开口；环形件（戒指、腕饰）要有沿轴方向的视角；袜口、手套口这类贴合件要有接缝那一圈的特写。
- **本流程里**：Runtime 只出换装照与 Play 几何探针，不跑动态姿势，也不补机位；这些写进报告的未测项。
- 渲不出或测不了的姿势记「未覆盖」，不要用静态正对照冒充动态结论。多渲一个机位只多几秒；漏掉的那一面会一路带到交付，而中间每一次「验收通过」都会强化错误的信心。

## 覆盖记录：写明跑了什么、没跑什么

- **本流程的覆盖记录由 Runtime 写**（写在本阶段自己的构建副本根，即 `_harness_build/regression_pre/project/_regression/coverage.json` 或 `_harness_build/regression/project/_regression/coverage.json`，同时拷一份到 Run 目录），你写的会被构建副本的重镜像删掉再覆盖。它固定列出 Play 口径 T1/T4、T3 转台、感知对账、2D 混合树、PhysBone／约束／参数驱动器；若本轮没有超阈值同名键配对，或任一超阈值配对的端点烘焙/BVH 未成功，另列几何 p95 未测。体型参数两端、动态姿势、补足视角、真机与远端不在其中，要写进你的报告，交付诊断据此列未测项。
- 每轮回归结束都留覆盖记录：跑了多少个状态、几条真序列、哪些渲图、有没有菜单导出、同名键跟随与几何量距、感知机制的声明对账（`verdict.py`）；**没跑的逐项写出来**。覆盖记录（如 `coverage.json` 的 `ran` / `not_ran`）是回归结论的一部分。
- 没跑的路径上，这一轮既不能判通过，也不能判「没有缺陷」。例如测量不进 Play 时，PhysBone 不模拟，动骨观感无从判断；驱动方式不是 GestureManager（`driver=animator`）时，VRC 参数驱动器的联动验证不了。失败若落在这些路径上，结论写成「需要 Play 口径或人工复核」，不能用其它路径的通过顶替。
- 覆盖不全不是通过：开关只测了开没测关、轮盘只测了整数档没测档间值、只跑了默认态的入口冒烟，都要写成未测。默认态冒烟只证明工具能跑，不能替代全状态覆盖与真序列。
- 测量入口本身缺前提（例如没有可重载的构建产物、Play 预处理入口没有隔离）时，记 `blocked` 或「未测」，继续做不依赖它的离线准备；不要换一个不合格的入口去凑结果。
