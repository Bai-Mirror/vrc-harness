# 回归失败的分类与修复

## 本流程的回归：Runtime 测什么，修复落在哪

- **Runtime 测什么**：你退出后，Runtime 先把工程重新镜像到本阶段自己的隔离构建副本（优化前回归是 `_harness_build/regression_pre/project`，最终回归是 `_harness_build/regression/project`；副本里源工程没有的文件会被删），再依次构建、做构建后控制器的静态模拟（T1 状态扫描、真序列、同名键值差、换装照）、跑 Play 几何探针（状态集与请求参数由 Runtime 固定）。两轮回归各有自己的副本，`build_pre`／`build` 的槽位只有产出它们的阶段会写。跑了什么、没跑什么写在 `_regression/coverage.json` 的 `ran`／`not_ran`，这份覆盖记录也由 Runtime 写。本阶段没有工具：不要启动 Unity、不要自己构建、不要改构建副本，也不自己发状态请求、渲图或量几何。
- **你手上的证据**：上一轮的检查结论与 Run 目录里的 `coverage.json`、`photos/`、`fit/geo_state_*.json`。据此定位根因，改设计输入。
- **修复落点**：菜单类缺陷只改 `Assets/_Harness/Menu/design.json`（`objects`、`disable_when_on`、`vendor_clips`），不要直接改 `RouteBClips/`、`OutfitRouteB.controller` 或 `Menu/Avatar.prefab`；最终轮的优化类缺陷只改 `Assets/_Harness/Optimize/design.json`。改了这些输入，Harness 会重跑对应的上游阶段，再重建回归。
- **修不持久的**：装配层（`Outfit/`）与改色层（`Recolor/`）没有你可写的设计输入。缺收缩键、BoneProxy 逃逸（应进 `outfit.json` 的 `bone_proxy_visuals`，由装配工具生成）、碰撞体挂点这类缺陷，直接改生成物本轮也许能过，但产物指纹一变，上游阶段会重跑并整层重建，失败在下一轮重现；动了改色层还会让 `recolor_approval` 失效、要人重新批准。写明根因与建议，交人。（「衣物带着身体的同名键却没有驱动者」这一类不再属于这里：装配阶段已自动补 MA BlendshapeSync，`D-139` ②。）
- **Runtime 不测的**：`not_ran` 固定列出 Play 口径 T1/T4、T3 转台、感知对账、2D 混合树、PhysBone／约束／参数驱动器；当没有超阈值同名键配对，或任一超阈值配对无法完成端点烘焙/BVH 时，覆盖记录另列几何量距未测。体型参数两端、动态姿势、补足视角、真机与远端也没有测。这些写进报告的未测项，不算通过。

## 形态键类失败：五种实测缺陷与各自的查法

以下各类都在实际交付工程的回归复盘中出现过。先把失败归到其中一类，再决定修哪一层。

| 类 | 症状（实测例） | 怎么查 |
|---|---|---|
| 同名键没人同步 | 衣服带着身体的同名形态键却没有驱动者：体型参数拉满时胸部穿出；连体袜不跟高跟脚型 | 同名键跟随：衣服可见时与身体的值差 >5 为候选，再量几何 |
| 件上缺键 | 某件根本没有身体对应的键，如乳贴缺 `Breast_small`/`Breast_big(limit)` | 同名键跟随查不到；按状态读值，对照写者清单 |
| 写者挂错件 | 11 个收缩键挂在整套衣服上；平脚键挂在袜子上；平脚键只挂在鞋上、丝袜又不归袜子开关，脱鞋后脚趾穿出丝袜 | 按状态读值对照写者清单，并看构建后 FX 里 `MA Responsive:` 层实际驱动了什么 |
| 删除区靠别件遮 | 无脚长袜用 Shape Changer 的 Delete 删掉脚踝、靠靴子盖住，「袜开鞋关」时脚踝破洞 | 逐条读 Delete 的宿主件，确认被删区域只靠宿主自己就能盖住；逐件「单关」渲图 |
| 交付根缺组件 | 面捕根上的收缩 Shape Changer 被覆盖删除 | 写者清单里有、读值恒为 0 → 比较两个根上的组件 |

- 同名键跟随检查查不到「件上缺键」与「写者挂错件」，这两类只能靠按状态读值、对照写者清单。
- 认「身体」按蒙皮权重，不按物体名。

## 显隐与菜单类失败：六种实测缺陷与各自的查法

| 类 | 症状（实测例） | 怎么查 |
|---|---|---|
| 串档 | 外购档里部位开关关了再开，素体开衫冒出来；切到某档后素体内裤残留 | 真序列（`reset: none`）按点击顺序走 |
| 备选件同时显示 | 外套两层同时显示；长短两款手套同时显示 | 重合网格探针 `coincident` |
| 失效菜单 | 厂商子菜单所在层 weight 为 0，客户点了没反应 | 构建后菜单导出 ＋「单关」态读数零变化 |
| 一个开关管多件 | 开衫、裙、鞋挂在同一个开关上 | 写者清单 ＋ 全量状态扫描 |
| 抓屏点提前 | 换色动画引用了渲染队列 2450 的厂商材质，抓屏链的顺序被提前 | 抓屏链探针 `grab_chain` |
| 互压死锁 | 压制层互相压制，同一身体位置的所有件都被关掉 | 每个状态检查「同一身体位置至少有一件开着」 |

- 「失效菜单」只看默认态发现不了：单独关掉该开关后读数零变化，才是证据。
- 「互压死锁」是菜单压制设计的问题，回菜单阶段改设计，不在回归里绕过。

## 同名键失配：先量几何再判

- **候选**：部件盘点列出「衣服带着身体的同名键却没人驱动」的键。
- **值判定**：衣服可见时，衣服与身体同名键的值差 >5 才算失配（权重单位 0–100，阈值表 `key_follow_mismatch`）；判定工具 `key_follow_verdict.py` 读状态扫描的结果来判。
- **几何判定**：失配先量几何再判。编辑模式把身体键设到两端，`BakeMesh` 后比较衣服顶点到身体最近距离的分位数，p95 变化 <1 mm 记为无可见后果（阈值表 `key_follow_p95_mm`），这种失配不必修。
- **几何判定的实际口径**：对每个可见衣装、每个状态里值差超过 5 的同名键配对都测；保留衣物键和其它状态条件，只把身体该键实际烘焙到 0 与 100，衣物保持当前权重。每端烘焙、每端 BVH 都必须真实成功，读完恢复现场；任一配对量不出且已测读数尚不能确定违规时，`key_follow_geometry_p95_mm` 保持 null，规则得到 `no_data`。可测配对取 p95 距离变化的最坏值；值差不超过 5 时直接由规则第一项通过，不制造几何 no_data。
- **阈值的标定**：这两个阈值只记录了测量方法（编辑模式、身体键两端、`BakeMesh`、最近距离分位数），没有记录标定用的素体与插件版本。用在新素体上时，先拿一个已知会穿出的例子确认 1 mm 能把它挑出来。
- 这条检查查不到两类：件上缺键、写者挂错件。
- 修好后按状态读回数值验证，例如件与身体的胸型键在三档上逐值相同。

## 修复排序：先证据、再机制、后个案

多处失败同时出现时按下面的顺序处理。这个顺序综合自回归、优化与交付三处的做法，本身不是单独实测出的规则。

1. **先确认失败证据成立**：零值背后有没有配对、覆盖声明是否符合实物、复位口径（declared / none）是否对应要判的问题、读的是否是构建后产物。证据不成立时先修测量，不改工程。
2. **再修机制层**：参数没进构建后的参数表、层序被压、写者挂错件、根上缺组件、压制互锁。一处机制错误通常解释多个状态的失败，修一处能消掉一批。
3. **最后修个案**：某件某态的键值、显隐、覆盖区域。
4. **优化后才出现的失败**：先回退或收窄对应的优化再判，不在优化结果上叠修补。
5. **设计层的问题**（压制互锁导致某个身体位置无件可穿、菜单语义冲突）：回到菜单或装配设计上改，不在回归阶段绕过。
6. **一次只落一个改动**：多个改动叠在一起、造成解释不了的差异时，拆开逐个重跑。

## 修一处复验一处：生成层改动跑全量回归

- 小问题直接修；每修一处，按状态读回数值（必要时定点渲图并交独立评审）确认它真的生效。
- 生成层（批量产出菜单、动画、形态键驱动的生成器）的改动要跑全量回归：同一请求重跑，逐态比较修前修后，**只允许出现预期的差异**；非预期的差异就是新引入的缺陷。本流程里重跑由 Runtime 在你退出后做，你比较前后两轮 Run 目录的证据。
- 设计记录、准备清单、写者清单都是快照：回归推翻的结论要回写，否则下一轮会沿用旧结论。

## 优化后回归：专查优化带来的变化

适用于优化后的最终回归；优化前那一轮没有这些变化。

- **材质错位与接缝**：AAO 的 `allowShuffleMaterialSlots`（材质槽重排）与 `optimizeTexture`（UV 重打包、单色贴图）开启时，逐件复检材质是否错位、贴图是否出现接缝。
- **被删的渲染器**：AAO 会删除「永远关着」的渲染器。某件在某档不见了，先在菜单与动画资产里搜它的名字：有 clip 引用却被删，是真缺陷（AAO 的追踪没看到这条引用）；没有任何引用，才说明它本来就永远关着。
- **动画路径与死参数**：AAO 会删除或改名 clip 路径。优化后重跑死参数检查，并确认所有动画路径仍可解析。
- **网格合并**：AAO 只合并显隐动画完全相同的蒙皮网格；Play 中还会合并、改名网格并重排骨骼，要换网格做对照就在编辑模式做。
- **参数裁剪**：基线、Pico 等其它场景里的头像也要确认裁剪后仍然生效。
- **PhysBone 合并**：合并后仍要做穿模与动态检查；合并可能改变组件的抓取与摆姿设置（`allowGrabbing`/`allowPosing`）。
- **贴图降档**：观感变化用与降档前同机位的 A/B 图比较，交独立评审；被看出差异就恢复该贴图的档位，而不是在别处补偿。本流程里：主图改回 `keep`（撤销降档）；辅助图（1024）与 Cubemap（512）的档位是硬上限，不能恢复到档位以上，在 `rationale` 写明差异并作为风险交人。
