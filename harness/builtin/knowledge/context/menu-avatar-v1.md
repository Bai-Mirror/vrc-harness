# 菜单、参数与动画层上下文 v2

plan/0.3 按已接受 avatar_config 编译独立服装/发型轮盘、独立配饰 Bool 与共享语义开关；成员身份用稳定 id，技术解析不能删档或重定默认。以下单轮盘约束仅适用于 plan/0.2。

你负责把造型功能整理成用户能理解、能预测、能恢复默认状态的 Avatar Menu。不要把工程对象树直接暴露给用户，也不要因为一个开关“看起来能动”就宣布完成。

## 先探查，再选择实现路线

轮盘与其 BoneProxy 可视件只纳管所属 exclusive 组；fixed 是共同穿戴件，不能写入互斥曲线。全 fixed 时不生成空轮盘。plan/0.3 按 avatar_config 保留多个独立组；plan/0.2 的旧合同仅有一个互斥组。

1. 枚举现有 Expressions Menu、Parameters、FX/Action/Gesture Animator、Modular Avatar、VRCFury 和厂商参数层。
2. 建立“用户功能 → 参数 → 状态机/MA 组件 → 动画曲线 → 最终对象”的所有权表。
3. 厂商参数层与目标属性完全不重叠时，可用 MA Object Toggle/Menu Item；存在重叠、层序或组合条件时，使用受控 Animator 层并驱动厂商参数。
4. 厂商已有参数层的功能优先驱动其参数，不直接只关网格。只关网格可能留下骨骼姿势、身体收缩和形态键状态。

## 信息架构与参数预算

- 按用户任务与身体部位分区，不按脚本或卖家包名分区。显示名可本地化，内部参数名保持稳定。
- plan/0.3 直接消费已接受 avatar_config 与 menu.tree：各互斥组可独立使用 Float 或 Int，独立成员用 Bool，共享开关按已接受 targets 全局记忆。技术调查不能重定组、默认值或布局。
- plan/0.2 才把横向通道调查写入 `Assets/_Harness/Menu/design.json`，并使用旧单衣装轮盘合同；缺失映射必须明确记录，不按对象名猜。
- 控件对应的是用户理解的语义部件组/穿搭层，而不是单个网格。不得为了实现方便把一个包的包体、肩带和挂件拆成多个用户开关。
- 厂商 ON/OFF 动画若还写 BlendShape、材质、骨骼或其他让位状态，不得只隐藏网格。plan/0.2 用 `vendor_clips` 登记；plan/0.3 只在能证明已有参数完整行为时显式 adopt，未知接管阻断。
- 厂商 ON clip 中“写成开启”不代表对象属于该功能；预制体默认关闭的对象通常是胸型、开襟等互斥备选件。默认拒绝收进组合开关，只有说明书与 solo 预览证明应联动时才在 `allow_default_off` 逐路径放行。
- Harness 会按“对象路径＋组件类型＋属性名”审计最终写者；两个部件组写同一属性是设计冲突，必须收归一个语义所有者。
- 共享语义开关不得为每套衣装复制独立参数；Int 互斥组选项可以用 Toggle，独立配饰各用 Bool。分页遵循生成器的 8 控件限制，批准布局不得用机械页号替代业务分组。
- 每个菜单最多 8 个控件。整套、发型和同部位多选通常使用轮盘；独立卖点与明确的单件功能才占独立 Toggle。
- 101 Button、102 Toggle、103 SubMenu、203 Radial 的语义不得互换。默认值应描述用户第一次加载时看到的唯一状态。
- 预算按构建后 Expressions Parameters 计算：Bool 1 bit，Int/Float 8 bit，总计不超过 256 bit。编辑期列表不是交付态证据。
- VRCFury 只能压缩符合条件、绑定菜单的同步参数；Contact、PhysBone、Raycast、未绑定菜单以及面捕 OSC 参数不能假设会被压缩。超预算时先区分可压与不可压，再请求取舍，不自行删功能。

## 属性所有权和厂商控制器合并

- 一条动画属性只能有一个最终写入层。动画曲线按后层覆盖前层；Parameter Driver 是进入状态时写一次，多个层 Set 同一参数会随进入顺序产生“切一圈又回来”的不稳定状态。
- Driver 写者按“构建后控制器/层”归并；同一层不同互斥状态是一个所有者，两个不同层或控制器写同一目标参数则必须合并、改为 Copy/范围转换或明确撤掉其中一方，不能靠当前层序碰巧正常。
- 需要跟随另一个参数时使用 Copy/范围转换或收归一个所有者，不用多个 Set 竞争。
- 容器根、子网格、材质槽、BlendShape、鞋型和显隐组合都必须有明确所有者。把曲线从旧层迁出时，同时删除旧写入。
- 读取合并后的控制器决定真实层名与索引。`VRCAnimatorLayerControl` 不得引用烘焙前猜测的层号；默认权重为 0 且没有控制器抬权会造成“菜单有开关、游戏里无反应”。
- Avatar Mask 一旦包含手臂或手指，就必须在所有状态持续写该部位，否则会覆盖厂商 Gesture，表现为手势失效或手一直半握。

## 复杂组合态

1. 先按位置枚举所有来源：素体、每套服装、每档发型和外购配饰；solo 渲染确认语义，不按名字猜。
2. 冲突表必须形成无环优先级链。同一位置默认态最多一个来源开启；发现 A 压 B 与 B 压 A 同时存在则停止。
3. 派生形态是“衣装档位 × 部件开关”的函数。鞋开、鞋关袜开、全关分别定义；一条转移的多条件是“与”，“或”需拆成多条。
4. 容器门控和部件门控不能重复写同一对象。追加件关闭后应恢复被它让位的原件；只验证开启态不够。
5. 每个 Toggle 验证开/关，每个轮盘逐档验证，再跑真实切换序列；离屏静态图不能证明 Parameter Driver 的事件顺序。
6. 服装根下带渲染器的 BoneProxy 会在 NDMF 后搬到目标骨骼下；套间轮盘必须对这些可视代理另写逐档显隐，不能只关闭源服装根。验收读取烘焙后曲线路径，手动关根的编辑期截图不构成证据。

## 生成、回读与恢复

- 生成 clip 后回读所有 CurveBinding；单帧 clip 同时写 `t=0` 与 `t=1/60`，父容器需要显式曲线时不得遗漏。
- 菜单资产必须非空，参数必须同时具备菜单入口和动画消费者；孤儿参数、死参数、重复写入和不可达状态均为失败。
- 生成结束后按层序把默认参数选中的 clip 真正应用到编辑期场景，并检查所有祖先激活状态；不要维护第二份手写默认清单。
- 重跑必须稳定更新 Harness 派生资产，不产生重复菜单、层、参数或 `Clone`。失败尝试精确回退对应资产，不用撤销栈。
- 最终检查基于 NDMF/插件合并后的控制器：参数预算、孤儿参数、死锁格、LayerControl 目标、单一 Descriptor 和骨架高度。
- Motion Time 轮盘按 clip 的真实 `m_StopTime` 与关键帧时间计算边界；取档用区间中点，不用四位小数近似或 1.0。循环 clip 的 1.0 会回绕首档，末档必须在烘焙后证明可达。
- 参数存活性扫描不能只看转移与 BlendTree；还必须覆盖 State 的 Motion Time、Speed、Mirror、Cycle Offset 与 Parameter Driver。每个菜单轮盘档位在真实 clip 长度上重新采样，任意两个无条件档位结果完全相同都视为死档。
- 对构建后的每个非首层检查 `defaultWeight`；权重 0 只有在存在可解析的 LayerControl 抬权时才合法。新增层后，旧的组合回归证据自动失效并重跑。

Runtime 会在受控 Unity 步骤后独立回读菜单、参数、动画层和真实状态组合。缺少审美命名或分区决定时，只提交两种信息架构候选；机制与安全规则不作为审美候选。
