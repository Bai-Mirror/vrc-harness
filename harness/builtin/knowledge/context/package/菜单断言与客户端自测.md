# 菜单断言与客户端自测

## 编译态菜单断言：期望由第二视角写、在构建后产物上测、由脚本比对

- **为什么**：多个已交付的工程都需要重交，缺陷都在「能用」这一层而不是「能编译」：部位开关与轮盘档位不对、胸型不跟随、厂商子菜单 9 个开关整体无效（客户点了没反应）、总包缺文件。开发态自验只验自己的假设：一次执行者自验 382 组全过，独立核查仍查出 5 个缺陷。
- **三段**：① 期望从交付说明写，不看生成器代码，每条带出处行；② 在构建后的产物上先导出菜单、拿到真实参数名，再按期望生成状态请求并扫描；③ 由脚本比对期望与实测。
- **必须有**：非空的行为断言、期望来源与每个状态的出处；Bool 开关两态、实际离散值全覆盖；连续轮盘或轴显式写 `coverage` 档数或边界并带出处，不从控件标签猜档数；同一参数兼有按钮与轮盘时，两种覆盖取并集；数值原样测，只有显式 `slot:N` 才换算成档中点。
- **工具**：`menu_expect_check.py`；交付链用 `gen-request --delivery` → 构建后状态扫描 → `check --delivery --params <菜单导出的 params.json>`。
- **成本**：每单多一次菜单导出与全档扫描（批处理约 10–20 分钟），外加一次写期望；与重交的代价相比值得。
- **本流程的口径**：编译态菜单断言由 Runtime 在你退出后、在冷导入副本上做（`delivery_menu_assertion`）：期望读自菜单阶段自己的 `menu.json`（由 `design.json` 生成的记录）与 `outfit.json`，在 NDMF 烘焙上测，属于实现自检，不是这里说的第二视角。你在打包之前运行、只写 `diagnosis.json`，那时交付包与冷副本都还不存在，也没有 `menu_expect_check.py`。在 `verified` 里引用这条检查时写明它的口径，相关项保留在 `client_checks`；不要因为没有独立期望文件就每次写 blocker。

## 菜单断言的判读：退出码、出处与改期望的规矩

- **退出码**：0 表示约定内的菜单断言通过；1 表示业务失败、缺失或缺测；2 表示输入、来源格式、匹配或覆盖约定不可判定。研究模式下的局部通过不作交付卡口。**退出 0 只是必要条件。**
- **独立复核**：第二视角核对出处确实支持该操作与断言，并检查每个参数的断言是否在验证它实际控制的效果。脚本不核出处正文，也发现不了「测衣装参数却只断言一个常亮的背景」这类无关断言。
- 输入异常、未覆盖、未核出处或含义的，一律不按交付通过处理。本流程的 `delivery_menu_assertion` 通过，只说明实现与菜单设计一致，不说明设计符合用户要求。
- **期望也会错**：期望写错会把正确的实现判成 FAIL。FAIL 时先核期望的出处，再核实现；不许为了 PASS 改期望，改期望必须写明「出处误读」。
- 状态扫描是编辑器构建后的口径，不等于游戏端（远端量化、同步位、他人视角）；这一层交给上传后自测清单。

## 上传后自测清单：固定项与本单项

编辑器构建后的口径不等于游戏端：一个工程的 Play 与构建终检全过，上传后用户仍报了两项游戏内问题。这份清单让真机口径成为交付的最后一格，由用户在游戏里勾。

**固定项（每单都有）**

- 镜子里与第一人称各看一次：默认装、全脱、每套衣装各一档。
- 让一个有 Friends 权限的朋友看你：轮盘每档切换后，他那边跟着变（同步位）。
- 轮盘拖到最末档与最首档：都能选到，不跳回。
- 每个开关连点两次（开 → 关 → 开）：没有「关了开不回来」。
- 换套装后，旧套装的小件（袜、手套、饰品）没有残留。
- 表情或面捕开着做 3 个表情：舌头、眼睛、嘴部小件没有穿出。
- 动骨：头发、裙、链子摇一摇，没有炸开或卡进身体。
- SDK 面板上的性能等级与参数量，与交付说明一致。

**本单项**：从期望文件的状态逐条转成一行——每个轮盘每档一行、每个开关开与关各一行，列「操作 / 应该看到 / 勾」。

**回传**：用户勾完发回截图或文字；未勾的项进该工程的待办并附截图。写诊断时，这些项全部留在 `client_checks` 里、状态为待测，不能写成已验证。

**本流程的 `client_checks` 固定为 5 个 id**，多一个、少一个打包工具都会直接失败（本阶段只有一次重试）：`upload`、`network_sync`、`saved_reload`、`vr_gestures`、`platform_rendering`，全部 `status: pending`，各有 `steps`、`expected`、`evidence_limit`。上面的固定项与本单项写进对应 id 的 `steps`（映射是建议，可按产品口径调整）：
- `upload`：SDK 面板上的性能等级、参数量与交付说明一致；
- `network_sync`：朋友视角看轮盘每档、每个开关是否同步；
- `saved_reload`：重进世界或重载头像后轮盘档位与开关保持；首档、末档都选得到；开关连点两次能开回来；
- `vr_gestures`：表情或面捕做 3 个表情、动骨摇动、第一人称；
- `platform_rendering`：镜子里看默认装、全脱、每套一档，换套后旧小件没有残留；本单每档、每个开关各一行。
