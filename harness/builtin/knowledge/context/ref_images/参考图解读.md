# 参考图解读阶段

把客户给的参考图变成可执行的捏脸方向与配色方向。位于接单建档之后、开工定方向（人工确认）之前；产出喂给捏脸候选与贴图配色。与选型图鉴互不依赖，可以并行。每节可单独注入。

## 参考图解读：产出是方向，不是捏脸方案

- **职责**：从参考图里读出「想往哪走」——脸型、五官、妆容、发型、配色、风格——写成可执行的方向和具体色值。
- **权威输入**：客户参考图原件；建档记录（已定装哪些素材、哪些不装）；导入后的形态键枚举清单。
- **决策边界**：这一步的产出**不构成捏脸方案**。它只有「想往哪走」，还缺「能往哪走」，也就是素体实际提供了哪些脸型形态键。两边取交集才是方案。所以本阶段必须配一步形态键枚举，否则会产出「凭空发明不存在的键」的方向。
- **捏脸手段的硬边界**：捏脸只调厂商形态键，不许自由编辑顶点造型。
- **禁止**：把方向直接写成键值方案；引用枚举清单里没有的键名；拿建档判为「不装」的素材当风格依据。
- **产出**：参考图解读汇总（图片对照表、逐图描述、捏脸方向、配色 hex、风格关键词、分歧汇总六部分），供开工定方向时由人确认。
- **怎么验证**：方向里提到的每个键名都在枚举清单里（逐条比对）；配色方向都有 hex；每条方向都标出依据是哪张图的哪个特征。
- **升级给人**：参考图之间风格互相矛盾、或方向明显超出素体形态键能做到的范围时，给出 2～3 组互斥候选，交人在开工定方向时选。

## 多路独立描述与一条独立审美路

- **职责**：用几种互相独立的方法读同一批图，靠「不同方法得出同一结论」来提高可信度。
- **权威输入**：参考图的短名副本与任务说明。
- **决策边界**：每一路只做自己的描述或判断，不读别路的产出。
- **编成（做法层面）**：
  - 若干路**视觉模型描述**：通过多模型评审工具发给不同的视觉模型，只做描述。
  - 一路**本地子代理描述**：直接读图。先自己读、写下结论，再看模型结果，避免被带跑。
  - 一路**独立审美判断**：负责风格配比、捏脸方向、配色 hex。它写自己单独的输出文件，任务描述里明写「不要去找别的路的产出」——否则几路退化成一路。
- **为什么有效**：有记录显示，独立审美路与其余各路各自得出「帅气感不来自骨相」的同一结论，两路测得的瞳色 `#B7B0BD` 与 `#B6AEBC` 几乎重合，构成跨方法的交叉验证。
- **禁止**：让各路共享输出文件；让汇总者在各路跑完前把自己的结论发给它们。
- **怎么验证**：每一路的输入只有图和任务说明；每一路都有独立的输出文件。
- **产出**：每一路一个独立的输出文件。
- **升级给人**：只有一种方法能跑通（其余都失败）时，写明结论缺少交叉验证，交人决定是否继续。

## 备图与描述型结构化输出

- **职责**：把参考图整理成各路都能稳定读取的形式，并定好描述任务的输出结构与系统提示。
- **权威输入**：客户参考图原件。
- **决策边界**：只处理副本（改名、缩图），不改原图。
- **备图**：
  1. 参考图复制成 ASCII 短名（`ref01.png`…）。评审工具对中文、emoji 文件名不稳。
  2. 等比缩到长边 ≤ 1600px，并记下「短名 ↔ 原名 ↔ 是否缩图」的对照表。
  3. 判据：对照表条目数＝原图张数。
- **输出结构（每张图一条）**：`image_id`、`hair`、`eyes`、`face_shape`、`makeup`、`outfit`、`accessories`、`mood_keywords`、`standout_feature`。评审工具默认的是缺陷评审型结构（`findings`、`verdict`），描述任务要自带结构与系统提示。
- **系统提示必写的四条（每条都对应一次踩坑）**：
  1. 只描述实际附上的图，没附的图一个字都不要写。有模型收到 2 张图却评了 8 张。
  2. 不要在提示里列「有哪些图」的清单，模型会照着清单编。
  3. 这是描述任务，不是挑错任务，不要给改进建议。
  4. 只用只读的文件查看工具，不要调用任何终端命令，否则会撞权限墙、返回空结果。
- **禁止**：直接用原始文件名和原图尺寸送审；沿用缺陷评审型的输出结构。
- **产出**：短名副本、对照表、输出结构与系统提示。
- **怎么验证**：对照表条目数＝原图张数；每张图的输出都含全部字段。
- **升级给人**：参考图含敏感内容、平台拒绝处理时，如实记录哪几张被拒，交人决定是否换图。

## 分发与失败处理：每一路都标成功或失败

- **职责**：把图送到各路，并如实记录每一路的结果。
- **权威输入**：备好的短名图、系统提示与输出结构。
- **决策边界**：只送审与记录；失败的路改分批重送，或如实记为失败。
- **分批**：有的模型一次喂五张图没问题；有的模型一次多图就超时。遇到后者改成一张一批。有一次实测：5 张（27 MB）超时，缩到 1600px（8 MB）仍然超时，1 张则正常返回完整描述——驱动因素是**张数**，不是体积，缩图不解决。
- **超时容易误诊**：超时时响应是空串，标准输出的尾巴只剩结构回显和用量统计，极易误诊成「解析出了 bug」。评审工具失败时应把原始输出落盘，并分清「工具报错」与「解析不出」；看到「没解析出」，先去读那份原始输出。
- **判据**：每一路都明确标出成功或失败；失败的写清原因，不能默默少一路。
- **禁止**：把失败的一路当成「没问题」——零条指认不等于通过；为「解析不出」写补丁之前不先看原始输出。
- **怎么验证**：结果表里路数＝派出的路数，每路有状态与原因。
- **产出**：结果表（路、状态、原因、输出文件）。
- **升级给人**：多数路失败，或失败原因是平台拒绝而不是技术问题时，写明情况交人。

## 汇总结构：六部分，方向写成部位、方向、幅度

- **职责**：把各路结果汇总成一份可执行的解读文档。
- **权威输入**：各路输出文件、建档记录、形态键枚举清单。
- **决策边界**：汇总与复核，不替用户定方向。
- **结构**：
  1. **图片对照表**（短名 ↔ 原名 ↔ 是否缩图）。
  2. **逐图描述**：各路并列；多路一致的加粗；有分歧的单独标出，并说明分歧在哪。
  3. **捏脸方向建议**：写成可执行的方向（部位＋往哪边＋幅度），不要只写「可爱一点」；每条标出依据是哪张图的哪个特征；给 2～3 组互斥候选。
  4. **配色方向建议**：给具体 hex，不给色彩形容词。
  5. **风格关键词收敛**。
  6. **各路分歧汇总**：单独一节，列出只有一家说的结论，逐条自己复核。
- **禁止**：只给一组方向；用形容词代替 hex；把单路结论混进「多路一致」。
- **怎么验证**：六部分齐全；每条方向有依据；每组候选之间确实互斥。
- **产出**：参考图解读文档（六部分）。
- **升级给人**：方向候选需要客户或用户拍板时，在开工定方向环节交人。

## 读结果：跨方法一致才算证实

- **职责**：判断哪些结论可以采信、哪些要待核。
- **权威输入**：各路结果、子代理的工具调用记录、建档记录。
- **决策边界**：只判断可信度，不补造证据。
- **规则**：
  - 同一结论由「视觉模型」与「本地子代理」两种方法各自得出 → 可信度最高。
  - 单路结论一律进「待核」，不直接丢，也不直接信。
  - 零条分歧不等于通过。先问：是真没分歧，还是喂的图让它们看不见。
- **子代理报上来的三种错（都出现过）**：
  - 把不在用的素材当依据：拿「客户买过某眼睛贴图包」推风格，而那个包在建档里标着不装（不支持本素体）。
  - 与建档冲突却不自查：报「发型二选一」，但建档里用户已定两个都装。
  - 观察对、结论错：报「三级解析回退全落空」（观察对），断为解析 bug（错，其实是超时）。
- **核对方法**：子代理的每条结论，先问它的工具调用能不能支撑。列目录得不出「内容等价」，读文件名得不出「功能等价」，截断的日志尾巴得不出病因。
- **禁止**：因为结论听起来合理就采纳；把多数票当成交叉验证（同一种方法跑几遍不算）。
- **产出**：每条结论的可信度标记（已交叉验证／待核）。
- **怎么验证**：每条标为「已证实」的结论都能指出两种不同方法的来源。
- **升级给人**：关键结论只有单路支持、又影响方向选择时，标「待核」交人。
