# 菜单与动画层：跨工程的稳定结论

来自 7 个客户工程与 14 个历史工程的菜单、FX 层与轮盘核查。

## Motion Time 轮盘：档位取精确 i/n，循环片段的末档会回绕

- **适用范围**：用单个 Float 通过 Motion Time（`m_TimeParameterActive: 1`）拖一条片段来切换档位的换装、发型轮盘（厂商自带或生成器生成）。
- **结论**：① 片段用常量切线时，档 i 占 `[i/n, (i+1)/n)`；测试或文档里写 0.2857 这类截断值会落进上一档（0.2857 < 2/7），曾让三行测试结果看似「两档相同」。② 片段 `m_LoopTime` = 1 时，参数 1.0 会回绕到 0；如果最后一个关键帧在归一化时间 1.0、且该帧的 `m_IsActive` 相对前一帧有独立变化，这一档只存在于 t = 1.0，永远选不到（例：素体基础装、全关态）。
- **判据**：扫描所有 Motion Time 状态的片段，读 `m_LoopTime` 与关键帧归一化时间（time / `m_StopTime`）：`loop = 1` 且末键 = 1.0 且末键有独立变化 → 真缺陷；末键与前一键完全相同只是收尾。测试取档中点 (i+0.5)/n，并单独测 1.0；档位表写成 i/n 而不是小数。
- **修法**：做一份不循环的片段或给轮盘加一档，让末档有自己的区间；Play 下逐档读回，所有头像根都改。
- **证据等级**：多工程验证——两个 Rurune 工程的末档回绕（均修复读回）、一个 Kaguya 工程的截断取值；一次横向普查在 7 个工程 968 个 Motion Time 状态中找到 2 个真缺陷。
- **失效条件**：档位由 Int 参数＋独立状态实现时不适用。

## 层默认权重为 0 又无人抬权：开关点了没反应

- **适用范围**：厂商 FX 层与合并进来的控制器；菜单里有开关或轮盘、FX 里也有对应层的情况。
- **结论**：层的 `m_DefaultWeight` 为 0、又没有任何 LayerControl（或 MA 等工具）在运行时把它抬起来时，该层的动画不生效，菜单项「点了没反应」。实例：一个 Kipfel 工程厂商面捕菜单下的 9 个 Outfit 开关在 36 个状态里零效果（厂商 `Outfit *` 层权重全为 0）；一个历史工程的胸型轮盘对应层默认权重 0、静态看无人抬权（运行时是否生效未开 Unity 确认）。
- **判据**：在构建产物上逐层读 FX 的 `m_DefaultWeight`，对照全部 LayerControl，列出「权重 0 且无人抬」的层及其菜单控件；这类菜单项要么接通、要么从菜单删掉，并写进交付说明。
- **证据等级**：多工程验证——一个客户工程 Play 实测确认，另一个历史工程静态发现（运行时未证）。
- **失效条件**：层由构建期工具在合并时改写权重的，以构建产物为准。

## 自建层不要改写厂商已有的开关逻辑

- **适用范围**：在厂商头像或厂商服装自带 FX 层的基础上，再用生成器或手写层做换装菜单的工程。
- **结论**：自建层去写厂商层也在管的物体或参数，会与厂商逻辑打架，而且症状往往延迟出现：
  - 厂商已做好 A/B 二选一（例：两双袜子由一个 Bool 层切换），自建层的 ON 片段强开其中一双、再用参数驱动器强写那个 Bool，用户的选择被冲掉；
  - 厂商层是「播一次就停」的结构（进入空状态后不再写某属性），自建层覆盖过该属性后值会永久卡住（例：换发型再换回来猫耳消失）；
  - 生成器把厂商开关片段里的全部 `m_IsActive` / `m_Enabled` 路径当成「本件物体」收进开关组，把厂商默认关着的备选件（例：另一版外套）也激活，两件重合同时可见；
  - 部位开关层的 ON 状态无条件把厂商的 `*_OFF` 参数写回 false，穿外购整套时素体原装又冒出来。
- **判据**：改层前先查清「谁驱动、几档、层权重、默认值」；自建层只管「开 / 关」这一层语义，「开哪一个变体」留给厂商层；每个开关做「开 → 关 → 开」往返与跨档切换的真序列测试。
- **修法**：维护「厂商备选件表」在收集路径时排除；按上下文拆状态（例：整套档位下的 ON 不写素体 `*_OFF`）；删掉对厂商参数的强写驱动。
- **证据等级**：多工程验证——Milfy、Kipfel、Kaguya 三个工程各自出现并修复。
- **失效条件**：厂商层本身有缺陷需要替换时，整层接管并写明，不要半接管。

## 开关归属与语义要逐件核对

- **适用范围**：多件服装共用一个开关、或菜单里多个同类开关的情况。
- **结论**：常见的三类错：一个开关同时管多件（例：开衫、裙、鞋三件挂在「外套」一个开关上，一次脱三件；拆开后应做到只点鞋时只脱鞋，鞋负责的脚型键 `High_heel` 随之归 0）；同一菜单里某个开关的语义与其他开关相反（其余「开 = 穿上」，眼镜「开 = 摘下」，默认值也不一致）；菜单保留了一整组无效的厂商子菜单。
- **判据**：对每个开关列出它控制的物体、写的键、默认值；同类开关语义一致（开 = 显示）；只点一件只变一件。
- **修法**：拆成各自独立的开关；语义反的改为反向开关（Inverted）并统一默认值；无效子菜单删掉或接通。
- **证据等级**：单一案例（候选）——一个 Kipfel 工程的一次修复（三类合并为一个回放用例）。
- **失效条件**：需求方明确要求「一键脱整套」时保留，但要在交付说明写清。

## 死参数：开关、参数、层都在，点了没反应

- **适用范围**：经过 AAO 等优化工具处理后的构建产物；历史工程。
- **结论**：动画片段里的曲线路径指向的物体被优化工具删掉或改名后，路径解析不到，开关就成了死参数；只看 `VRCExpressionsMenu` 判「缺项」「参数悬空」也会误判，要连同 MA Menu Item 一起解析。
- **判据**：在构建后的克隆上按「参数 → 层 → 片段 → 曲线路径」逐级解析，0 条曲线路径可解析即死参数（一个历史工程用这种追踪查出 5 处）；AAO 之后要重跑一次。
- **证据等级**：单一案例（候选）——一个历史工程的追踪结果；方法在其他工程的审查计划中沿用。
- **失效条件**：无。

## 菜单编排：一个属性只有一个写者

- **适用范围**：用生成器或手工编排的换装菜单（整套档位＋逐件开关＋配色轮盘并存）。
- **结论**：同一个属性（物体激活、形态键、材质槽）被两层以上写入时，结果依赖层序与 Write Defaults，最容易出现「某些组合下不一致」。一次编排的第 2 轮自称通过，独立核查仍查出 5 个缺陷；第 3 轮按「一属性一写者」重排后，静态模拟 3895 种组合在 Write Defaults 开 / 关两种设置下不一致数都为 0，再经完整预处理＋运行时逐项复测通过。另一处遗留：旧片段仍在写 `outer_shrink` / `sailor_shrink`，与声明层重复，属于要撤掉的重复写者。
- **判据**：列出每个属性的写者，超过一个就合并或拆分；轮盘档位按中点阈值判定；标签锁定（避免重生成后标签错位）；静态模拟全组合 × Write Defaults 两种设置，不一致数为 0；再在构建产物上抽测。
- **证据等级**：单一案例（候选）——一个 Kaguya 工程的新衣根菜单。
- **失效条件**：厂商层必须保留时，把厂商层当作该属性的唯一写者，自建层不再写它。
