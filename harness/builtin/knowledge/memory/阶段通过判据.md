# 阶段通过判据：质量记忆

人工工作流里各阶段「可以自动检查的通过判据」汇总，按阶段分节。与 Harness 自带的检查可能重叠；两者不一致时以 Harness 的检查为准，这里的条目用于补漏与自查。每节独立成立，按「适用范围、结论、判据、证据等级、失效条件」写。

## 接单建档与素材清点的通过判据

- **适用范围**：接单建档、素材清点与导入。
- **结论**：清点与导入以「条目对得上、GUID 没变、每件素材有去向」为完成。
- **判据**：委托方给的全部需求文本都读到；素材清单条目数等于商品目录数；每件素材的兼容结论属于「支持 / 不支持 / 待骨骼比对 / 项目依赖」之一（「项目依赖」是包内只有 VPM 安装入口的件，见挑包与兼容判定）；没有未解开的压缩包；没有缺失的公共包或材质包；GUID 未被重生成；素材应用表每一行都写了「用途」或「不用的原因」，且应用表的判据过了一正一反两例自检；交付前应用表不得有空白格，「不用」必须写得出原因。Harness 的 pc-recolor-outfit 流程里，「不用」以方案批准的 `unused` 为准：打包检查只豁免列在 `unused` 里的商品。清点与完整性判定可以并行，导入动作必须串行。
- **证据等级**：多工程验证
- **失效条件**：改由工具自动清点时，以工具的清单格式为准；「每件有去向、GUID 不变」两条仍成立。

## 参考图解读、选型图鉴与定方向的通过判据

- **适用范围**：方案前置环节：参考图解读、给委托方的选型图鉴、开工定方向。
- **结论**：方向要落到可执行的量上；选型图鉴要能离线打开、可以点选。
- **判据**：参考图的每一路解读都标出成功或失败；捏脸方向写得出「部位 + 方向 + 幅度」；配色给得出 hex。选型图鉴：HTML 零外链且每项有图；PDF 的 `/Btn`（表单按钮）数等于条目数；PDF 文案不含「复制清单」字样。开工方向由委托方一句话确认。
- **证据等级**：多工程验证
- **失效条件**：不出选型图鉴（素材已由输入清单指定）时，图鉴两条不适用。

## 形态键枚举、捏脸与面捕的通过判据

- **适用范围**：完整定制流程的形态键枚举、捏脸（调值、烘焙、导出）与面部追踪。
- **结论**：捏脸只调厂商形态键，键值由委托方定；烘焙、导出、校验是机械步骤，全部用数值判据；面捕在捏脸通过之后、全部作业的最后安装。
- **判据**：方案里引用的每个形态键名，都在导入后素体的键名清单里（逐条 grep）。烘焙形状键到基础网格是精确重建，不是累加；闭眼补偿键要重算。接缝裂开 < 0.3 mm、|Δy| < 2 mm；烘焙后 Basis 与 `mesh.vertices` 差 0 mm；FBX 落盘前做二进制自检，含厂商材质名计数；全量 `.anim` 表情无外推越界；覆盖 FBX 后重挂材质并扫空材质槽。面部追踪被捏脸阻塞，捏脸未通过不能开工；安装器会克隆整个头像，装完核对只有一个活跃头像根。
- **证据等级**：多工程验证
- **失效条件**：素体没有可用的厂商形态键、必须动网格造型时，本节不适用，手段要另行与委托方确认。

## 配色的通过判据

- **适用范围**：贴图与配色阶段。
- **结论**：配色是审美卡口，定案靠独立评审；产出要覆盖需求里点名的每个颜色。
- **判据**：每一步做一次单评审快评；定案时三家独立评审交叉，至少两家没有阻断级意见；需求里点名的眼睛、头发颜色都有对应产出。换过 FBX 之后配色要重做（材质数组会被重置）。出候选与评审可以全自动，定案有分歧时才交人。
- **证据等级**：多工程验证
- **失效条件**：有版本化的自动通过策略（最少家族数、法定票数）时，以该策略为准。Harness 的 pc-recolor-outfit 流程以人工闸门为准：配色方向随方案批准，定档由人在 `recolor_approval` 外观批准时决定，模型评审只供参考。

## 服装装配与配饰装位的通过判据

- **适用范围**：服装发型装配、配饰装位。
- **结论**：装配以「件件接上线、骨架不缺、环状配饰套住」为完成。
- **判据**：每件服装有部件图鉴（缺则先建档）；每件导入的素材都有包外引用（没有就是没接线）；骨架零缺失。环状配饰每件都判定为「套住」：偏心 < 内半径，且夹角 < 12°。位姿有闭式判据，先断言再看图；观感问题走独立评审。
- **证据等级**：多工程验证
- **失效条件**：悬浮、贴面类配饰不适用「套住」判据，改用渲染参照面判据。

## 菜单与动画层的通过判据

- **适用范围**：菜单与动画层阶段。
- **结论**：菜单以预算内、结构合规、资产真实落盘为完成。
- **判据**：构建后的参数 ≤ 256 bit（Harness 的 menu 阶段按 NDMF 处理后、VRCFury 压缩前的数计，超过即阻断）；每个菜单 ≤ 8 个控件；生成的菜单与动画资产回读非空。层序设计按既定惯例，不现场发挥。
- **证据等级**：多工程验证
- **失效条件**：VRChat 调整参数预算或菜单控件上限时，按新上限改判据。

## 回归、感知与性能优化的通过判据

- **适用范围**：感知对账、回归测试、性能优化。
- **结论**：回归与优化的「通过」必须写明覆盖面与运行口径，未测的不算通过。
- **判据**：感知对账里未测的项照实列出，不计为通过。回归按离散档位与开关以及约定的连续值验证行为；动作穿模按本工程标定的阈值判；写明未覆盖项与运行口径；平台覆盖类改动在编辑器里验不出来，必须在真机上验。优化后贴图内存下降，AABB 与 PhysBone 不超限；动骨观感的改动只能在 Play 里看。
- **证据等级**：多工程验证
- **失效条件**：无。

## 交付打包与终审的通过判据

- **适用范围**：交付打包、上传与终审。
- **结论**：交付包以「行为断言通过、冷导入可编译、清单一致」为完成；上传与终审只能由人做。
- **判据**：先通过编译态菜单行为断言（构建后的菜单行为与交付说明写明的期望逐项比对；Harness 的 `delivery_menu_assertion` 以菜单阶段自己的 `menu.json` 为期望，属于实现自检，不能替代客户端自测）；解包后冷导入能编译，内容清单与大小一致；VRChat SDK 上传由人操作，打包、校验、写交付说明可以全自动。
- **证据等级**：多工程验证
- **失效条件**：无。
