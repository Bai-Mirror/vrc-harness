# 渲染：抓屏排序与「透过它看不见」

## 抓屏材质决定透过它能看到什么

- **适用范围**：使用 lilToon 抓屏类 shader 的头像（lilToon 2.3.4：`Hidden/lilToonRefraction`、`Hidden/lilToonGem`、`Hidden/lilToonRefractionBlur`、`Hidden/lilToonMultiRefraction`、`Hidden/lilToonMultiGem` 带具名 `GrabPass {"_lilBackgroundTexture"}`；另有 `LilBugShader/Refraction` 也用同名纹理）。宝石、液滴、玻璃窗、折射类小件最常见。
- **结论**：抓屏在渲染队列的某一刻截一次屏；当前可见的抓屏材质里**队列最小的那个就是抓取点**，队列 ≥ 抓取点的可见物，透过抓屏窗口看时都会消失（例：透过头饰宝石看到的发型、脸部透明层、丝袜变成透明）。一个 Kaguya 工程里，头饰换色动画引用了厂商原件材质（队列 2450），构建后把场景里准备好的高队列副本顶掉，抓取点提前到 2450。
- **判据**：不用渲图就能查：对每个状态列出可见材质里用抓屏 shader 的那些，取最小队列作为抓取点，再列出队列 ≥ 它、且可能被透过看到的物体。修后抓取点应在所有需要被透过看到的物体之后（实例：2450 → 3050，28/28 状态；被遮对象数 24 → 0）；渲图与盲测只做确认。要用渲图定位时，渲「有 / 无该前景件」两张同机位图做像素差，比肉眼找更可靠。
- **修法**：给抓屏材质做高队列副本（例 3050），并确保所有会换材质的动画（换色轮盘等）引用副本而不是厂商原件；小件抓屏点在 2900 的，逐个评估透过它能看到的东西（一个工程的液滴、宝石经盲测没有可见后果，另一个工程的星星贴纸、发饰宝石待复核）。
- **证据等级**：多工程验证——三个工程（Kaguya、Rurune、Shinano）用同一方法检出抓取点，Kaguya 一例由用户报告并修复确认，其余两例为候选。
- **失效条件与未决**：VRChat 里具名抓屏在整个场景共用，别人的头像或世界可能把抓取点提前，这可能是「偶发透明」的另一个来源（推理，未证实）；对策设计是复制抓屏 shader 做私有变体、把纹理名改成工程专用名，未完成实机验收。无名 `GrabPass {}` 每批次都抓，不受同名共用影响。
