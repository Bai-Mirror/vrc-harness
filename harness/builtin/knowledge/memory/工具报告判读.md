# 工具报告的字段与判读

几类常用工具报告（性能、贴图清单、贴图分级、AAO 设置、形态键清单、PSD 图层树）的字段含义与读法。样例都来自同一个 Kipfel 工程，数值只作标定参考。每节固定写适用范围、结论、判据、证据等级、失效条件。

## 性能报告：字段、评级与「构建前／构建后」两种口径

- **适用范围**：按 VRChat 性能分级输出的头像性能报告（PC）。
- **结论**：
  - 抬头注明素体与口径：「运行模式＝构建后」或「编辑模式＝构建前」。逐项有 `Polygons`、`Skinned Meshes`、`Meshes`、`Material Slots`、`Bones`、`Texture Memory`、`Animators`、`PhysBone Components`、`PhysBone Transforms`、`PhysBone Colliders`、`PhysBone Collision Check Count`、`Contact Count`、`Constraints`、`Particle Systems`、`Audio Sources`，每项带数值与等级（Excellent／Good／Medium／Poor／VeryPoor）。
  - 「综合评级」取所有项里最差的一档。下载与解压后体积只有真正构建出包时才有值。报告尾部另有渲染器数、材质槽合计、去重后的材质数，以及按头像下第一层子物体分组的面数分布。
  - **两种口径不能混比**：同一个头像，编辑模式下骨骼 859、PhysBone Transforms 713、Contact 4、约束 6、贴图显存 100.5 MB；构建后是 758、684、18、13、208.4 MB。构建流程（NDMF、MA、AAO、插件生成的克隆）会增删物体与贴图。
- **判据**：优化前后对比只在同一口径下做；综合评级常被一项拖住（例如面数 39 万），判断优化效果要看分项的变化（贴图显存 208.4 → 107.8 → 92.4 MB、蒙皮网格 64 → 51、骨骼 758 → 588）；面数分布找占比最大的顶层分组，决定开关、删除或减面的对象。
- **证据等级**：单一案例（候选）。
- **失效条件**：VRChat 调整性能分级或报告工具改版时。

## 贴图清单：逐张尺寸、格式、实际占用与使用处

- **适用范围**：按贴图逐张列出显存占用的报告。
- **结论**：
  - 抬头给总张数与合计 MB；每行依次是占用 MB、尺寸、格式、资产路径，以及 `<- 材质名 . 槽名`（这张贴图被哪个材质的哪个槽使用）。
  - 材质名带 `(LLC Clone)` 的是 Light Limit Changer 克隆出来的材质；路径在 `Packages/nadena.dev.ndmf/__Generated/<头像>(Clone)/_assets/` 下的是构建时生成的资产。
  - 同尺寸下，这份报告里 RGBA32 的占用是 DXT5／BC7 的 4 倍、DXT1 的 8 倍（2048² 分别为 42.67、10.67、5.33 MB）。
  - 这份清单就是「四张 2048² RGBA32 克隆贴图各占 42.67 MB」现形的地方；排在前面的还有 1024 立方体贴图（宝石反射，16 MB）和 4096² 主贴图。
- **判据**：按占用排序，先看构建生成的克隆和未压缩格式，顺着路径找到源图，改源图的导入设置；再看大尺寸立方体贴图、4096² 贴图能否降档。改完用同一口径重跑性能报告对账。
- **证据等级**：单一案例（候选）。
- **失效条件**：工具改变占用的计算口径时。

## 贴图分级改动明细：只记改了哪几张

- **适用范围**：批量调整贴图导入设置（分级压缩）的改动记录。
- **结论**：抬头之后逐张列出改动的贴图路径与改法（例如「默认平台格式 RGBA32 -> 自动压缩」），末行给「共扫 N 张，改了 M 张」。样例里扫 69 张、只改 2 张——正是那几张被克隆的源图；前后两份同口径性能报告的贴图显存从 208.4 MB 降到 107.8 MB。
- **判据**：改动明细要与前后性能报告配对保存，才能说明显存下降来自哪几张；「扫了多少张」不是效果，效果看同口径的显存读数。
- **证据等级**：单一案例（候选）。
- **失效条件**：分级工具改版时。

## AAO 自动优化设置：TraceAndOptimize 的开关项

- **适用范围**：Avatar Optimizer 的 TraceAndOptimize 组件。
- **结论**：报告逐项列出开关与当时的取值：`optimizeBlendShape`、`removeUnusedObjects`、`preserveEndBone`、`removeZeroSizedPolygons`、`optimizePhysBone`、`optimizeAnimator`、`mergeSkinnedMesh`、`allowShuffleMaterialSlots`、`optimizeTexture`、`mmdWorldCompatibility`、`debugOptions`。样例工程里除 `preserveEndBone`、`removeZeroSizedPolygons` 外都开着。
- **判据**：每次优化都记录当时的设置，前后结果不一致时先比设置；排查「优化后外观或功能变了」时，逐个关掉可疑项（合并网格、动画优化、贴图优化）复现。
- **证据等级**：单一案例（候选）（Avatar Optimizer 1.9 系）。
- **失效条件**：AAO 增删设置项时。

## 形态键清单：按网格分组、带默认权重

- **适用范围**：导出全部形态键的报告，用于形态键枚举与核对。
- **结论**：按网格分段，段头形如 `=== <网格名>  (N shapes) ===`；每行是序号、键名、`w=` 当前权重。名字由连字符包起来的键是厂商的分段标记，本身不驱动变形。服装网格上的非零默认权重（例如 `Lens_ON`、`Necktie_spine_OFF`、`Shirt_spine_OFF` 为 100，某个刘海键约 55.9）说明厂商有意让该状态默认生效。样例素体的身体网格有 372 个键、身体底座网格 51 个键（肩、上臂、肘、前臂、腕、手、颈、胸、脊柱、髋、腿、脚、脚趾的 `_OFF` 收缩键及其左右分键，另有 `Bust_slim`、`Waist_slim`、`Leg_slim`、`Ankle_slim`、`Foot_down`、`High_heel` 几个体型键）。
- **判据**：捏脸方案引用的键逐个在清单里查到；动非零默认权重之前先弄清它的作用。
- **证据等级**：单一案例（候选）。
- **失效条件**：素体版本更新改键时，重新导出。

## PSD 图层树：可见性、类型与包围框

- **适用范围**：导出 PSD 完整图层树的报告，用于找图层、抠图。
- **结论**：首行是画布尺寸；每行一个图层：`[v]` 表示可见、`[ ]` 表示隐藏，然后是图层名、类型（`group`／`pixel`）和包围框 `(x0, y0, x1, y1)`，缩进表示嵌套。隐藏的组包围框显示为 `(0, 0, 0, 0)`：合成隐藏组得到的是空图，但组内像素图层仍有各自的包围框和像素。图层名里可能带厂商的操作提示（例如「用油漆桶填色」）。样例是一个约 960 层的眼睛贴图 PSD。
- **判据**：要抠的目标在隐藏组里时，按图层取原始像素（例如 psd-tools 的 `layer.numpy()`），不要用组合成；抠完检查像素非空。
- **证据等级**：单一案例（候选）。
- **失效条件**：导出工具改变格式时。
