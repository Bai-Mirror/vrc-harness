# 换装依赖的八类：谁该写哪个键、什么状态下显隐

从 7 个客户工程与 14 个历史工程的缺陷归纳出的八类依赖（D1–D8）。装配与回归时按类逐一过，比按物体逐个猜更不容易漏。

## 换装依赖 D1–D4：身体、脚、袜、内外层

- **适用范围**：多套服装、多件部件可单独开关的头像（MA Shape Changer、动画层、BlendshapeSync 混用）。
- **结论与期望**：
  - **D1 身体 ← 衣物（收缩 / 删除）**：遮住的地方缩够但不过头，露出的地方不缩；衣物不可见就回基线。已知问题：Delete 不可恢复；有的厂商服装根本没有收缩机制（不是漏挂，但穿模要渲图确认）；整套级常驻收缩键会与其他服装叠加。
  - **D2 脚 ← 鞋**：按鞋跟选脚型姿态键；只有封闭且会顶出的鞋才用收缩键。已知问题：同一脚型键在不同鞋上的取值不同（78 / 100；按套装 70 / 80 / 100）；某些服装对脚型键是 Delete（删顶点），不是抢写。
  - **D3 袜 ↔ 脚型，袜 ← 鞋**：袜子可见时脚型满足袜子；鞋关袜开不能回到中性。两个方向都出过事：厂商把平脚键只挂在袜子上，关袜穿鞋时脚趾顶出鞋头；另一个工程把脚型只挂在鞋上，关鞋后脚从袜子里顶出来。袜子 Delete 脚部键时要对照露趾鞋。
  - **D4a 衣物 ← 衣物（内层收缩）**：内外层都可见时内层收缩；外层关掉回基线；**再打开要重新收缩**（1 → 0 → 1 往返）。实例：内层衬衣的 `Parker_on` 只在某些片段里写，「关掉外套后内层还保持收缩」是需求方实测到的问题。
  - **D4b 内衣 ↔ 下装**：要分开表达谁缩谁、谁压谁的显隐、同部位的优先级链（例：丝袜开的档把内裤写成隐藏，但缺少优先级链时会与其他下装冲突）。
- **判据**：每类列出「写者、条件、期望值」，按可达状态逐个读回；往返序列必测。
- **证据等级**：多工程验证——各类都有两个以上工程的实例。
- **失效条件**：厂商已用自己的机制完整覆盖某类时，只核对不改写。

## 换装依赖 D5–D8：体型、遮挡显隐、发型、姿势

- **适用范围**：多套服装、多件部件可单独开关的头像（MA Shape Changer、动画层、BlendshapeSync 混用）。
- **结论与期望**：
  - **D5 衣物 ← 体型**：贴身衣物跟随身体的体型键（胸、腰等）；体型决定变体时（大胸专用外套）按体型选变体、二选一。已知问题：衣物缺键；只写了身体没写衣物；Delete 不被同步；厂商滑块层与 Shape Changer 抢键；生成器没有「体型变了自动换变体」的机制。
  - **D6 遮挡显隐**：被遮住的小件随覆盖件隐藏（乳头类键、脚甲）。期望：**任一**覆盖件可见即隐藏（「鞋开或袜开」隐藏脚甲，露趾款例外）。已知问题：把「或」写成「与」；只跟整套档位、不跟具体部件；乳头类键构建后被 AAO 合并成一个键。
  - **D7 发型 ← 外套、帽子**：素体自带发型有外套避让键（如 `Outer_on`），开外套时取目标值、关掉回基线；第三方发型通常没有这类键，只能渲图确认、列为视觉残余；兜帽与帽子之间常缺互斥。
  - **D8 姿势相关**：走、坐、蹲时不穿出（如膝、肘的收缩键只在弯曲时才需要）。大多数检查只在 T / A 姿势下做过；一个 Kipfel 工程做过 85 个姿势的动作扫描（素体自带动作层的人形片段＋合成抬臂），确认衬衫下的肩臂收缩键只在举手、趴下、坐姿表情时才需要，待机差 0 像素。裙摆等布料归视觉残余。
- **共有的失效方式**：同键多写者，源文件看不出谁胜；超出 0–100 的值编辑器里看着对、客户端被钳；构建后改名、合并、冻结；键名不可信（名字与实际作用对不上，要看几何）；「挂了」不等于「挂对了」。
- **判据**：每类列出「写者、条件、期望值」，按可达状态逐个读回；往返序列必测；动作中的检查至少做走、坐、抬腿三种。
- **证据等级**：多工程验证——D5–D7 各有两个以上工程的实例；D8 只有一个工程做过动作扫描（单一案例）。
- **失效条件**：厂商已用自己的机制完整覆盖某类时，只核对不改写。
