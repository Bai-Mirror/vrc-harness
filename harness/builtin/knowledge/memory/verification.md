# 验证与验收：跨工程反复出现的教训

检测工具、渲图核对与交付验收在多个工程里反复踩过的坑。这里的「验收」指有读回证据的判定，不是执行方自称完成。

## 检测报「0 个问题」不等于没有问题

- **适用范围**：所有自动检测（穿模斑块、同名键跟随、驱动扫描、菜单断言）与自验。
- **结论**：0 常常只说明「这个工具看不见」。实例：鞋袜检测报 0 个穿出斑块，据此撤掉收缩键后脚趾直接穿出（原始数据里 472 个顶点在外，是聚合步骤把它们丢了）；同名键跟随检查设计上只覆盖「件上有键但无人写」，对「件上缺键」「键挂错件」看不见，68 条候选里确认有可见后果的是 0 条，但同期修掉的真缺陷有好几个不在它的范围内；驱动扫描返回全空却照常退出 0；一轮开发态自验 382 组全过，独立核查仍查出 5 个缺陷。
- **判据**：报告要写清口径与覆盖范围——「本工具未发现 X 类问题」而不是「没有问题」；覆盖最薄的工程只能说「本轮未发现新缺陷」。检测结论处于低置信（前两名差距 <10%、候选度量完全相同、有顶点超阈值却凑不成斑块）时，输出「无法判定」而不是 0，让直接读那一列的人读不到 0。
- **做法**：期望由第二视角（交付说明、需求原文）写出，实测来自构建后扫描，比对由脚本做；自验只验自己的假设。
- **证据等级**：多工程验证——Milfy、Kaguya 工程与多工程横向审查各自出现。
- **失效条件**：无。

## 探针与检查脚本要带已知正样本自检

- **适用范围**：只读探针、批处理检查脚本、构建期断言。
- **结论**：检查脚本自身出错时，最常见的表现是「什么都没查到，退出码 0」。必须给它一个已知必然命中的对象做自检：已知必有驱动的键驱动数 ≥1；已知会被删的顶点数 >0；打包后已知应存在的插件内部目录，缺失数为 0。
- **判据**：自检不过就非零退出；自检项写进报告。测试候选前把同域的键先清零，并读回「写进去的值」（`GetBlendShapeWeight` 回读），否则几个候选测到的是同一个姿势（实例：5 行候选里 4 行度量完全相同，推荐照样给出）。多个候选度量完全一致时，标记「不可分辨」并撤销推荐。
- **做法**：修代码后先确认跑的是新代码（构建开头打印版本戳，本地 `file:` 包尤其要查导入缓存）；阈值换素体就重标，不沿用别的素体标出的数（面积阈值随网格密度换算）。
- **证据等级**：多工程验证——Kaguya 饰品工程、Milfy 工程、一个 Kipfel 工程的交付包复核各自出现。
- **失效条件**：无。

## 视觉核对用原图局部裁切，外观真值先查部件图鉴

- **适用范围**：渲图人判与第二个模型的视觉复核（缺件、瞳色、服装形制、穿模）。
- **结论**：在缩略拼图上判断细节会反复误判，人和模型都错过：把被发丝遮住的发卡当成缺件、把视角遮挡的远侧耳朵当成缺失、把分腿短裤看成裙子。模型的指认也常被原图推翻：一轮 5 条指认里 4 条被原图否定；剩下 1 条（下装形制）起初被人凭定妆照目测驳回，查已验收的部件图鉴后确认成立。所以服装形制等外观真值应先查部件图鉴，不凭定妆照目测。
- **判据**：每条视觉结论回到原图做局部裁切复核；送评材料要附侧视图（否则 YZ 平面内的弯折会被当成不存在），并写明拍摄视角与遮挡关系；评审运行失败返回空结果时，记「未完成」，不能记成「0 条问题」。
- **做法**：部件图鉴只写可见结构，不写没测量过的精确角度或推断用途；「无金属」这类绝对否定写成「可见图内未见」。
- **证据等级**：多工程验证——两个角色的定妆照与创意照复核、部件图鉴抽查中反复出现。
- **失效条件**：无。

## 状态要覆盖菜单的全部可达组合

- **适用范围**：换装、配饰、脚型、胸型等由菜单组合决定外观的头像；回归测试与交付前检查。
- **结论**：历史上 14 个工程都没有回归报告，定妆照只用绑定姿态、不动菜单、只拍 4 个视角；「穿衣」点名在多个工程命中 0 件照样出图。缺陷集中在单件开关的组合、往返与中间档：两件压同一键的衣服同开、开后再关不回退、轮盘停在两档之间、露趾鞋配 Delete 了脚部键的袜子。
- **判据（必覆盖）**：每件单开、全开、全关；两双鞋同开；开后再关看回退；轮盘按档中点 (i+0.5)/n 逐档（研究时加 1/4、1/2、3/4）；两组互斥组同选；滑块非默认 × 每双鞋；袜子 × 露趾 / 镂空鞋；只留一个活跃根；Quest 根单独过；改动后跑一次完整构建；动态姿势（行走、坐下、抬腿）。视角在正面、四分之三、背面、面部之外加侧面 90°、低机位、俯视、手部。菜单断言按「行为档位」计覆盖，不按参数名计：Bool 要 0 与 1 各一条带断言的状态。
- **证据等级**：多工程验证——14 个历史工程的核查与 7 个客户工程的缺陷统计。
- **失效条件**：菜单极小的头像可以缩减，但要写明省略了哪些组合。

## 自己写的状态与分类，要以声明为准而不是以现场为准

- **适用范围**：测试工具的「默认状态」、形态键归属与分类、菜单档位值。
- **结论**：现场读到的值会漂移：一个测试工具把每次启动时的实际值当默认，上一轮停在哪、下一轮就把哪当默认，造成过「头饰一直不显示」「全开其实是关袜」两个假象；轮盘档位用打印出来的 4 位小数（0.2857）会落进上一档（2/7 = 0.285714…）。
- **判据**：基线状态来自声明（表达参数的默认值、交付说明的档位表），不是现场；档位取精确的 i/n 或档中点；参数被驱动器改写时（请求 1、读回 0.5）要识别为「被覆盖」而不是直接判失败或忽略。
- **证据等级**：单一案例（候选）——一个 Kaguya 工程的测试复盘，驱动器覆盖另见一个 Milfy 工程。
- **失效条件**：无。
