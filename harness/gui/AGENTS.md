# GUI design guidance

For changes under `harness/gui/`, read [Harness interface redesign and long-term rules](../../docs/zh/设计/2-功能模块/17_界面重构方向与长期规范.md) before changing user-facing pages, components, copy, or styles. The document defines the approved Codex-like workspace direction, restrained frosted surfaces, system-following light/dark themes, progressive disclosure, business states, and review checklist.

The [standalone visual sample](../../docs/zh/设计/2-功能模块/附件/界面示范/README.md) is illustrative code only. It does not establish that any feature is connected to Runtime or verified in a real project. Keep UI labels aligned with real capability and state. Follow the repository-wide `CLAUDE.md` and the product, Runtime, and release documents when they impose stronger requirements.
